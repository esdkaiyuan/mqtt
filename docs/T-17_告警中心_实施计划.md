# T-17 告警中心（Alert Center） — 实施计划

> 版本：v1.1　创建日期：2026-10-02　最后更新：2026-10-02
> 上游依据：[`T-17_告警中心_设计文档.md`](./T-17_告警中心_设计文档.md)
> 交付原则：端到端可用（数据模型 + 后端接口 + 前端页面 + 测试 + 文档），不做只有后端没有入口的半成品。

## P1 迁移与数据模型

- [x] `backend/src/main/resources/db/migration/V7__alert_center.sql`
  - 新建 `alert_rule`（阈值 / 离线 / 事件三类来源，含 `deleted` 逻辑删除，外键 `ON DELETE CASCADE`，字段见设计文档 §6.1）
  - 新建 `alert_record`（含状态、计数、抑制窗口基准时间，**无逻辑删除**，外键 `ON DELETE CASCADE`）
  - **只加表**，不改既有表，应用版本可安全回滚（回滚后新旧表共存，旧代码忽略新表）
  - 头部注释说明「只加表」与「数据来源 / 通知出口均为服务端」的事实
- [x] `entity/AlertRule.java`（`@TableName("alert_rule")`，`@Data @EqualsAndHashCode(callSuper=false)`；`createdAt` 用 `fill = FieldFill.INSERT`、`updatedAt` 用 `INSERT_UPDATE`；`deleted` 走全局逻辑删除）
- [x] `entity/AlertRecord.java`（`@TableName("alert_record")`，**无逻辑删除字段**，字段与迁移对齐）
- [x] `mapper/AlertRuleMapper.java`（`extends BaseMapper<AlertRule>`）
  - `List<AlertRule> selectEnabledByUser(@Param("userId") Long, @Param("sourceType") String)`：`enabled=1 AND deleted=0`
  - `List<AlertRule> selectEnabledBySource(@Param("sourceType") String, @Param("limit") int)`：跨用户按来源取启用规则（巡检用）
  - `int countEnabledBySource(...)`（可选，用于巡检分批日志）
- [x] `mapper/AlertRecordMapper.java`（`extends BaseMapper<AlertRecord>`）
  - `AlertRecord selectOpenByRuleAndDevice(@Param("ruleId") Long, @Param("deviceId") Long)`：`status <> 'RECOVERED'` 至多一条（`LIMIT 1`）
  - `int updateTrigger(@Param("id") Long, @Param("triggerCount") int, @Param("lastTriggeredAt") LocalDateTime, @Param("triggerValue") String, @Param("notifiedAt") LocalDateTime)`：`UPDATE ... WHERE id = ? AND status <> 'RECOVERED'`，返回受影响行数（幂等 / 并发兜底）
  - `int markRecovered(@Param("id") Long, @Param("recoveredAt") LocalDateTime)`：`UPDATE ... WHERE id = ? AND status <> 'RECOVERED'`
  - `int markAcknowledged(@Param("id") Long, @Param("acknowledgedAt") LocalDateTime, @Param("acknowledgedBy") Long)`：`UPDATE ... WHERE id = ? AND status = 'TRIGGERED'`
  - `long countOpenByUser(@Param("userId") Long)`：`status <> 'RECOVERED'`
  - `List<AlertRecord> selectOpenByRule(@Param("ruleId") Long, @Param("limit") int)`：巡检恢复判定用
  - `List<AlertRecord> selectOpenByUserLimit(@Param("userId") Long, @Param("limit") int)`：顶栏最近告警
  - 分页列表走 `BaseMapper.selectPage` + `LambdaQueryWrapper`（按 `status` / `sourceType` / `severity` / `deviceId` 过滤，`last_triggered_at` 倒序）
- [x] `resources/com/mqtt/cloud/mapper/AlertRuleMapper.xml` / `AlertRecordMapper.xml`
  - 所有状态迁移均为**条件更新**，返回受影响行数

## P3 评估服务

- [x] `service/AlertRuleService.java`（接口，**不得依赖 mapper**）+ `impl/AlertRuleServiceImpl.java`
  - `AlertRule create(Long userId, AlertRuleRequest request)`：完整校验（设计文档 §7.1），设备归属校验失败抛 `2003`
  - `AlertRule update(Long userId, Long id, AlertRuleRequest request)`：越权 / 不存在抛 `6207`，校验抛 `6208`
  - `void delete(Long userId, Long id)`：逻辑删除
  - `List<AlertRule> list(Long userId, String sourceType, Boolean enabled)`
  - `AlertRule getOwned(Long userId, Long id)`：越权抛 403 / 不存在抛 `6207`
  - 校验工具：`sourceType` 枚举、`operator` 枚举、`eventType` 枚举、`thresholdValue` 数值可解析性（按 `operator`）
- [x] `service/AlertEvaluationService.java`（接口，**不得依赖 mapper**）+ `impl/AlertEvaluationServiceImpl.java`
  - `void onProperties(Long deviceId, Long productId, List<PropertySample> samples)`：阈值评估（**推**）
  - `void onEvents(Long deviceId, List<EventSample> samples)`：事件评估（**推**）
  - `void onOfflineSweep()`：离线评估（**拉**，供 `AlertSweeper` 调用）
  - 内部 record：`PropertySample(identifier, valueText, reportedAt)`、`EventSample(identifier, eventType, outputData, reportedAt)`
  - 评估核心四步见设计文档 §8.2：查活动告警 → 新建 / 去重 / 再通知 → 恢复
  - 抑制窗口：`rule.suppressWindowSeconds > 0 ? 该值 : app.alert.suppressWindowSeconds`
  - 阈值口径：数值比较符 `BigDecimal.compareTo`，不可解析跳过（WARN）；`EQ` / `NE` 按归一化文本
  - 全程 try/catch 隔离，异常只记 WARN（对齐 `IngestDispatcher` 契约）
- [x] `service/AlertService.java`（接口，**不得依赖 mapper**）+ `impl/AlertServiceImpl.java`
  - `Page<AlertRecord> page(Long userId, AlertQuery query)`：分页 + 过滤
  - `AlertRecord getOwned(Long userId, Long id)`：越权 403 / 不存在 `6209`
  - `void acknowledge(Long userId, Long id)`：仅 `TRIGGERED` 可确认，否则 `6210`
  - `void recover(Long userId, Long id)`：仅活动告警可恢复，否则 `6210`；发 `alert.recovered` 通知
  - `long unreadCount(Long userId)`
  - `List<AlertRecord> recent(Long userId, int limit)`
- [x] `service/AlertSweeperService.java` + `impl/AlertSweeperServiceImpl.java`（离线巡检主体，供 `AlertSweeper` 调用）
  - 取启用中 `OFFLINE` 规则（分批 `sweepBatchSize`）→ 查作用域内 `deleted=0`、`status='OFFLINE'` 且（`last_seen` 为空 或 `last_seen <= now - offlineSeconds`）的设备 → 走评估
  - **恢复分支**：对每条规则的活动告警，若对应设备已非 `OFFLINE`（或规则已逻辑删除）→ 置 `RECOVERED` 并通知
