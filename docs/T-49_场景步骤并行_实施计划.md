# T-49 场景步骤并行 实施计划

> 版本：v1.0　创建日期：2026-10-22　状态：已交付
> 目标：补齐 G-12-3，让场景步骤流支持「PARALLEL 分叉 → 多条分支并发执行 → JOIN 汇合」，同时保持既有单步抢占、重试、巡检与执行明细语义。

---

## 1. 背景与范围

T-23 的场景是严格串行的步骤流，T-44 增加了向前条件分支与有界循环，但没有并行。主流 IoT 编排平台普遍支持「同时控制多台设备 / 并行等待多个动作完成后再继续」，本任务补齐：

- 新增 `PARALLEL`（并行开始）与 `JOIN`（并行汇合）两种流程步骤；
- 并行块内普通动作步骤通过 `parallelSeq` / `branchIndex` 归属到具体分支；
- 每个分支按 `seq` 顺序串行执行，各分支之间并发执行；
- 所有分支全部完成后才执行 `JOIN` 后的步骤；
- 任一分支失败沿用既有中止语义，不再启动该分支后续步骤；
- 前端表单与画布支持并行块配置、分支归属与汇合展示。

不在本任务范围：并行块嵌套、并行块内部再使用分支 / 循环、分支内子流程、并行分支之间共享变量、并行日志聚合展示。

## 2. 数据模型

### 2.1 步骤类型

| `action_type` | 含义 | `target_type` | `action_config` |
|---|---|---|---|
| `PARALLEL` | 并行开始 | `NONE` | `{branches: 2..8}` |
| `JOIN` | 并行汇合 | `NONE` | `{}` |

普通动作步骤新增两个字段：

| 字段 | 含义 |
|---|---|
| `parallel_seq` | 所属并行块的 `PARALLEL` 步骤序号；不在并行块内为 `NULL` |
| `branch_index` | 分支序号，0 起；不在并行块内为 `NULL` |

`PARALLEL` / `JOIN` 自身的两个字段恒为 `NULL`。

### 2.2 迁移 `V27__scene_parallel_steps.sql`

- `scene_step` 增加 `parallel_seq INT NULL`、`branch_index INT NULL`；
- `scene_step_run` 同步增加两列（执行明细快照，保证场景后续编辑不影响历史记录）；
- 仅加列、不改既有列；同步 `action_type` 列注释。

---

## 3. 保存期校验

1. `PARALLEL` / `JOIN` 目标类型必须为 `NONE`，动作配置仅允许规定字段；
2. 结构必须成对：每个 `PARALLEL` 之后、步骤结束之前必须有且只有一个 `JOIN`，不允许嵌套；
3. 并行块内只允许普通动作步骤，禁止 `BRANCH` / `LOOP` / `PARALLEL` / `JOIN`；
4. 块内每个启用步骤必须有 `parallelSeq`（等于块起始序号）与 `branchIndex`（0..branches-1）；
5. 每个分支至少有一个启用步骤；
6. 并行块不允许与循环体范围相交；`BRANCH` 不允许跳入并行块（含 `JOIN`）；
7. 分支数 2..8；总步骤数上限仍为 20。

---

## 4. 执行语义

### 4.1 分叉

`PARALLEL` 步骤执行时：

1. 读取 `branches`；
2. 在本次执行的步骤明细中，按 `parallelSeq` + `branchIndex` 找到每个分支序号最小的已启用步骤；
3. 并行步骤自身置 `SUCCESS`，并回填 `flow_result`（各分支起始序号）；
4. 按各分支首步的 `delaySeconds` 同时排期并投递（延时 0 立即投递）。

### 4.2 分支内推进

分支内普通步骤成功后：

- 找到同 `parallelSeq`、同 `branchIndex`、`seq` 更大的最小步骤并排期；
- 若已无后续步骤，则检查该并行块所有分支是否全部 `SUCCESS` / `SKIPPED`；
- 全部完成才排期 `JOIN` 步骤；否则等待其它分支。

分支完成判定**按执行明细状态实时计算**，不新增计数器，因此手动重试不会出现计数漂移。

### 4.3 汇合

`JOIN` 是空动作流程步骤，执行后正常推进到下一个 `seq`；`flow_result` 记录「并行汇合（N 路）」。

### 4.4 失败与手动重试

- 任一分支步骤重试耗尽后沿用 `SceneExecutionFinalizer` 中止执行，未执行的并行步骤置 `SKIPPED`；
- 已在执行中的其它分支允许完成当前动作，但不再排期后续步骤 / `JOIN`；
- 手动重试时，从最早可重放步骤所在的并行块开始整体重置该块及之后的并行块，重新从 `PARALLEL` 启动，避免只重放单个分支导致汇合条件永远不满足。

- 长分支 / 接近 8 分支的执行器线程池压力。

## 8. 关键决策与已知限制

1. **显式 `PARALLEL` / `JOIN` 成对结构**：比隐式按 `seq` 推断更容易校验与可视化，也避免「分支范围如何结束」的二义。
2. **分支归属落库**：`parallel_seq` + `branch_index` 作为步骤与执行明细的快照，执行器无需每次反解整份配置。
3. **不新增计数器**：分支完成判定直接读明细状态，重试、进程重启、多副本场景都不会产生计数漂移。
4. **并行块内禁用分支 / 循环 / 嵌套**：首版只支持「普通动作步骤的并行分支」，避免并行 + 回跳 + 重放的组合爆炸。
5. **失败后不强行中断在途动作**：当前执行器没有协作式中断，已开始的外部动作允许完成，但不会继续排期后续步骤。
