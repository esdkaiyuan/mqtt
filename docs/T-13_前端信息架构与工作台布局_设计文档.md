# T-13 前端信息架构与工作台布局 设计文档
> 版本：v1.1  修订日期：2026-10-02
> 变更：v1.1 补充 §4.7 官网首页、§4.8 文档站的布局骨架与断点行为细则
> 范围：仅前端（`frontend/`），不改动后端接口与数据契约

---

## 1. 背景与目标

### 1.1 背景

前端已经历 T-06（基础架构与设计系统）、T-07/T-08（业务页面）、T-10（部署）三轮建设，页面「单看」简洁美观，但缺少统一的**信息架构**与**页面骨架**，随着页面数量增加，问题开始累积：

- 站点没有「官网（对外首页）」与「工作台（登录后后台）」的清晰分层，根路径 `/` 直接进工作台，官网 `/landing` 游离在外。
- 工作台只有一个「左导航 + 内容区」的两区结构，缺少顶栏、上下文栏、状态栏，信息无处安放，页面各写各的头部。
- 缺少功能/API 说明文档页，仅有一个工作台内的端点清单（`/api-docs`）。
- 页面宽度、内边距、控件选型各行其是，出现「错位」。

### 1.2 目标

1. **统一信息架构**：确立「公开站（官网 / 文档 / 登录注册）」与「工作台（登录后）」两大分区，路由按分区收敛。
2. **统一页面骨架**：工作台采用「顶栏 + 左导航 + 内容区 + 右上下文栏 + 底部状态栏」五区骨架，官网/文档采用「站点头 + 内容 + 站脚」骨架，所有页面遵循同一套栅格与间距。
3. **消除错位**：统一内容容器职责（谁负责内边距、谁负责最大宽度），统一页头组件，统一控件与间距，杜绝双重内边距与宽度不一致。
4. **补齐官网与文档站**：官网首页落在 `/`，新增公开文档站 `/docs`（功能说明 + API 参考）。
5. **保留既有视觉语言**：延续当前「方正」风格（品牌蓝 `#165DFF`、白底卡片、1px 细边框、克制圆角），只重构结构与一致性，不更换视觉调性。

### 1.3 成功标准

| 编号 | 成功标准 | 量化口径 |
|------|----------|----------|
| S-1 | 站点分层清晰 | 未登录访问 `/`、`/docs`、`/login`、`/register` 均可达；访问 `/workbench/**` 跳转登录 |
| S-2 | 骨架统一 | 工作台全部页面渲染于同一 `WorkbenchLayout`，无页面自绘顶栏/侧栏 |
| S-3 | 无错位 | 工作台所有页面左右边界对齐同一栅格；不存在「双重内边距」与页面级 `max-width` 特例 |
| S-4 | 控件统一 | 表单控件统一使用 Element Plus；全站无原生 `<select>`/`<input>` 混用；无 Emoji 图标 |
| S-5 | 文档可读 | `/docs` 提供左目录树 + 正文，覆盖快速开始、设备接入、消息与数据、开放 API、运维五章 |
| S-6 | 响应式可用 | ≥1440 / 1024–1440 / 768–1024 / <768 四档均无横向滚动与内容遮挡 |
| S-7 | 回归通过 | `npm run test`、`npm run build`、`npm run lint` 全部通过；旧路径 301 到新路径 |

## 2. 现状与问题（证据）

### 2.1 页面错位根因

| 问题 | 证据 | 后果 |
|------|------|------|
| 双重内边距 | `components/Layout/MainLayout.vue` 的 `.app-main { padding: var(--spacing-lg) }`，而每个页面又套 `.page-container`（`assets/css/global.css` 中 `padding: var(--spacing-lg)`） | 内容距边界 32px，与设计 16px 不符，且卡片贴边不一致 |
| 宽度策略不一致 | `.page-container` 自带 `max-width: var(--page-max-width)`（1200px）+ `margin: 0 auto`；`views/api/ApiDocs.vue` 又写 `max-width: 900px`；而 `Dashboard.vue`/`DeviceList.vue` 用默认 1200px；工作台主区却是全宽 | 同一工作台内，有的页面居中 900、有的居中 1200，视觉左右边界跳动，即「错位」 |
| 页头重复 | `MainLayout` 顶栏渲染 `route.meta.title`；同时 `Dashboard.vue`/`DeviceList.vue`/`ApiKeys.vue`/`Webhooks.vue`/`ApiDocs.vue`/`MessageMonitor.vue`/`HistoryQuery.vue`/`DeviceDetail.vue` 各自又写一份 `.page-header` | 标题出现两遍，层级与字号各页不同 |

### 2.2 框架与组件不统一

| 问题 | 证据 |
|------|------|
| Element Plus 与原生控件混用 | `DeviceList.vue` 筛选栏用原生 `<select>`/`<input>`；`MessageMonitor.vue` 发布表单用原生 `<select>`/`<textarea>`；`DeviceDetail.vue` 指令表单用原生 `<select>`；而 `Dashboard.vue` 用 `el-select` |
| 对话框实现混用 | `ApiKeys.vue`/`Webhooks.vue` 用 `el-dialog` 但内部表单是原生控件；`device/*Dialog.vue` 自研 |
| 颜色/字体硬编码 | 多处直接写 `#1D2129`/`#86909C`/`#F5F7FA`/`'Courier New'`，绕过 `variables.css` 令牌 |
| 图标不统一 | `LandingFeatures.vue`、`Login.vue` 使用 Emoji（📡📊🔔…），与既有规范「无 Emoji、统一 SVG 图标」冲突 |
| 目录命名不一致 | `components/Layout/`（首字母大写）与其余全小写目录风格不一致 |

### 2.3 站点结构缺失

| 问题 | 证据 |
|------|------|
| 无对外官网入口 | `router/index.js` 中 `/` 直接挂 `MainLayout` 且 `requiresAuth: true`，官网只能通过 `/landing` 访问 |
| 无文档站 | `/api-docs` 仅是 `views/api/ApiDocs.vue` 内硬编码的 3 组端点清单，无目录、无快速开始、无错误码 |
| 登录后无处可去 | `stores/auth.js` 登录/登出后 `emit('navigate', '/dashboard')`、`'/login'`，路径需随分区调整 |

### 2.4 工作台骨架缺失

- 无顶栏工具区：全局搜索、环境标识、通知、主题切换无处安放。
- 无上下文栏：`DeviceDetail.vue` 自行用 `grid-template-columns: 1fr 360px` 造了「右栏」，其他页面无右栏，导致同类信息（状态、快捷操作）在不同页面位置不同。
- 无底部状态栏：实时通道（SSE）连接状态只出现在 `MessageMonitor.vue` 页内，其他页面看不到链路是否正常。
- 左导航不可折叠：`Sidebar.vue` 中 `const isCollapsed = computed(() => false)` 写死为 `false`，`--sidebar-width-collapsed` 令牌形同虚设。

### 2.5 违反既有设计规范项

| 规范出处 | 条目 | 现状 |
|----------|------|------|
| T-06 §2.5 | 禁止装饰性元素、禁止渐变 | `LandingHero.vue`、`Login.vue` 使用大面积渐变 |
| T-06 §2.5 | 无 Emoji | `LandingFeatures.vue`、`Login.vue`/`Register.vue` 使用 Emoji |
| T-06 §2.5 | 对齐严格、禁止错位 | 见 §2.1 |

> 处置口径：Emoji 与原生控件**必须**收敛；渐变属于官网品牌表现，本次**保留官网 Hero 的克制渐变**，仅统一其令牌与间距（见 §7 风险与取舍）。

## 4. 总体设计

### 4.1 站点信息架构

```
MQTT Cloud
├── 公开站（无需登录）
│   ├── /                 官网首页（产品介绍 + 入口）
│   ├── /docs             文档站
│   │   ├── /docs/getting-started/*      快速开始
│   │   ├── /docs/device/*               设备接入
│   │   ├── /docs/data/*                 消息与数据
│   │   ├── /docs/api/*                  开放 API（REST + Webhook）
│   │   └── /docs/ops/*                  平台运维
│   ├── /login            登录
│   └── /register         注册
└── 工作台（需登录）
    └── /workbench
        ├── /workbench/dashboard         概览
        ├── /workbench/devices           设备管理
        ├── /workbench/devices/:id       设备详情
        ├── /workbench/messages          实时消息（ADMIN/OPERATOR）
        ├── /workbench/history           历史数据
        └── /workbench/access
            ├── api-keys                 API 密钥
            └── webhooks                 Webhook
```

分区原则：

- **公开站**回答「这是什么、怎么用」，可被搜索引擎与外部用户直接访问，不含任何需要鉴权的数据。
- **工作台**回答「现在怎么样、怎么操作」，全部需要登录，统一在同一骨架内。
- 文档站是公开站的子区，工作台左导航提供「开发文档」外链跳转到 `/docs`（新开标签），不再在工作台内重复维护文档。

### 4.2 路由与访问控制

#### 4.2.1 路由结构

```js
// src/router/index.js（骨架）
const routes = [
  // ===== 公开站 =====
  { path: '/', name: 'Home', component: () => import('@/views/site/home/HomePage.vue'),
    meta: { requiresAuth: false, layout: 'site' } },
  { path: '/docs', component: () => import('@/components/layout/DocsLayout.vue'),
    meta: { requiresAuth: false, layout: 'docs' }, redirect: '/docs/getting-started/overview',
    children: [ /* 各章节，meta: { title, group } */ ] },
  { path: '/login', name: 'Login', component: () => import('@/views/auth/Login.vue'),
    meta: { requiresAuth: false, layout: 'blank' } },
  { path: '/register', name: 'Register', component: () => import('@/views/auth/Register.vue'),
    meta: { requiresAuth: false, layout: 'blank' } },

  // ===== 工作台 =====
  { path: '/workbench', component: () => import('@/components/layout/WorkbenchLayout.vue'),
    meta: { requiresAuth: true }, redirect: '/workbench/dashboard',
    children: [
      { path: 'dashboard', name: 'Dashboard', component: () => import('@/views/workbench/dashboard/Dashboard.vue'),
        meta: { title: '概览', icon: 'dashboard', group: 'monitor' } },
      { path: 'devices', name: 'DeviceList', component: () => import('@/views/workbench/device/DeviceList.vue'),
        meta: { title: '设备管理', icon: 'device', group: 'monitor' } },
      { path: 'devices/:id', name: 'DeviceDetail', component: () => import('@/views/workbench/device/DeviceDetail.vue'),
        meta: { title: '设备详情', hidden: true, group: 'monitor' } },
      { path: 'messages', name: 'MessageMonitor', component: () => import('@/views/workbench/message/MessageMonitor.vue'),
        meta: { title: '实时消息', icon: 'message', group: 'monitor', roles: ['ADMIN', 'OPERATOR'] } },
      { path: 'history', name: 'HistoryQuery', component: () => import('@/views/workbench/history/HistoryQuery.vue'),
        meta: { title: '历史数据', icon: 'history', group: 'monitor' } },
      { path: 'access/api-keys', name: 'ApiKeyManagement', component: () => import('@/views/workbench/access/ApiKeys.vue'),
        meta: { title: 'API 密钥', icon: 'settings', group: 'access' } },
      { path: 'access/webhooks', name: 'WebhookManagement', component: () => import('@/views/workbench/access/Webhooks.vue'),
        meta: { title: 'Webhook', icon: 'settings', group: 'access' } }
    ] },

  // ===== 旧路径兼容（301） =====
  { path: '/landing', redirect: '/' },
  { path: '/dashboard', redirect: '/workbench/dashboard' },
  { path: '/devices', redirect: '/workbench/devices' },
  { path: '/devices/:id', redirect: (to) => `/workbench/devices/${to.params.id}` },
  { path: '/messages', redirect: '/workbench/messages' },
  { path: '/history', redirect: '/workbench/history' },
  { path: '/api-docs', redirect: '/docs/api/rest' },
  { path: '/settings/api-keys', redirect: '/workbench/access/api-keys' },
  { path: '/settings/webhooks', redirect: '/workbench/access/webhooks' },

  { path: '/:pathMatch(.*)*', name: 'NotFound', component: () => import('@/views/site/NotFound.vue'),
    meta: { requiresAuth: false, layout: 'blank' } }
]
```

#### 4.2.2 守卫规则

| 场景 | 行为 |
|------|------|
| 未登录访问 `requiresAuth: true` | 跳 `/login?redirect=<fullPath>` |
| 已登录访问 `/login`、`/register` | 跳 `/workbench/dashboard` |
| 已登录访问 `/`、`/docs` | 允许（公开站不强制跳工作台，保留「先看官网」体验） |
| 角色不满足 `meta.roles` | 跳 `/workbench/dashboard`（后端仍独立鉴权） |
| 匹配 `NotFound` | 渲染 404 页，提供「返回首页 / 进入工作台」 |

> 公开站与工作台共用同一 `createWebHistory()`；不引入多实例 router。

### 4.3 工作台四区骨架（上下左右）

#### 4.3.1 结构

```
┌───────────────────────────────────────────────────────────────────────────┐
│ TopBar  56px                                                              │
│ [≡折叠] [logo MQTT Cloud] │ 面包屑：概览        [🔍全局搜索] [ENV] [🔔] [用户▾] │
├──────────┬──────────────────────────────────────────────┬─────────────────┤
│ LeftNav  │  Content                                     │ ContextRail     │
│ 240px    │  PageHeader（标题/描述/操作）                 │ 320px（可收起） │
│ 可折叠   │  router-view                                 │ 随页面变化      │
│ →64px    │                                              │                 │
├──────────┴──────────────────────────────────────────────┴─────────────────┤
│ StatusBar  28px                                                           │
│ ● 实时通道已连接 │ Broker 正常 │ 在线 12/20 │ 版本 v1.0.0 │ 更新于 12:03:45    │
└───────────────────────────────────────────────────────────────────────────┘
```

#### 4.3.2 各区职责

| 区 | 组件 | 职责 | 不做 |
|----|------|------|------|
| 顶栏 | `TopBar.vue` | 折叠左导航、产品标识、面包屑、全局搜索（设备/Topic 跳转）、环境标识、通知、用户菜单 | 不显示当前页面大标题（交给 `PageHeader`） |
| 左导航 | `LeftNav.vue` | 分组主导航（监控 / 开发接入 / 系统）、折叠、当前项高亮、底部「返回官网」「开发文档」 | 不放业务操作按钮 |
| 内容区 | `router-view` + `PageHeader.vue` | 页面标题与操作区 + 页面内容 | 不自带 `max-width` 特例 |
| 右上下文栏 | `ContextRail.vue` | 承载「与当前页面强相关」的辅助信息与快捷操作，按路由注册内容 | 不放主导航、不放跨页面常驻信息 |
| 底部状态栏 | `StatusBar.vue` | 全局健康度：SSE 通道、Broker、在线设备、版本、最后刷新时间 | 不放操作按钮 |

#### 4.3.3 右上下文栏内容矩阵

| 路由 | ContextRail 内容 |
|------|------------------|
| `/workbench/dashboard` | 在线率环形、异常设备 Top5、最近事件流 |
| `/workbench/devices` | 快捷筛选（在线/离线/未激活）、最近访问设备 |
| `/workbench/devices/:id` | 设备摘要、快捷操作（发送指令 / 查历史 / 复制 Topic / 复制密钥入口）、Topic 路径 |
| `/workbench/messages` | Topic 过滤器、订阅管理、通道详情（心跳、重连次数） |
| `/workbench/history` | 查询历史记录、常用查询保存 |
| `/workbench/access/*` | 使用说明、权限范围速查、调用示例 |

> 实现方式：`ContextRail.vue` 作为壳，内部按 `route.name` 通过 `<component :is>` 挂载 `components/rail/*` 具体面板；无注册内容的页面右栏显示「默认面板（平台健康度）」或整体收起。

#### 4.3.4 折叠与持久化

- 左导航折叠状态、右上下文栏展开状态持久化到 `localStorage`（键 `ui.nav.collapsed`、`ui.rail.open`）。
- 由 `stores/ui.js`（新增 Pinia store）统一管理，避免各组件各自读写 localStorage。
- 折叠动画 200ms `ease`，与既有 `.fade` 过渡时长一致。

### 4.4 设计令牌与统一规范

#### 4.4.1 布局令牌（在 `variables.css` 新增/调整）

```css
:root {
  /* 骨架尺寸 */
  --topbar-height: 56px;
  --statusbar-height: 28px;
  --nav-width: 240px;
  --nav-width-collapsed: 64px;
  --rail-width: 320px;

  /* 内容栅格 */
  --content-padding: 24px;      /* 内容区四周内边距，唯一来源 */
  --content-max-width: 1440px;  /* 超宽屏内容上限，居中 */
  --grid-gutter: 16px;          /* 卡片/栅格间距，全站统一 */

  /* 层级 */
  --z-nav: 100;
  --z-topbar: 200;
  --z-rail: 150;
  --z-overlay: 900;
  --z-modal: 1000;

  /* 过渡 */
  --transition-fast: 150ms ease;
  --transition-base: 200ms ease;
}
```

- **移除** `--sidebar-width` / `--sidebar-width-collapsed` / `--header-height` / `--page-max-width`，由上述令牌替代（保留一次性兼容别名，见 §5.1）。
- 语义色、字号、间距、圆角、阴影**沿用现有令牌**，不再新增色值。

#### 4.4.2 容器职责划分（消除双重内边距）

| 层 | 负责 | 不负责 |
|----|------|--------|
| `WorkbenchLayout` 内容区 | 定义可用区域（grid 单元），**不设 padding** | 不设内边距、不设 max-width |
| `.page`（页面根容器） | 唯一提供 `padding: var(--content-padding)`，超宽时 `max-width: var(--content-max-width); margin: 0 auto` | 不再出现页面级 `max-width` 特例 |
| `.card` | 卡片自身内边距 `var(--spacing-lg)` | 不再承担页面间距 |

- 删除 `.page-container` 的双重 padding 语义，统一替换为 `.page`（工作台）与 `.site-container` / `.docs-container`（公开站，宽度上限 1200px）。
- 全站删除 `max-width: 900px` 一类的页面特例；阅读型页面通过 `.page--narrow`（上限 960px）显式声明，仅文档正文使用。

#### 4.4.3 统一页头组件

`components/common/PageHeader.vue`：


| 设备列表/详情 | `stores/device.js`、`composables/useDeviceList.js` | DeviceList、DeviceDetail、ContextRail |

## 7. 风险与取舍

| 风险/取舍 | 说明 | 处置 |
|-----------|------|------|
| 迁移面大、易漏引用 | 目录改名 + 路由重构涉及大量 import | 分阶段实施（见实施计划），每阶段 `build` + `test` 通过再进入下一阶段 |
| 视觉调性被改坏 | 用户要求「延续方正设计」 | 只重构结构与一致性，不新增色板；渐变仅保留官网 Hero 与登录品牌区两处，其余拉平为纯色 |
| 官网与工作台断点不同 | 官网 1200px、工作台 1440px | 通过 `--site-max-width` / `--content-max-width` 区分，属有意设计，写入文档 |
| SSE 上提为应用级 | 连接生命周期变化，可能影响消息页行为 | `stores/ui.js` 保留事件缓冲；MessageMonitor 消费 store，断线重连逻辑不变（沿用 `subscribeRealtime`） |
| 文档内容准确性 | 文档站涉及后端契约 | 内容取自现有 `docs/*` 与代码，标注「以实际接口为准」，端点数据单一来源 `data/apiEndpoints.js` |
| 旧令牌别名残留 | 兼容别名长期存在会腐化 | 别名标注「T-13 后移除」，在实施计划收尾任务中统一清理 |
| Element Plus 全量 vs 按需 | 新增组件可能触发 barrel 打包 | 继续使用现有 `ElementPlusOnDemand` 细粒度解析器，构建后核对 chunk 体积 |
