# T-44 场景步骤分支与循环 实施计划

> 版本：v1.0　创建日期：2026-10-21　状态：已交付
> 目标：补齐 G-12-2，让场景步骤流支持**向前条件分支**与**有界循环**，同时保持执行记录、重试与多副本抢占语义不变。

---

## 1. 背景与范围

T-23 / T-29 的场景是线性步骤流：始终按 `seq` 顺序执行，无法按条件走不同路径，也无法重复一组步骤。本任务在**不新增第二套流程引擎**的前提下扩展：

- 新增 `BRANCH`（条件分支）与 `LOOP`（循环结束标记）两种步骤类型；
- 分支只允许**向前跳转**（`trueSeq` / `falseSeq`），避免任意回跳形成死循环；
- 循环为**有界计数循环**：`LOOP` 步骤标记循环体结束，`startSeq` 指向循环体首步，`times` 为重复次数（1..20）；
- 复用既有 `scene_step_run` 一行一步骤的执行模型、`claimPending` 抢占、退避重试、手动重试与执行抽屉。

不在本任务范围：步骤并行、无限 / 条件循环（while）、跨循环跳入、影子变更触发、版本回滚。

---

## 2. 数据模型

### 2.1 步骤类型

| `action_type` | 含义 | `target_type` | `action_config` |
|---|---|---|---|
| `BRANCH` | 条件分支 | `NONE` | `{deviceId?, identifier, operator, threshold, trueSeq?, falseSeq?}` |
| `LOOP` | 循环结束标记 | `NONE` | `{startSeq, times}` |

- `BRANCH` 的 `deviceId` 为空时使用触发设备；`TIMER` 源必须显式指定取值设备；
- `trueSeq` / `falseSeq` 为空表示「结束本次执行」，至少需要一个非空；
- `LOOP` 的循环体为 `[startSeq, 当前循环步骤 seq - 1]`，`startSeq` 必须小于当前步骤且对应步骤已启用；
- 两者都不执行动作，也不占用目标设备。

### 2.2 执行明细

`V23__scene_flow_steps.sql`：

- `scene_step_run` 新增 `loop_iteration INT NOT NULL DEFAULT 0` 与 `flow_result VARCHAR(512) NULL`；
- 同步 `scene_step.action_type` / `target_type` 与 `scene_step_run.action_type` 的列注释；
- 无表结构重建、无索引变更。

`flow_result` 记录分支决策（如 `temperature=31 GT 30 → 真，跳转第 4 步`）或循环轮次（如 `第 2/3 次循环`），供执行抽屉排障。

## 3. 执行语义

### 3.1 分支

1. 读取条件设备的最新属性值（无值按不满足处理）；
2. `RuleConditionMatcher` 与规则 / 场景条件组同一口径；
3. 命中取 `trueSeq`，否则取 `falseSeq`；目标为空则结束执行；
4. 当前分支步骤置 `SUCCESS`，目标步骤按自身 `delaySeconds` 排期；被跳过且从未执行的步骤在终态统一置 `SKIPPED`。

### 3.2 循环

1. 循环体按正常线性流程执行到 `LOOP` 步骤；
2. 未达次数：`resetLoopBody` 把循环体内已执行 / 已跳过步骤复位为 `PENDING`，`resetLoopStep` 把循环步骤复位为 `PENDING` 并记录轮次，然后重新排期循环体首步；
3. 达到次数：循环步骤置 `SUCCESS`，继续执行其后的步骤；
4. 分支可在循环体内提前跳到循环步骤或循环外（向后跳转不允许）；
5. 嵌套循环按「区间嵌套或互不相交」校验，内层循环轮次在外层每轮开始时归零。

### 3.3 进度与终态

- 循环重放会减少已完成步骤数，因此重放后调用 `recountFinishedSteps` 按明细重算，避免手工增量漂移；
- 终态收口先把残留 `PENDING` 置 `SKIPPED`，再重算进度并置 `SUCCESS`；
- 失败中止同样重算进度；手动重试重置 `FAILED/SKIPPED` 步骤并重算，`SUCCESS` 步骤不重放。

---

## 4. 保存期校验

- `BRANCH` / `LOOP` 目标类型必须为空或 `NONE`，不允许配置目标集合；
- 分支目标只允许向前、必须存在且已启用；不能从循环外跳入循环体（包括跳入循环步骤本身）；
- 循环范围不能部分重叠；可完全嵌套或互不相交；
- 单循环次数 1..20；循环展开后的总执行次数 ≤ 200（按嵌套循环次数乘积计算上界）；
- `TIMER` 源的分支必须显式指定取值设备；
- 条件属性标识符 / 比较符 / 阈值复用既有比较符与阈值校验。

## 8. 关键决策与已知限制

1. **向前分支 + 有界循环**：不做任意跳转 / while 循环，避免不可判定的死循环；上限在执行步数层面再兜底。
2. **循环步骤作为结束标记**：不改步骤表结构、不引入块嵌套表，`startSeq` 向前引用即可定义循环体。
3. **复用一行一步骤的执行明细**：循环每轮覆盖同一行，只保留最终状态与轮次，**不保留每轮的独立历史**；这是不新建执行明细表的取舍。
4. **手动重试不回到循环开头**：只重置失败 / 跳过步骤，保留当前 `loop_iteration`；复杂场景建议重新触发。
5. **被跳过的步骤在终态统一清理**：不在分支时立即标记，避免循环重放时反复翻转状态。
6. **画布跳转边仅可视化**：Vue Flow 的边不参与执行，执行顺序完全由服务端 `seq` 路由决定。
