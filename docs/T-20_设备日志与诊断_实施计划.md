## P2 Mapper 与聚合 SQL

- [x] `mapper/DeviceLogMapper.java`（`@Mapper`，**不继承 `BaseMapper`**，仅两个自定义方法）
  - `long countQuery(@Param("deviceId") Long deviceId, @Param("types") List<String> types, @Param("startTime") LocalDateTime startTime, @Param("endTime") LocalDateTime endTime, @Param("keyword") String keyword)`
  - `List<DeviceLogItem> pageQuery(@Param("deviceId") Long deviceId, @Param("types") List<String> types, @Param("startTime") LocalDateTime startTime, @Param("endTime") LocalDateTime endTime, @Param("keyword") String keyword, @Param("offset") long offset, @Param("size") long size)`
- [x] `resources/com/mqtt/cloud/mapper/DeviceLogMapper.xml`
  - 可复用片段 `<sql id="logUnion">`：四段 `SELECT` 投影到**同一列集**（缺失列置 `NULL`），列顺序严格一致，别名统一为 snake_case（`log_id` / `log_type` / `direction` / `occurred_at` / `topic` / `identifier` / `sub_type` / `status` / `payload` / `command_id` / `call_type` / `source` / `operator_id` / `error_message` / `attempt_count` / `secondary_time` / `qos` / `seq`）（设计文档 §7.2）
  - 四源映射：`message`（`CONCAT('MSG-', m.id)` / `MESSAGE` / `m.direction` / `m.sent_at`）→ `device_command_record`（`CMD-` / `COMMAND` / `'DOWN'` / `c.created_at`）→ `device_event_record`（`EVT-` / `EVENT` / `'UP'` / `e.reported_at`）→ `device_status_history`（`STA-` / `STATUS` / `NULL` / `s.timestamp`）
  - 各源时间条件：`m.sent_at` / `c.created_at` / `e.reported_at` / `s.timestamp` 的 `>= startTime` 与 `< endTime`（**半开区间**），`<if>` 动态拼接
  - `countQuery`：`SELECT COUNT(*) FROM ( <include refid="logUnion"/> ) t <where> 类型 / keyword 过滤 </where>`
  - `pageQuery`：同 `countQuery` 的过滤 + `ORDER BY t.occurred_at DESC, t.seq DESC` + `LIMIT #{offset}, #{size}`
  - 类型过滤：`AND t.log_type IN <foreach>`（`types` 非空时）；keyword 过滤：`AND (t.topic LIKE #{keyword} OR t.identifier LIKE #{keyword} OR t.error_message LIKE #{keyword} OR t.payload LIKE #{keyword})`
  - **全部 `#{}` 占位符**，无 `${}` 拼接；`resultType="com.mqtt.cloud.dto.response.DeviceLogItem"`
  - 头部注释说明：查询时聚合、无新表、半开区间、显式 count 的原因

## P3 服务层

- [x] `service/DeviceLogService.java`（接口，**不得依赖 `..mapper..`**，ArchUnit 门禁）
  - `IPage<DeviceLogItem> page(Long userId, Long deviceId, DeviceLogQueryDTO query)`
- [x] `service/impl/DeviceLogServiceImpl.java`（流程见设计文档 §7.3）
  - 构造注入 `DeviceMapper` / `DeviceLogMapper` / `ObjectMapper`（`tools.jackson.databind.ObjectMapper`，与 T-15 同款）
  - **设备鉴权**：`deviceMapper.selectById(deviceId)` → 空 → `BusinessException(DEVICE_NOT_FOUND)`；`!ownerId.equals(userId)` → `DEVICE_NOT_OWNED`
  - **参数归一化**：
    - `types` 白名单校验（任一非法 → `6224`）；空 / `null` 视为全部
    - `pageNum` / `pageSize` 夹取：`pageNum < 1 → 1`；`pageSize` 取 `[1, maxPageSize]`，`maxPageSize` 取配置（缺省 / 非正 → `MAX_PAGE_SIZE_FALLBACK`）
    - `startTime` / `endTime` 解析（支持 `yyyy-MM-dd HH:mm:ss` 与 ISO；非法 → `6223`）；`startTime >= endTime` → `6223`
    - 跨度校验：两者均非空且 `endTime - startTime > maxRangeDays` → `6223`（`maxRangeDays` 缺省 / 非正 → `DEFAULT_MAX_RANGE_DAYS`）
    - `keyword` 空白 → `null`；非空包裹 `%...%` 后传入
  - `countQuery` → `total`；`total == 0` **直接返回空 `Page`，不执行 `pageQuery`**
  - `pageQuery` → `records`
  - **关联键与展示字段回填**（仅对返回页内条目，Java 侧）：
    - `MESSAGE` 且 `topic` 以 `/reply` 结尾 → `ObjectMapper.readTree(payload)` 取 `id` → `correlationId` + `correlationRole=REPLY`（解析失败 / 无 `id` → 保持 `null`，记 DEBUG，**不抛异常**）
    - `COMMAND` → `correlationId = commandId`、`correlationRole=REQUEST`
    - `STATUS` → `title = "设备上线 / 设备离线"`（按 `status` 判定）
    - `direction` 展示：`MESSAGE` 用报文方向、`COMMAND=DOWN`、`EVENT=UP`、`STATUS=null`
  - 手工组装 `Page<DeviceLogItem>`（`setTotal` + `setRecords` + `setSize` + `setCurrent`），保持 `IPage` 对外形状与既有列表接口一致
- [x] `config/DeviceLogProperties.java`（`@Data @Component @ConfigurationProperties(prefix = "app.device-log")`，字段 `maxPageSize=100` / `maxRangeDays=31`，带中文注释）
  - 或（择一）在 `DeviceLogServiceImpl` 以 `@Value("${app.device-log.max-page-size:100}")` 注入；**优先独立 Properties 类**，与 `AlertProperties` / `RuleProperties` 一致
- [x] `resources/application.yml`：`app` 下新增 `device-log` 块，紧随 `app.rule` 之后（设计文档 §9.2）
  ```yaml
  app:
    device-log:
      max-page-size: ${DEVICE_LOG_MAX_PAGE_SIZE:100}
      max-range-days: ${DEVICE_LOG_MAX_RANGE_DAYS:31}
  ```
