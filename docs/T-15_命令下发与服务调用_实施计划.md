## P3 命令服务

- [ ] `config/CommandProperties.java`（`app.command`，字段见设计文档 §12）
- [ ] `service/DeviceCommandService.java`（接口，不得依赖 mapper）
  - `CommandCapability getCapability(Long productId)`
  - `DeviceCommandRecord invoke(CommandInvoke command)`
  - `IPage<DeviceCommandRecord> listCommands(Long deviceId, long page, long size)`
  - 内部 record：`CommandInvoke(deviceId, productId, commandType, identifier, paramsJson, callType, source, operatorId)`
  - 内部 record：`CommandCapability(boolean modeled, List<PropertySpec> properties, List<ServiceSpec> services)`
- [ ] `service/impl/DeviceCommandServiceImpl.java`
  - 前置：物模型必须存在（否则 `6201`）
  - 校验：`property_set` → 每个键命中属性且 `accessMode=rw`（否则 `6202`）、值过类型校验（否则 `6204`）；`service` → 命中服务（否则 `6203`）、入参必填与类型（否则 `6204`）
  - `params` 序列化大小超 `max-params-bytes` → `6204`
  - 落库 `PENDING` → 发布 `device/{deviceKey}/cmd/down`（QoS 1）→ 成功置 `SENT`，异常置 `FAILED` + `4001`
  - `callType=sync`：轮询记录至终态或 `sync-timeout-ms`，超时 `markTimeout` 后返回 `TIMEOUT` 记录
  - 发布载荷：`{"id": commandId, "version":"1.0", "method": ..., "params": ...}`（见设计文档 §5）
- [ ] 超时巡检：`@Scheduled(fixedDelayString = "${app.command.timeout-sweep-interval-ms:30000}")`
  - 同步记录与异步记录分别按 `sync-timeout-ms` / `async-timeout-ms` 兜底置 `TIMEOUT`
  - 间隔为 0 时不注册（`@ConditionalOnProperty` 或显式判空跳过）
