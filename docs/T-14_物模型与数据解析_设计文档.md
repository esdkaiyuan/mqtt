## 1. 背景与目标

### 1.1 背景

当前平台的设备数据是**无语义**的：上行 `device/{deviceKey}/data` 的 payload 原样写入 `message` 表，平台不知道「temperature 是浮点属性、范围 -40~125」「highTempAlarm 是一个告警事件」。`product.metadata_schema` 字段虽已建，但从未被校验或消费。

对照主流平台：阿里云 IoT 以 **TSL 物模型**（属性 / 事件 / 服务）描述设备能力，设备按 **Alink JSON** 上报，云端据此做数据解析、属性存储、服务调用与影子同步 [$TRAE_REF](https://help.aliyun.com/en/iot/user-guide/device-properties-events-and-services)；ThingsCloud 同样以「设备属性 / 事件」为消息规则的输入对象 [$TRAE_REF](https://www.thingscloud.xyz/docs/guide/rules/attrs-rpt.html)。

物模型是后续所有能力的前提：命令的参数、影子的属性标识符、告警的阈值对象，全部依赖它。

### 1.2 目标

1. 产品拥有结构化设备模型（TSL），支持定义、校验、导入导出与前端编辑；
2. 上行数据按物模型解析为**有语义的属性最新值**与**事件记录**；
3. 全程**不破坏既有摄取管线**：解析失败不丢消息、不拖慢主链路。

## 2. 范围

### 2.1 在范围内

| 项 | 内容 |
|----|------|
| TSL 数据结构 | 属性 / 事件 / 服务三集合，含数据类型、单位、读写权限、枚举、结构体、数组 |
| TSL 校验 | 标识符规范与全局唯一、数据类型约束、数量上限 |
| 物模型存储与版本 | `product` 新增物模型字段 + 版本号，每次保存自增 |
| 物模型接口 | 查询 / 保存 / 清空 / 导入 / 导出（REST） |
| 上行数据解析 | Alink JSON 子集解析 → 属性最新值表 + 事件记录表 |
| 前端产品管理页 | **当前前端完全没有产品页面**（产品只能经 `POST /api/products` 创建，前端仅在下拉里消费 `getList`）。物模型必须挂在产品上，故本任务补一个精简产品管理页（列表 + 新建 / 编辑 / 停用启用 / 删除）作为物模型入口 |
| 前端编辑器 | 工作台产品物模型页：属性 / 事件 / 服务三区 + 动态表单 + 导入导出 |

### 2.2 不在范围内（明确排除）

- **命令下发 / 服务调用**：归 T-15（本任务只定义服务的入参 / 出参结构，不实现下发）
- **设备影子**：归 T-16（本任务只产出「属性最新值」，不做 desired/delta）
- **属性历史时序与聚合**：归 L8 / T-21（本任务只存最新值，不建时序表）
- **自定义脚本解析**：主流平台的「脚本解析」本期不做，仅支持 Alink JSON 子集
- **物模型多版本历史与灰度**：只保留「当前版本 + 版本号」，不做版本列表与回滚
- **子设备 / 网关拓扑**：归 L11

## 3. 术语

| 术语 | 含义 |
|------|------|
| TSL | Thing Specification Language，物模型描述语言 |
| 属性 property | 设备状态量（如温度），有读写权限 |
| 事件 event | 设备主动上报的通知（info / alert / fault） |
| 服务 service | 云端可调用的能力，有入参出参 |
| 标识符 identifier | 属性 / 事件 / 服务的程序化名称，全局唯一 |
| Alink JSON | 阿里云定义的上下行 JSON 格式，本项目采用其**兼容子集** |
| 数据解析 | 把上行原始 payload 按物模型翻译成属性值 / 事件记录的过程 |

## 4. 物模型数据结构（TSL）

存储于 `product.thing_model`（MySQL `JSON` 类型，与 `device.metadata` 一致），应用侧以 `String` 承载。

### 4.1 顶层结构

```json
{
  "schemaVersion": "1.0",
  "properties": [],
  "events": [],
  "services": []
}
```

三个集合均可为空数组；`schemaVersion` 固定 `"1.0"`，用于后续结构演进。

### 4.2 属性 property

```json
{
  "identifier": "temperature",
  "name": "环境温度",
  "dataType": { "type": "float", "min": -40, "max": 125, "step": 0.1, "unit": "℃" },
  "accessMode": "r",
  "required": false,
  "description": "摄氏度"
}
```

| 字段 | 必填 | 说明 |
|------|------|------|
| identifier | 是 | `^[a-zA-Z][a-zA-Z0-9_]{0,31}$`，全局唯一 |
| name | 是 | 展示名，≤ 64 字符 |
| dataType | 是 | 见 4.5 |
| accessMode | 是 | `r`（只读，仅设备上报）/ `rw`（可读可写，允许云端下发 set） |
| required | 否 | 默认 `false`；`true` 表示影子中该属性缺失即视为 `delta` 未收敛 |
| description | 否 | ≤ 255 字符 |

### 4.3 事件 event

```json
{
  "identifier": "highTempAlarm",
  "name": "高温告警",
  "type": "alert",
  "outputData": [
    { "identifier": "value", "name": "触发温度", "dataType": { "type": "float", "unit": "℃" } }
  ],
  "description": "温度超过阈值时上报"
}
```

| 字段 | 必填 | 说明 |
|------|------|------|
| identifier | 是 | 同上，全局唯一 |
| name | 是 | 展示名 |
| type | 是 | `info` / `alert` / `fault`（对齐主流平台事件分级） |
| outputData | 否 | 输出参数数组，元素结构同 `struct` 成员 |
| description | 否 | ≤ 255 字符 |

### 4.4 服务 service

```json
{
  "identifier": "setMode",
  "name": "设置工作模式",
  "callType": "async",
  "inputData": [
    {
      "identifier": "mode",
      "name": "工作模式",
      "dataType": { "type": "enum", "specs": { "0": "自动", "1": "手动" } },
      "required": true
    }
  ],
  "outputData": [
    { "identifier": "accepted", "name": "是否接受", "dataType": { "type": "bool" } }
  ],
  "description": "切换设备工作模式"
}
```

| 字段 | 必填 | 说明 |
|------|------|------|
| identifier | 是 | 同上，全局唯一 |
| name | 是 | 展示名 |
| callType | 是 | `sync`（云端等待回执，超时判失败）/ `async`（发后即返回） |
| inputData | 否 | 入参数组，元素含 `required`（默认 `true`） |
| outputData | 否 | 出参数组 |
| description | 否 | ≤ 255 字符 |

### 4.5 数据类型 dataType

| type | 附加约束 | 示例 |
|------|----------|------|
| `int` | `min` / `max` / `step`（整数）/ `unit` 可选 | `{"type":"int","min":0,"max":100,"step":1,"unit":"%"}` |
| `float` / `double` | `min` / `max` / `step`（>0）/ `unit` 可选 | `{"type":"float","min":-40,"max":125,"step":0.1}` |
| `bool` | `boolValue` 可选（`{"0":"关","1":"开"}`） | `{"type":"bool"}` |
| `text` | `length`（1~10240） | `{"type":"text","length":64}` |
| `date` | 无 | `{"type":"date"}` |
| `enum` | `specs` 必填、非空、键唯一 | `{"type":"enum","specs":{"0":"关","1":"开"}}` |
| `struct` | `specs` 必填、非空，元素含 `identifier` / `name` / `dataType` | `{"type":"struct","specs":[...]}` |
| `array` | `item` 必填（一个 dataType） | `{"type":"array","item":{"type":"int","min":0,"max":10}}` |

> `struct` 支持嵌套，递归深度上限 **5 层**，防止构造畸形模型。

## 5. 校验规则

保存 / 导入时在服务端一次性校验，任一条不通过则整份拒绝（返回首个错误路径，如 `properties[0].identifier`）。

| # | 规则 |
|---|------|
| V1 | `schemaVersion` 必须为 `"1.0"` |
| V2 | 三个集合均须存在（可为空数组），元素须为对象 |
| V3 | `identifier` 匹配 `^[a-zA-Z][a-zA-Z0-9_]{0,31}$` |
| V4 | `identifier` 在**属性 + 事件 + 服务**范围内**全局唯一**（对齐主流平台） |
| V5 | `identifier` 不得为保留字：`id` / `version` / `method` / `params` / `code` / `data` |
| V6 | 数量上限：属性 ≤ 200、事件 ≤ 100、服务 ≤ 100 |
| V7 | `name` 非空且 ≤ 64 字符；`description` ≤ 255 字符 |
| V8 | `dataType.type` ∈ `{int,float,double,bool,text,date,enum,struct,array}` |
| V9 | 数值类型：`min ≤ max`，`step > 0`；`int` 的 `min/max/step` 必须为整数 |
| V10 | `enum.specs` 非空、键唯一、键 ≤ 32 字符 |
| V11 | `struct.specs` 非空、成员 `identifier` 在结构体内唯一、递归深度 ≤ 5 |
| V12 | `array.item` 必须存在且为合法 dataType |
| V13 | `text.length` ∈ `[1, 10240]` |
| V14 | 属性 `accessMode` ∈ `{r, rw}` |
| V15 | 事件 `type` ∈ `{info, alert, fault}` |
| V16 | 服务 `callType` ∈ `{sync, async}` |

校验实现放在 `ThingModelValidator`（纯函数、无副作用），便于单测穷举。

## 6. 数据模型与迁移（Flyway V4）

### 6.1 `product` 表扩展

```sql
ALTER TABLE product ADD COLUMN thing_model JSON NULL COMMENT '物模型 TSL JSON';
ALTER TABLE product ADD COLUMN thing_model_version INT NOT NULL DEFAULT 0 COMMENT '物模型版本号，每次保存 +1';
ALTER TABLE product ADD COLUMN thing_model_updated_at DATETIME NULL COMMENT '物模型最后保存时间';
```

- `metadata_schema` **保留不删**（历史字段，避免破坏既有数据），在文档与前端标注为「已废弃，请使用物模型」；
- 版本号从 `0` 起，首次保存为 `1`；T-15 的命令参数校验需读取当时版本（本期只存当前值）。

### 6.2 新增 `device_property_latest`

```sql
CREATE TABLE IF NOT EXISTS device_property_latest (
    id BIGINT AUTO_INCREMENT PRIMARY KEY,
    device_id BIGINT NOT NULL COMMENT '设备ID',
    identifier VARCHAR(64) NOT NULL COMMENT '属性标识符',
    data_type VARCHAR(16) NOT NULL COMMENT '数据类型（落库时的物模型定义）',
    value_text TEXT COMMENT '属性值（统一以文本存储，按 data_type 解释）',
    reported_at DATETIME(3) NOT NULL COMMENT '设备上报时间',
    updated_at DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '云端更新时间',
    UNIQUE KEY uk_device_identifier (device_id, identifier),
    INDEX idx_identifier (identifier),
    FOREIGN KEY (device_id) REFERENCES device(id) ON DELETE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='设备属性最新值';
```

- 只保留**最新值**（时序归 T-21）；
- `value_text` 统一文本化：`bool` 存 `true/false`，数值存十进制字符串，`enum` 存键，`struct/array` 存 JSON 文本；
- 写入用 `INSERT ... ON DUPLICATE KEY UPDATE`，且**仅当 `reported_at` 不早于库中值**才更新（防乱序旧包覆盖新值，与 `updateStatusGuarded` 同一思路）。

### 6.3 新增 `device_event_record`

```sql
CREATE TABLE IF NOT EXISTS device_event_record (
    id BIGINT AUTO_INCREMENT PRIMARY KEY,
    device_id BIGINT NOT NULL COMMENT '设备ID',
    identifier VARCHAR(64) NOT NULL COMMENT '事件标识符',
    event_type VARCHAR(16) NOT NULL COMMENT 'info/alert/fault（落库时的物模型定义）',
    output_data JSON COMMENT '事件输出参数',
    reported_at DATETIME(3) NOT NULL COMMENT '设备上报时间',
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP COMMENT '入库时间',
    INDEX idx_device_reported (device_id, reported_at),
    INDEX idx_identifier (identifier),
    FOREIGN KEY (device_id) REFERENCES device(id) ON DELETE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='设备事件记录';
```

- 事件是**追加型**记录，不做去重（去重属告警中心 L4 的抑制窗口职责）。

## 7. 上行数据解析

### 7.1 载荷格式（Alink JSON 兼容子集）

设备上报 `device/{deviceKey}/data`：

```json
// 属性上报
{ "id": "1001", "version": "1.0", "method": "thing.event.property.post",
  "params": { "temperature": 25.3, "humidity": 60 } }

// 事件上报
{ "id": "1002", "version": "1.0", "method": "thing.event.post",
  "params": { "eventId": "highTempAlarm", "value": { "value": 88.5 } } }
```

- `id`：设备侧消息序号，仅用于回执关联（T-15）；
- `method`：解析分派依据；
- 属性上报的 `params` 为 `identifier → 值` 平铺映射；事件上报的 `params.eventId` 指定事件，`params.value` 为其输出参数。

### 7.2 解析流程

在**摄取事务提交后**执行（与 Webhook / SSE 同为提交后副作用），保证「解析出的属性值一定有对应消息记录」：

```
IngestWorker.persist() → 事务提交
   └─ IngestDispatcher.dispatch(events)
        ├─ Webhook 分发（既有）
        ├─ SSE 实时广播（既有）
        └─ ThingModelInterpretService.interpret(events)   ← 新增
```

`interpret` 逐条处理 `messageType == "data"` 的事件：

| 步骤 | 处理 |
|------|------|
| 1 | 取该设备所属产品的物模型（**缓存优先**，未命中回源并回填） |
| 2 | 物模型为空 → 记为「未建模」，跳过（不报错） |
| 3 | payload 非合法 JSON 或缺 `method` → 记为「未解析」，跳过（**原始消息已落库，不丢**） |
| 4 | `method == thing.event.property.post` → 逐个 identifier：命中属性定义则 upsert `device_property_latest`；未命中记 `unknown_identifier` 指标 |
| 5 | `method == thing.event.post` → `params.eventId` 命中事件定义则插入 `device_event_record`；未命中记 `unknown_identifier` |
| 6 | 其它 `method`（含 T-15 的回执）→ 本期跳过 |

**失败隔离**：单条消息解析异常只记 WARN + 指标，不中断本批其余消息，**不进入死信**（死信只兜「落库失败」，解析是派生数据）。

### 7.3 兼容与降级

- **未建模产品**（含存量 `legacy` 产品）：解析整体跳过，行为与现状完全一致；
- **非 Alink 载荷**：跳过解析，原始 payload 仍完整落 `message` 表（既有监控 / 历史查询不受影响）；
- **物模型缓存**：进程内 `ConcurrentHashMap` + TTL（`app.thing-model.cache-ttl-seconds`，默认 60，`0` 关闭），保存物模型时**主动失效本副本**；多副本收敛窗口 = TTL（与 `ACL_CACHE_TTL` 同一「TTL 兜底」思路，文档明示）；
- **解析总开关**：`app.thing-model.interpret-enabled`（默认 `true`），关闭后整条解析链路退化为现状。

### 7.4 指标

| 指标 | 含义 |
|------|------|
| `thing_model_interpret_total{result="property"}` | 成功写入的属性值条数 |
| `thing_model_interpret_total{result="event"}` | 成功写入的事件条数 |
| `thing_model_interpret_total{result="unparsed"}` | 非 Alink 载荷 |
| `thing_model_interpret_total{result="unmodeled"}` | 产品无物模型 |
| `thing_model_interpret_total{result="unknown_identifier"}` | 载荷含未定义标识符 |
| `thing_model_interpret_total{result="error"}` | 解析异常 |

## 8. 后端接口设计

统一挂在 `ProductController`（`/api/products`）下，权限与产品管理一致（查询：登录用户；写入：`ADMIN`，与现有产品写接口口径一致）。

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/products/{id}/thing-model` | 返回 `{thingModel, version, updatedAt}`；未建模返回 `thingModel: null` |
| PUT | `/api/products/{id}/thing-model` | 保存物模型（先校验，通过后版本号 +1 并失效缓存） |
| DELETE | `/api/products/{id}/thing-model` | 清空物模型（版本号 +1，缓存失效） |
| POST | `/api/products/{id}/thing-model/validate` | 只校验不保存，返回校验结果与错误路径 |
| GET | `/api/products/{id}/thing-model/export` | 导出 TSL JSON（`application/json` 附件，文件名含 productKey 与版本） |
| POST | `/api/products/{id}/thing-model/import` | 导入 TSL JSON（等价于保存，同样校验） |

**错误码**（沿用 `ResultCode` 风格）：

| 码 | 场景 |
|----|------|
| 6101 | 物模型 JSON 解析失败 |
| 6102 | 物模型校验不通过（message 带首个错误路径） |
| 6103 | 产品不存在 |

**新增 DTO**：
- `ThingModelRequest`（`thingModel` 字符串）
- `ThingModelResponse`（`thingModel` / `version` / `updatedAt`）
- `ThingModelValidationResponse`（`valid` / `errors: [{path, message}]`）

**新增服务**：
- `ThingModelService`（接口）：`get / save / clear / validate / export / importModel`、`getForProduct(productId)`（供解析链路与 T-15/T-16 复用）
- `ThingModelValidator`：纯校验
- `ThingModelInterpretService`（接口 + impl）：上行解析
- `ThingModelCache`：进程内缓存 + 失效

**新增 Mapper**：`DevicePropertyLatestMapper`、`DeviceEventRecordMapper`（含 `upsertIfNewer` 自定义 SQL）。

> 边界约束：`ThingModelService` 接口不得依赖 `mapper`（ArchUnit 规则 4），持久化细节只出现在 `service.impl`；`ingest` 包只依赖 `service` 接口（规则 2、3）。

## 9. 前端页面设计

### 9.1 路由与入口

新增两条工作台路由（`meta.group: 'monitor'`，与「设备管理」同组）：

| 路径 | name | 说明 |
|------|------|------|
| `/workbench/products` | `ProductList` | 产品管理（列表 + 新建 / 编辑 / 停用启用 / 删除） |
| `/workbench/products/:id/thing-model` | `ProductThingModel` | 物模型编辑器 |

入口：左导航「设备管理」分组新增「产品管理」；产品列表行操作「物模型」跳转编辑器。旧路径无兼容需求（新增页面）。

### 9.2 产品管理页（`ProductList.vue`）

补齐前端缺口，保持精简：

- `el-table` 列：产品标识 / 名称 / 认证方式 / 主题前缀 / 状态 / 物模型版本 / 操作；
- 操作：编辑、**物模型**、停用 / 启用（幂等，沿用 `POST /{id}/disable|enable`）、删除（命中业务码 6003 时提示「该产品下存在设备，无法删除」）；
- 新建 / 编辑用 `el-dialog`（`productKey` / `productName` / `description` / `topicPrefix` / `payloadFormat`）；
- 写操作按 `authStore.hasRole(['ADMIN'])` 置灰（后端仍独立鉴权）；
- 停用 / 删除为不可逆或影响面大的动作，需 `ElMessageBox.confirm` 二次确认。

### 9.3 物模型页结构（沿用工作台五区骨架）

```
PageHeader（产品名 + 版本徽标 + 「导入 / 导出 / 保存」动作）
├── el-tabs
│   ├── 属性  → el-table（标识符 / 名称 / 数据类型 / 读写 / 单位 / 操作）
│   ├── 事件  → el-table（标识符 / 名称 / 类型 / 输出参数数 / 操作）
│   └── 服务  → el-table（标识符 / 名称 / 调用方式 / 入参出参数 / 操作）
└── 编辑抽屉（el-drawer）：按数据类型动态渲染表单
```

- 顶部展示「未保存」脏标记；离开页面前 `onBeforeRouteLeave` 二次确认；
- 版本徽标显示 `thing_model_version`，保存成功后刷新；
- 校验失败时 `el-message` 提示错误路径（如 `properties[0].identifier 不合法`）。

### 9.4 动态表单（数据类型编辑器）

`ThingModelTypeEditor.vue` 递归组件：选择 `type` 后展开对应约束字段；`struct` 递归渲染成员列表；`array` 渲染 `item` 编辑器。属性 / 事件输出参数 / 服务入参出参**复用同一组件**。

### 9.5 数据流

- 服务端状态用 Vue Query（`useQuery` / `useMutation`），`queryKey: ['thing-model', productId]`；
- API 层新增 `frontend/src/api/product.js` 的物模型方法（`getThingModel` / `saveThingModel` / `clearThingModel` / `validateThingModel` / `exportThingModel` / `importThingModel`）；
- 导入 / 导出走 `Blob` 下载与文件读取，前端不重复校验（以服务端校验为准）。

### 9.6 属性最新值与事件记录展示（只读）

- 设备详情页新增「属性」区块：读取 `device_property_latest`（新增接口 `GET /api/devices/{deviceKey}/properties`）；
- 设备详情页新增「事件」区块：读取 `device_event_record`（`GET /api/devices/{deviceKey}/events?page=&size=`，分页）。

## 11. 安全与边界

- 物模型**写入限 `ADMIN`**，查询限登录用户；跨用户读取他人产品物模型返回 403；
- 导入的 TSL 大小上限 **256 KB**，超限直接拒绝（防大 payload 拖垮校验）；
- 解析链路**只读**物模型、只写派生表，不回写设备 / 产品主数据；
- 属性值写入前按 `dataType` 做**类型与范围校验**，不合法则该 identifier 计 `unknown_identifier` 或跳过（不写库），避免脏值污染影子；
- 物模型缓存只缓存定义（非敏感），不做权限判定缓存。
