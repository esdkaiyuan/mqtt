# T-37 设备调试中心与属性代码 实施计划

> 版本：v1.1　创建日期：2026-10-21　最后更新：2026-10-21　状态：**已交付**
> 目标：对标 ThingsCloud「设备调试」与阿里云 IoT「在线调试」，补齐平台侧的**连接信息 → 上行模拟 → 实时报文 → 属性代码**闭环。

---

## 1. 为什么做

平台已有设备详情、属性最新值、命令下发、SSE 实时流与开放 API，但缺一条「联调入口」：

- 新设备接入时，用户不知道 Broker 地址、Topic 形状、用户名格式与上报载荷长什么样；
- 设备还没上电时，无法验证物模型解析、规则、告警、影子是否配置正确；
- 上位机开发者需要自己翻文档拼 Open API 调用，容易在路径 / 鉴权 / 参数上反复试错。

本任务把上述信息**按当前设备即时生成**，并提供一条与真实设备**完全同形**的模拟上行通道。

---

## 2. 设计决策（后续勿推翻）

1. **模拟上行走平台代理注入，不直连 Broker**
   - 设备密钥以 BCrypt 哈希存储，无法回显明文；浏览器直连必须重置密钥，既破坏现网设备又会泄露凭据。
   - 代理注入复用 `IngestPipeline`，与 MQTT / HTTP 上报**同分片、同落库、同六路 fan-out**：物模型解析、影子、规则、告警、Webhook、SSE 全部真实触发。
   - 控制台只拿登录态，不接触设备密钥；写操作只对 ADMIN / OPERATOR 开放并发审计日志。
2. **连接信息是「只读投影」**
   - Broker 地址取 `app.debug.public-broker-host`（部署时填公网域名 / IP），端口取 `.env` 的 MQTT 端口；不读、不返回平台账号密码。
   - 用户名格式固定 `{productKey}.{deviceKey}`；密码位只显示「创建 / 重置设备时一次性展示」，避免误导。
3. **Topic 以产品模板为准**
   - 上行 / 下行主题由 `TopicPrefixResolver.resolve(product.topicPrefix, productKey, deviceKey)` 计算，不硬编码 `device/{key}`。
4. **属性代码是模板生成，不是运行时代码执行**
   - 设备端提供 JavaScript / Python / Java / Arduino 四种最小可运行样例；
   - 上位机端提供 JavaScript / Python / Java 三种 Open API 样例（查询属性、写期望值、下发命令）；
   - 样例中的物模型字段、Topic、deviceKey 均来自当前设备，密钥 / API Key 用显式占位符。
5. **模拟报文只做结构校验，不替代设备端校验**
   - `data` / `reply` / `ota` 必须是 JSON 对象；`heartbeat` / `lwt` 允许空或文本；
   - 不按物模型拒绝未知字段：真实设备也会上报未知字段，调试链路必须保持同形。
   - 载荷上限沿用 `app.http-ingest.max-payload-bytes`（默认 64KB）。

## 3. 交付内容

### 3.1 后端端点（`DeviceDebugController`）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/devices/{deviceKey}/debug/context` | 连接参数、Topic、物模型投影、属性最新值、能力 |
| POST | `/devices/{deviceKey}/debug/simulate` | 模拟上行（data / heartbeat / lwt / reply / ota） |
| GET | `/devices/{deviceKey}/debug/code` | 生成属性代码（target=device/host，language=javascript/python/java/arduino） |

- 归属校验与 `DeviceController` 同口径：设备不存在 2002，非本人（非 ADMIN）2003。
- `POST /simulate` 在 `SecurityConfig` 限定 ADMIN / OPERATOR；GET 端点任意登录用户可读。
- 开关：`app.debug.enabled`（默认 `true`），关闭时控制器不注册，端点 404。

### 3.3 模拟上报

- 构造 `IngestRecord(deviceKey, 产品模板主题 + messageType, messageType, payload, qos, now, traceId)`；
- QoS 与 MQTT 侧一致：`heartbeat=0`，其余 `1`；
- **`data` 必须使用 Alink 信封**：`{"id":"debug","version":"1.0","method":"thing.event.property.post","params":{...}}`。
  物模型解析链路只处理带 `method` 与 `params` 的对象；平铺的 `{temperature:25}` 会被记为「无法解析」，
  表现为上报成功但属性不动。
- 返回 `{ topic, messageType, size, submitted, acceptedAt }`；`submitted=false` 表示摄取管线已关闭，本次未提交；
- 审计日志：`操作者 userId + deviceKey + messageType + size`，不记录完整 payload（可能含敏感数据）。

### 3.4 属性代码

| target | language | 内容 |
|---|---|---|
| device | javascript | `mqtt` 包连接、上报属性、订阅下行并回执 |
| device | python | `paho-mqtt` 同构样例 |
| device | java | Eclipse Paho 同构样例 |
| device | arduino | PubSubClient + WiFi 样例 |
| host | javascript | `fetch` 调用开放 API：查属性 / 写影子 / 下发命令 |
| host | python | `requests` 同构样例 |
| host | java | `java.net.http` 同构样例 |

设备端样例统一上报 Alink 属性信封（`method=thing.event.property.post` + `params`），与真实设备接入格式一致；回执使用 `{id, code, data}`。

生成规则：

- 属性样例值按类型给出：`bool→true`、`int/float→min 或 0`、`enum→首个枚举键`、`text→"hello"`、`date→当前格式样例`、`struct/array→{}` / `[]`；
- 只使用 `rw` 属性生成写样例，`r` 属性只生成读样例；
- 无物模型时生成最小心跳 / 心跳上报样例，并在注释中说明「请先定义物模型」。

## 4. 前端

新增 `/workbench/devices/:id/debug` 页面（设备详情「调试」入口进入），四个页签：

1. **连接信息**：Broker 地址、用户名、密码提示、Topic 表、一键复制；
2. **上行模拟**：消息类型、TSL 生成的 JSON 模板、发送、返回的 Topic / 时间 / 大小；
3. **实时报文**：消费全局 SSE（按 `deviceKey` 过滤）+ 最近命令记录，展示 Topic / 载荷 / 时间；
   下方提供与设备详情同源的「属性设置 / 服务调用」下行控制面板（仅 ADMIN / OPERATOR）；
4. **属性代码**：设备端 / 上位机端切换、语言切换、高亮代码、复制、下载。

## 7. 明确不做

- 浏览器直连 EMQX（理由见 §2.1）；
- 设备密钥明文回显；
- 任意 Topic 发布（只允许当前设备的标准上行主题）；
- 模拟下行链路的「伪造设备回执」以外的协议扩展（OTA / 点表回执已有专用通道）。
