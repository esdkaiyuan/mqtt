# T-48 分组级权限共享 实施计划

> 版本：v1.0　创建日期：2026-10-22　状态：已交付
> 目标：补齐 G-8-1，把设备分组从「严格按 `user_id` 私有」扩展为「所有者可向其他用户共享分组子树」，并提供 VIEW / OPERATE 两档权限与集中式访问判定。

---

## 1. 背景与范围

T-18 引入的设备分组与标签严格按 `user_id` 私有：分组树、组内设备、批量操作全部以当前用户为边界，跨用户只能各自维护一套分组。主流平台普遍支持「分组共享 / 成员授权」，本任务补齐该能力：

- 分组所有者可按用户名或邮箱添加成员，授予 `VIEW` 或 `OPERATE`；
- 权限沿分组祖先链继承：给父分组授权，成员自动获得整棵子树的对应权限；
- 被共享成员可在分组管理页看到共享分组及其子树，并查看组内设备；
- `VIEW` 只读；`OPERATE` 还可下发命令、写影子（仍需叠加平台 ADMIN / OPERATOR 角色闸门）；
- 分组结构、设备关联、成员管理仍仅限所有者；
- 共享分组只出现在分组管理页，不渗入场景 / 规则 / OTA 等「仅本人目标」选择器。

不在本任务范围：标签共享（标签仍严格私有）、按设备的细粒度共享、跨用户设备所有权转移、共享审计日志、组织 / 团队模型。

---

## 2. 权限模型

| 级别 | 是否落库 | 来源 | 能力 |
|---|---|---|---|
| `OWNER` | 否 | 分组 `user_id` / 设备 `owner_id` / 平台 ADMIN | 分组结构与成员管理、设备全部能力 |
| `OPERATE` | 是 | `device_group_member.permission` | 查看分组子树与设备、下发命令、写影子（叠加平台角色） |
| `VIEW` | 是 | `device_group_member.permission` | 查看分组子树与设备、属性 / 事件 / 命令记录 / 影子只读 |
| `NONE` | 否 | 无成员关系 | 拒绝，分组 6310 / 设备 2003 |

判定规则：

1. 分组所有者直接 `OWNER`；否则从目标分组沿 `parent_id` 上溯，逐级查成员表，命中即返回该级权限（最近祖先优先，祖先链最大 5 层）；无命中 `NONE`。
2. 设备所有者 / 平台 ADMIN 直接 `OWNER`；否则取设备所属全部分组的最高权限（`OWNER > OPERATE > VIEW > NONE`）。
3. `OWNER` 仅作为判定结果，不写入成员表；成员表只允许 `VIEW` / `OPERATE`。
4. 多组分归属时取最高权限；共享分组自身及全部后代自动可见。

## 3. 后端实现

### 3.1 数据模型与常量

- `V26__device_group_member.sql`：新增 `device_group_member`（`group_id` + `user_id` 唯一、`permission`、时间戳；分组 / 用户外键 `ON DELETE CASCADE`，`user_id + updated_at` 索引）。
- `GroupPermission`：`VIEW` / `OPERATE` / `OWNER` / `NONE`，提供 `SHARED` 集合、`rank`、`max`、`canView`、`canOperate`。
- `DeviceGroupMember` / `DeviceGroupMemberMapper` / `DeviceGroupMemberRequest` / `DeviceGroupMemberVO`。
- `DeviceGroup` 增加非持久化字段 `shared` / `sharedPermission`；`Device` 增加非持久化字段 `accessLevel`。

### 3.2 集中访问判定

`DeviceAccessService` / `DeviceAccessServiceImpl`：

- `resolveGroup(userId, groupId)`：返回 `GroupAccess(group, level)`；不存在的分组返回 `null` + `NONE`。
- `resolveGroupLevel`：只取级别，供设备判定复用。
- `resolveDeviceLevel(userId, role, deviceId)`：设备不存在 / 已删除返回 `NONE`；所有者与 ADMIN 短路；否则遍历设备所属分组取最高级别，命中 `OPERATE` 提前返回。
- `canViewDevice` / `canOperateDevice`：语义化封装。
- `sharedGroups(userId)`：查用户全部成员关系，按成员根分组展开子树（`selectDescendantIds`），同组多来源取最高权限，跳过自己拥有的分组，标记 `shared=true` / `sharedPermission`。
- 读取路径**无缓存**：成员变更、分组移动立即生效，避免多副本缓存失效窗口。

### 3.3 分组服务与成员管理

- `DeviceGroupService.tree(userId)` / `list(userId)` 保持原语义；新增 `tree(userId, includeShared)` / `list(userId, includeShared)`，`includeShared=true` 时合并 `sharedGroups` 并按 id 去重。
- `getAccessible(userId, groupId)`：`resolveGroup` 后不存在抛 `6212`、无权限抛 `6310`；回填 `shared` / `sharedPermission` / `deviceCount`。
- `pageDevices`：按访问级别决定设备查询边界 —— `OWNER` 用分组所有者过滤，共享成员不带 ownerId；分组范围始终取目标分组子树。
- `DeviceService.getDevicesInGroups(dto)`：共享分页专用；空分组范围直接返回空页，**绝不退化为全表**。
- 成员管理四端点（仅所有者）：
  - `GET /device-groups/{id}/members`：回填用户名 / 邮箱；
  - `POST /device-groups/{id}/members`：按用户名或邮箱查找 ACTIVE 用户；不能共享给自己或所有者；重复添加幂等更新权限；
  - `PUT /device-groups/{id}/members/{memberId}`：修改权限；
  - `DELETE /device-groups/{id}/members/{memberId}`：移除成员。
- 非法成员 / 权限 `6308`，成员不存在或不属于该分组 `6309`，越权访问 `6310`。

### 3.4 设备读写门禁

- `DeviceController` 读接口统一走 `requireReadableDevice`（详情 / 状态 / 属性 / 事件 / 命令能力 / 命令记录 / 影子），写接口走 `requireOperableDevice`（命令下发 / 写影子 desired）。
- 所有者与 ADMIN 短路为 `OWNER`；其他用户调用 `DeviceAccessService`；不可见抛 `2003`，无操作权同样抛 `2003`；可读设备回填 `accessLevel`。
- `SecurityConfig` 为 `PUT /devices/*/shadow/desired` 补 `ADMIN` / `OPERATOR` 角色闸门，与命令下发对齐 —— 共享 `OPERATE` 不能绕过平台只读角色。
- `PropertyHistoryServiceImpl` 的属性时序查询改为「所有者 / ADMIN / 共享 VIEW 及以上」可读，避免共享设备详情页趋势图 403。

## 7. 关键决策与已知限制

1. **OWNER 不落库**：成员表只存 VIEW / OPERATE，所有者身份始终来自分组 `user_id`，避免「成员表里出现所有者」造成权限来源二义。
2. **祖先链继承而非预展开**：给父分组授权即覆盖整棵子树；分组移动后权限自动跟随，不需要回填成员行。
3. **读取路径不缓存**：分组最多 5 层，逐级查询成本可接受；换来成员变更立即生效，避免多副本缓存失效广播。
4. **共享设备只从分组页进入**：主设备列表仍只显示本人设备，避免「共享设备混入个人设备列表」改变既有列表语义；分组页提供详情跳转。
5. **OPERATE 仍叠加平台角色**：共享操作权不替代 ADMIN / OPERATOR 闸门，VIEWER 即使被授予 OPERATE 也不能写命令 / 影子。
6. **共享分组不进入目标选择器**：`includeShared` 默认 false，场景 / 规则 / OTA 等选择器仍只展示本人分组，防止把设备共享误当成「可配置目标」。
7. **已知限制**：标签仍私有；无共享审计；无组织 / 团队层级；设备详情中的调试、点位表、HMI、日志、凭据、拓扑仍仅所有者可用。
