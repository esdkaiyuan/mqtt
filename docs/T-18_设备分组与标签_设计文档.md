# T-18 设备分组与标签（Device Groups & Tags）设计文档

> 所属链路：L5 设备分组与标签（`docs/平台功能链路路线图.md` §3）
> 依赖链路：L2 命令下发与服务调用（T-15，批量下发复用命令链路）、L4 告警中心（T-17，同层服务范式）
> 文档状态：待实施
> 最后更新：2026-10-03

---

## 1. 背景与目标

T-14 ~ T-17 已交付「物模型 → 命令 → 影子 → 告警」闭环，但设备在平台上仍是**一张扁平列表**：

- `DeviceList.vue` 只能按名称 / 类型 / 状态过滤，设备一多就无法按业务维度（车间 / 楼层 / 项目）组织；
- 没有任何「批量」入口：给 30 台设备下发同一条命令，只能一台一台点；
- 产品路线图 §2 能力域 8「设备分组与标签」现状为「无」，是主流平台（ThingsCloud / 阿里云 IoT）的标准能力缺口。

本任务引入**设备分组与标签**，把设备列表从「扁平」变成「可组织、可筛选、可批量操作」：

- **分组树**：`device_group` 自引用树（`parent_id`），支持增删改与移动；
- **标签**：`device_tag` 扁平标签（含展示色），一台设备可打多个标签；
- **多对多关联**：`device_group_relation` / `device_tag_relation` 两张关联表；
- **筛选**：设备列表按分组（含子分组）/ 标签过滤；
- **批量操作**：按分组 / 标签 / 手选设备并集，批量下发命令、批量启用 / 禁用、批量加入 / 移出分组、批量打 / 去标签。

目标：

1. **可组织**：分组树任意层级（深度上限 5），可移动（改父节点），同级不重名；标签按用户隔离、不重名。
2. **可筛选**：按分组过滤时**自动包含其所有子分组**的设备；按标签过滤命中打过该标签的设备。
3. **可批量**：批量下发对目标集合**逐台**生成命令记录，单台失败不阻断其余（返回逐台结果汇总）。
4. **可追溯**：批量操作返回 `total / succeeded / failed` 与逐台失败原因，前端可展示明细。
5. **不破坏既有链路**：批量下发完全复用 `DeviceCommandService.invoke`，不新增 MQTT 主题、不改 ACL；批量禁用复用 `DeviceService.disableDevice`（含踢线）。

## 3. 术语

| 术语 | 含义 |
| --- | --- |
| 设备分组（DeviceGroup） | 用户私有的一棵自引用树节点，`parent_id=NULL` 为根分组 |
| 设备标签（DeviceTag） | 用户私有的扁平标签，含展示色，无层级 |
| 关联（Relation） | 设备与分组 / 标签的多对多关系，落在两张关联表，**物理行**（无逻辑删除，解除即物理删） |
| 目标集合（BatchTarget） | 一次批量操作作用的设备集合，由「手选设备 ID ∪ 分组（含子分组）设备 ∪ 标签设备」去重得到 |
| 后代分组（descendant） | 某分组自身及其所有层级子分组；按分组筛选与批量下发均**包含后代** |
| 空分组 | 无子分组且无关联设备的分组；仅空分组可删除 |

## 4. 主题方案

### 4.1 不新增 MQTT 主题、不改 ACL

分组与标签是**纯服务端组织结构**：

- 批量下发命令完全复用 T-15 的 `device/{deviceKey}/cmd/down`（逐台调用既有 `DeviceCommandService.invoke`），**不新增任何主题**；
- 批量禁用复用 T-15/T-16 的 `enabled` 语义与 `EmqxClientKicker` 踢线，**不改认证 / 授权回调**；
- 分组与标签本身**不下发到设备**（设备端不感知分组，纯云端组织维度）。

因此 ACL、QoS、保留消息策略**均无变化**（继续 QoS 1、不保留，沿用 T-15 §4）。

### 4.2 权限与隔离

- 分组、标签、关联全部按 `user_id` 隔离；接口层用 `SecurityUtils.requireUserId()` 取当前用户。
- 所有设备归属校验复用 `DeviceController.checkOwnership` 的语义：非本人设备返回 `2003`（`DEVICE_NOT_OWNED`）。
- 分组 / 标签资源越权（访问他人分组）统一返回 `403`（沿用 `AlertController` 的 `FORBIDDEN` 处理方式），不新增同义码。
- 批量操作的目标集合在服务端**再次按当前用户过滤**（即使前端传了他人设备 ID 也会被剔除），避免越权下发。

### 4.3 为什么设备与分组是「多对多」而非「一对一」

- 阿里云 IoT 设备分组为多对多（一台设备可加入多个分组），更贴合「一台设备同时属于『产线 A』与『厂区 1』」的真实组织；
- 关联表天然支持「按分组筛选」「批量下发」的集合语义，且不与分组树的层级耦合；
- 代价：需处理「设备同时属于父分组与子分组」——按父分组筛选时二者都会被选中，属**预期行为**（去重后不影响批量下发次数）。

### 4.4 为什么删除分组要求「空分组」

- 级联删除子树风险大（误删一整棵组织树且不可见后果），「空分组才可删」把破坏面收敛到最小；
- 设备本身**永不因分组删除而被删**（关联解除即可），符合「分组只是组织维度」的定位；
- 非空分组返回 `6216`，前端提示「请先移动子分组或移出设备」，操作路径明确。

## 5. 载荷格式

### 5.1 分组 / 标签返回体

统一走既有 `Result<T>` 信封。分组返回 `DeviceGroup` 实体字段；树查询返回**带 `children` 的投影**（见 §10.1）。

```json
// GET /device-groups/tree
{
  "code": 200,
  "data": [
    {
      "id": 1, "parentId": null, "name": "华东厂区", "sortOrder": 0,
      "description": "上海基地", "deviceCount": 12,
      "children": [
        { "id": 2, "parentId": 1, "name": "1 号车间", "sortOrder": 0, "deviceCount": 5, "children": [] }
      ]
    }
  ]
}
```

### 5.2 批量操作返回体（`BatchOperationResult`）

```json
{
  "code": 200,
  "data": {
    "total": 3,
    "succeeded": 2,
    "failed": 1,
    "items": [
      { "deviceId": 11, "deviceKey": "dev-001", "deviceName": "温控器-1", "success": true,  "commandId": "8f1c…a1", "status": "SENT", "error": null },
      { "deviceId": 12, "deviceKey": "dev-002", "deviceName": "温控器-2", "success": true,  "commandId": "9a2d…b7", "status": "QUEUED", "error": null },
      { "deviceId": 13, "deviceKey": "dev-003", "deviceName": "温控器-3", "success": false, "commandId": null, "status": null, "error": "产品未定义物模型，无法下发命令" }
    ]
  }
}
```

- 命令类批量额外带 `commandId` / `status`；启用 / 禁用 / 关联类批量 `commandId` / `status` 为 `null`。
- `error` 为失败原因文案（取自 `BusinessException` 的 message），成功时为 `null`。

## 6. 数据模型（Flyway `V8`）

> 迁移原则：**只加表、只加列**，不改既有列；应用版本可安全回滚（回滚后新旧表共存，旧代码忽略新表）。

### 6.1 新表 DDL

```sql
-- V8：设备分组与标签（T-18）
-- 1) device_group          分组树（自引用）
-- 2) device_tag            标签（扁平）
-- 3) device_group_relation 设备-分组多对多
-- 4) device_tag_relation   设备-标签多对多
-- 只加表，不改既有列，应用版本可安全回滚。
-- 关联表为物理行（无 deleted 列）：解除关联即物理删除，避免逻辑删除与唯一键冲突。

CREATE TABLE IF NOT EXISTS device_group (
    id BIGINT AUTO_INCREMENT PRIMARY KEY,
    user_id BIGINT NOT NULL COMMENT '归属用户',
    parent_id BIGINT NULL COMMENT '父分组ID，NULL=根分组',
    name VARCHAR(64) NOT NULL COMMENT '分组名称',
    sort_order INT NOT NULL DEFAULT 0 COMMENT '同级排序（升序）',
    description VARCHAR(255) NULL COMMENT '描述',
    created_at DATETIME(3) NOT NULL COMMENT '创建时间',
    updated_at DATETIME(3) NOT NULL COMMENT '更新时间',
    deleted TINYINT(1) NOT NULL DEFAULT 0 COMMENT '逻辑删除：1/0',
    INDEX idx_group_user_parent (user_id, parent_id, deleted),
    CONSTRAINT fk_device_group_parent FOREIGN KEY (parent_id)
        REFERENCES device_group(id) ON DELETE SET NULL
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='设备分组树';

CREATE TABLE IF NOT EXISTS device_tag (
    id BIGINT AUTO_INCREMENT PRIMARY KEY,
    user_id BIGINT NOT NULL COMMENT '归属用户',
    name VARCHAR(64) NOT NULL COMMENT '标签名称',
    color VARCHAR(16) NULL COMMENT '展示色（如 #409EFF）',
    created_at DATETIME(3) NOT NULL COMMENT '创建时间',
    updated_at DATETIME(3) NOT NULL COMMENT '更新时间',
    deleted TINYINT(1) NOT NULL DEFAULT 0 COMMENT '逻辑删除：1/0',
    INDEX idx_tag_user (user_id, deleted)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='设备标签';

CREATE TABLE IF NOT EXISTS device_group_relation (
    id BIGINT AUTO_INCREMENT PRIMARY KEY,
    device_id BIGINT NOT NULL COMMENT '设备ID',
    group_id BIGINT NOT NULL COMMENT '分组ID',
    created_at DATETIME(3) NOT NULL COMMENT '关联时间',
    UNIQUE KEY uk_device_group (device_id, group_id),
    INDEX idx_group_rel_group (group_id),
    CONSTRAINT fk_group_rel_device FOREIGN KEY (device_id) REFERENCES device(id) ON DELETE CASCADE,
    CONSTRAINT fk_group_rel_group FOREIGN KEY (group_id) REFERENCES device_group(id) ON DELETE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='设备-分组关联';

CREATE TABLE IF NOT EXISTS device_tag_relation (
    id BIGINT AUTO_INCREMENT PRIMARY KEY,
    device_id BIGINT NOT NULL COMMENT '设备ID',
    tag_id BIGINT NOT NULL COMMENT '标签ID',
    created_at DATETIME(3) NOT NULL COMMENT '关联时间',
    UNIQUE KEY uk_device_tag (device_id, tag_id),
    INDEX idx_tag_rel_tag (tag_id),
    CONSTRAINT fk_tag_rel_device FOREIGN KEY (device_id) REFERENCES device(id) ON DELETE CASCADE,
    CONSTRAINT fk_tag_rel_tag FOREIGN KEY (tag_id) REFERENCES device_tag(id) ON DELETE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='设备-标签关联';
```

> 自引用外键 `fk_device_group_parent` 在逻辑删除下**不会触发** `SET NULL`（逻辑删除不物理删行），仅作为运维物理清理时的完整性兜底。

### 6.2 实体与 Mapper

- `entity/DeviceGroup.java`：`@TableName("device_group")`，字段一一对应；`createdAt` 用 `fill = FieldFill.INSERT`、`updatedAt` 用 `INSERT_UPDATE`；`deleted` 走全局逻辑删除；另加 `@TableField(exist = false) List<DeviceGroup> children`、`Integer deviceCount`（树投影用，不映射库）。
- `entity/DeviceTag.java`：`@TableName("device_tag")`，同上（无 children）。
- `mapper/DeviceGroupMapper.java`：`BaseMapper<DeviceGroup>`，另加：
  - `List<DeviceGroup> selectByUser(@Param("userId") Long)`：`deleted=0`，`ORDER BY sort_order, id`；
  - `int countChildren(@Param("parentId") Long)`：子分组数（删除前置校验）；
  - `List<Long> selectDescendantIds(@Param("userId") Long, @Param("rootId") Long)`：递归 CTE 取某分组及其所有后代 ID（含自身）；
  - `int countByUserAndName(@Param("userId") Long, @Param("parentId") Long, @Param("name") String, @Param("excludeId") Long)`：同级重名校验（`parentId` 为 NULL 时按 `IS NULL` 分支）。
- `mapper/DeviceTagMapper.java`：`BaseMapper<DeviceTag>`，另加 `List<DeviceTag> selectByUser(@Param("userId") Long)`、`int countByUserAndName(...)`。
- `mapper/DeviceGroupRelationMapper.java`：`BaseMapper<DeviceGroupRelation>`，另加：
  - `int insertIgnoreBatch(@Param("deviceIds") Collection<Long>, @Param("groupId") Long, @Param("createdAt") LocalDateTime)`：`INSERT IGNORE` 批量去重；
  - `int deleteByDeviceIdsAndGroup(...)` / `int deleteByDeviceIds(...)`；
  - `List<Long> selectDeviceIdsByGroupIds(@Param("groupIds") Collection<Long>)`；
  - `List<DeviceGroupRelation> selectByDeviceIds(@Param("deviceIds") Collection<Long>)`（列表批量装配用）；
  - `int deleteByGroupId(@Param("groupId") Long)`（删除分组时解除关联）。
- `mapper/DeviceTagRelationMapper.java`：同上对称（`selectDeviceIdsByTagIds` / `selectByDeviceIds` / `deleteByTagId`）。
- `entity/DeviceGroupRelation.java` / `entity/DeviceTagRelation.java`：关联实体（`id` / `deviceId` / `groupId|tagId` / `createdAt`，**无 deleted**）。

### 6.3 递归查询（MySQL 8 递归 CTE）

```sql
-- selectDescendantIds：某分组及其所有后代（含自身），用于「按分组筛选含子分组」
WITH RECURSIVE sub AS (
    SELECT id FROM device_group
    WHERE id = #{rootId} AND user_id = #{userId} AND deleted = 0
    UNION ALL
    SELECT g.id FROM device_group g
    JOIN sub ON g.parent_id = sub.id
    WHERE g.user_id = #{userId} AND g.deleted = 0
)
SELECT id FROM sub
```

> 若目标环境为 MySQL 5.7（不支持 CTE），降级方案：应用层一次性取该用户全部分组，在内存中 BFS 求后代（分组数量级为百，成本可忽略）。**实现时以 CTE 为准，并在 `DEPLOYMENT.md` 记录 5.7 降级说明。**

## 7. 参数校验

### 7.1 分组创建 / 更新校验（`DeviceGroupRequest`）

| 规则 | 校验 | 失败码 |
| --- | --- | --- |
| `name` | 非空，去空白后长度 1~64 | `6213` |
| `name` | 同一用户、同一父节点下不重名（`excludeId` 排除自身） | `6213` |
| `parentId` | 可空；非空时必须存在、属于当前用户、未删除 | `6212` |
| `parentId` | 移动时不得为自身或自身后代（防成环） | `6213` |
| 深度 | 新节点深度 ≤ `MAX_DEPTH=5`（根为 1） | `6213` |
| `sortOrder` | 可空，缺省 0；任意整数 | — |
| `description` | 可空，长度 ≤ 255 | `6213` |

### 7.2 标签创建 / 更新校验（`DeviceTagRequest`）

| 规则 | 校验 | 失败码 |
| --- | --- | --- |
| `name` | 非空，去空白后长度 1~64 | `6215` |
| `name` | 同一用户下不重名（`excludeId` 排除自身） | `6215` |
| `color` | 可空；非空时匹配 `^#[0-9A-Fa-f]{6}$` | `6215` |

### 7.3 批量目标校验（`BatchTargetRequest`）

| 规则 | 校验 | 失败码 |
| --- | --- | --- |
| 并集非空 | `deviceIds ∪ groupIds 展开 ∪ tagIds 展开` 去重后 ≥ 1 | `6217` |
| 上限 | 去重后 ≤ `MAX_BATCH_SIZE=500` | `6217` |
| 归属 | 最终集合按当前用户过滤，剔除他人设备（静默剔除，不报错） | — |
| `groupId` / `tagId` | 非空时校验存在且属于当前用户 | `6212` / `6214` |

### 7.4 批量命令参数

- 复用 T-15 的 `ThingModelParamValidator` 逐台校验（每台设备的物模型可能不同）；
- `type` / `identifier` / `params` 校验失败**只影响该台**，记入该台 `error`，不抛全局异常；
- 批量**强制 `callType=async`**：同步调用需逐台阻塞等待回执（500 台上限下不可接受），传入的 `callType` 被忽略并在响应中体现为异步结果。

## 8. 批量操作计算

### 8.1 目标集合解析（`DeviceBatchService.resolveTarget`）

1. 校验 `groupId` / `tagId` 归属（越权 → `6212` / `6214`）；
2. `groupIds` 逐个展开为「分组 + 后代分组」ID 集合，再查 `device_group_relation` 得设备 ID；
3. `tagIds` 查 `device_tag_relation` 得设备 ID；
4. 与手选 `deviceIds` 取并集、去重；
5. 用 `DeviceService` 按 ID 批量取设备并按 `owner_id = 当前用户` 过滤（剔除他人 / 已删除）；
6. 空集 → `6217`；超上限 → `6217`。

> 解析结果按 `deviceId` 升序稳定输出，保证同一次批量结果可复现、便于测试断言。

### 8.2 批量下发命令（`DeviceBatchService.sendCommands`）

对目标集合逐台：

```
try {
    record = deviceCommandService.invoke(new CommandInvoke(device.id, device.productId,
              type, identifier, paramsJson, ASYNC, SOURCE_CONSOLE, userId));
    items.add(success(device, record.commandId, record.status));
} catch (BusinessException e) {
    items.add(failure(device, e.getMessage()));   // 逐台隔离
}
```

- **逐台隔离**：单台失败（无物模型 / 参数非法 / 发布失败）只记该台 `error`，继续下一台；
- 非 `BusinessException`（如网络异常）同样捕获并记 `error`，仅 WARN 日志，不中断整批；
- 返回 `BatchOperationResult`（`total` / `succeeded` / `failed` / `items`）。

### 8.3 批量启用 / 禁用（`DeviceBatchService.setEnabled`）

- 逐台调用 `deviceService.disableDevice(id)` / `enableDevice(id)`，逐台隔离；
- 禁用复用既有踢线（`AfterCommit` 事务提交后踢）与认证缓存失效；
- 幂等：已是目标状态视为成功（`DeviceServiceImpl.setDeviceEnabled` 内部短路）。

### 8.4 批量关联分组 / 标签（`DeviceBatchService.assignGroup` / `assignTag`）

- `action=ADD`：`INSERT IGNORE` 批量插入关联（唯一键去重，重复关联幂等成功）；
- `action=REMOVE`：按 `(deviceIds, groupId|tagId)` 批量物理删除；
- 校验分组 / 标签归属；设备归属在 §8.1 已过滤；
- 返回 `BatchOperationResult`（关联类不产生 `commandId` / `status`）。

### 8.5 删除分组 / 标签的关联处理

- **删除分组**：先校验 `countChildren=0` 且关联设备数 = 0，否则 `6216`；通过后逻辑删除分组（关联表本已为空）。
- **删除标签**：先物理删除该标签全部关联（`deleteByTagId`），再逻辑删除标签。标签是扁平维度，删除不阻塞。

## 9. 与既有链路的交互边界

- **告警中心（T-17）**：分组 / 标签删除**不影响**告警规则与记录（告警只按 `device_id` / `user_id` 关联），无联动。
- **设备影子（T-16）**：批量下发 `property_set` 时，在线设备直接发布、离线设备照常入 `QUEUED` 并由既有 `ShadowDeliveryService` 补发，**分组逻辑不感知影子**。
- **命令超时巡检（T-15）**：批量产生的命令记录与单台下发完全同构，由既有 `CommandTimeoutSweeper` 统一兜底。
- **摄取管线**：分组 / 标签**不参与**上行解析，`IngestDispatcher` 与各旁路零改动。

## 13. 安全与边界

- **归属隔离**：分组 / 标签 / 关联均按 `user_id` 校验；批量目标集合在服务端按当前用户二次过滤，杜绝越权下发。
- **不阻塞主链路**：批量操作为控制台同步调用，逐台隔离异常，单台失败不影响其余；不进入摄取 / 解析热路径。
- **删除安全**：设备永不被分组 / 标签操作删除；删除分组要求空分组；删除标签仅解除关联。
- **命令一致性**：批量下发复用同一 `DeviceCommandService.invoke`，参数校验、影子写入、离线入队、超时巡检全部沿用，无并行实现。
- **批量上限**：`MAX_BATCH_SIZE=500` 防止一次批量打爆 MQTT 发布与数据库写入；超限返回 `6217`。
- **批量强制异步**：避免 500 台同步等待回执造成的请求长挂（`callType` 被忽略为 `async`）。
- **并发**：`INSERT IGNORE` + 唯一键保证重复关联幂等；分组移动的成环校验在事务内先查后写（并发极端情况下最坏产生短暂环，由深度校验兜底拦截，不影响数据一致性）。
- **物理删除关联**：设备物理删除时关联表由外键 `ON DELETE CASCADE` 清理；逻辑删除设备时关联保留（设备不可见，关联无害）。
