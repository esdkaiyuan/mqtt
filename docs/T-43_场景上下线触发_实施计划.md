# T-43 场景上下线触发 实施计划

> 版本：v1.0　创建日期：2026-10-21　状态：已交付
> 目标：补齐 G-12-4 的「上下线触发」部分，让场景可直接由设备 ONLINE / OFFLINE 状态切换驱动；「影子变更触发」仍留后续任务。

---

## 1. 背景与范围

T-23 场景引擎此前只有 `PROPERTY` / `EVENT` / `TIMER` 三类触发源。运维最常用的「设备离线就通知」「设备上线就下发配置」只能靠属性或定时间接实现，且离线时通常没有新属性上报，实际上无法可靠触发。

本任务交付：

- 新增 `ONLINE` / `OFFLINE` 两个触发源，复用既有条件组、冷却、步骤流、执行记录与试运行；
- 状态写入的两条路径（异步批量摄取、同步 / 巡检）都在**状态真实变化**时发布领域事件；
- 前端表单、画布触发面板、试运行对话框与列表文案同步支持；
- 只更新 `scene_definition.trigger_type` 列注释（`V22`），无表结构 / 索引变更。

不在本任务范围：影子变更触发、上下线触发的开放 API、状态抖动抑制（由冷却窗口承担）。

---

## 2. 触发语义

| 场景触发源 | 命中条件 | 允许字段 | 禁止字段 |
|---|---|---|---|
| `ONLINE` | 设备状态由非 `ONLINE` 变为 `ONLINE` | 可选 `triggerDeviceId`、条件组、步骤流 | 标识符 / 比较符 / 阈值 / 事件类型 / cron |
| `OFFLINE` | 设备状态由非 `OFFLINE` 变为 `OFFLINE` | 同上 | 同上 |

- `triggerDeviceId = null` 表示该账号下任意设备，触发时以实际设备作为作用域与条件组默认设备；
- 状态未变化（例如持续上报 `data` 时设备已在线）不发布事件，因此不会重复触发；
- 乱序旧事件被 `updateStatusGuarded` 的 SQL 守卫丢弃时不发布事件；
- `INGEST` 异步批量路径按 `deviceKey` 取批内最新记录决定状态，一批只产生一个状态事件；
- 触发上下文写入执行记录：`triggerIdentifier=null`、`triggerValue=ONLINE/OFFLINE`、`triggerEventType=null`，模板占位符 `${triggerValue}` 可直接引用状态。

## 3. 后端实现

### 3.1 常量与校验

- `SceneConstants`：新增 `TRIGGER_ONLINE` / `TRIGGER_OFFLINE`，加入 `TRIGGERS`；新增 `STATUS_TRIGGERS` 集合。
- `SceneValidator`：
  - 状态源只允许可选 `triggerDeviceId`，其余触发字段出现即 `6241`；
  - 条件组沿用既有规则（状态源有实际触发设备，条件项 `deviceId` 可空）；
  - 步骤沿用既有规则（`TRIGGER` 目标合法，非定时源约束不变）。
- `SceneTestServiceImpl`：状态源试运行要求 `deviceId`，`value` 为待判定状态，缺省按场景自身状态；不要求 `identifier`。

### 3.2 匹配与评估

- `SceneMatcher.matchesStatusTrigger`：作用域匹配 + 场景状态源与本次状态一致；
- `SceneEvaluationService.onStatus(deviceId, status, occurredAt)`：
  - 加载设备与账号启用场景，逐场景匹配后复用 `fire()`（冷却 → 条件组 → 执行记录）；
  - 全链路 `try/catch` 隔离，异常只记 WARN，不冒泡到状态写入线程；
  - 方法标注 `@Transactional(propagation = REQUIRES_NEW)`：监听器在 `AFTER_COMMIT` 回调中调用，此时连接尚未清理，`REQUIRED` 会误加入已提交事务导致执行记录不落库。

### 3.3 设备状态事件

- `DeviceStatusChangedEvent(deviceId, status, occurredAt)`：只表达「真实切换」；
- 两条发布路径：
  1. `DeviceServiceImpl.updateDeviceStatus`：`statusChanged && ONLINE/OFFLINE` 时发布（legacy 同步链路、心跳超时巡检）；
  2. `IngestPersistenceService.updateDeviceStates`：批量落库时对每台状态变化的设备发布（默认异步摄取链路）；
- `SceneStatusTriggerListener`：`@TransactionalEventListener(phase = AFTER_COMMIT, fallbackExecution = true)` 桥接到 `onStatus`，无事务入口立即执行；监听器自身再兜底一次异常隔离。

选择事件而非直接注入场景服务：设备状态写入路径与场景引擎解耦，事务回滚不触发场景，场景评估耗时也不占用状态更新事务。

## 4. 前端实现

- `utils/scene.js`：新增 `ONLINE` / `OFFLINE` 文案、标签色、下拉选项、`isStatusTrigger`；`normalizeTriggerSource` 清理状态源不支持字段；`formatTriggerSummary` 输出「设备上线 / 设备下线」。
- `SceneFormDialog.vue`：状态源只显示触发设备与说明，隐藏标识符 / 阈值 / 事件类型；提交时 `triggerIdentifier=null`。
- `SceneOrchestrationView.vue`：画布触发节点属性面板同步字段显隐。
- `SceneTestDialog.vue`：状态源只需设备 + 待判定状态（ONLINE / OFFLINE），提交 `value=status`。
- 场景列表与筛选复用统一选项，自动出现两个新触发源。

## 5. 数据库

`V22__scene_status_trigger.sql`：

- `scene_definition.trigger_type` 仍为 `VARCHAR(16)`，长度足够；
- 仅 `MODIFY COLUMN` 同步注释为 `PROPERTY/EVENT/TIMER/ONLINE/OFFLINE`，无类型、索引、数据变更。
