# T-28 规则与告警作用域 实施计划

## 计划概览

- **Goal**：把 `rule_definition` 与 `alert_rule` 的作用域从「单设备 / 全部设备」扩为「全部设备 / 指定设备 / 按分组 / 按标签」四档，分组档含所有后代分组；存量单设备 / 全部设备行为零回归。
- **Architecture**：`scope_type` 判别列 + `group_ids` / `tag_ids` JSON 文本列承载作用域；新增 `DeviceScopeService` 提供「设备 → 隶属」与「作用域 → 设备集合」双方向解析，纯函数 `ScopeMatcher` 承载四档匹配；推评估与离线巡检分别取用对应方向，分组档用「匹配时上溯祖先」而非「落库预展开」，与分组树变更解耦。
- **Tech Stack**：Java 17 + Spring Boot 4.1.1 + MyBatis-Plus 3.5.17 + Flyway + JUnit 5 + Mockito + ArchUnit；Vue 3 控制台。
- **Spec**：`docs/T-28_规则与告警作用域_设计文档.md` v1.0。
- **Global Constraints**：
  - 不改 `MqttMessageHandler`、`IngestPipeline` / `IngestDispatcher` / `IngestPersistenceService`、`emqx-init.sh`。
  - 不改分组与标签写路径（`DeviceGroupServiceImpl` / `DeviceTagServiceImpl` / `DeviceGroupController` / `DeviceTagController`），作用域只读复用其查询与归属校验。
  - 不改 T-17 告警评估四步与抑制窗口逻辑，不改 T-19 规则缓存 / 冷却 / 执行落库与投递链路。
  - 错误码自 6268 起，追加时把 `ResultCode` 末项 `ALERT_ASSIGNEE_INVALID(6267, …)` 的分号改为逗号。
  - 迁移文件为 `V16__rule_alert_scope.sql`，`V1`~`V15` 零改动；两表各只加三列一索引，只加不改。
  - 作用域内分组 / 标签一律按 `user_id` 归属校验，越权返 `403`；`group_ids` / `tag_ids` 只落 ID，不落名称快照。
  - 作用域 JSON 的解析 / 序列化统一走 `ScopeJson`，禁止在评估层另写一份解析。
  - ArchUnit 既有规则不得放松，服务接口不得直接依赖 Mapper（`DeviceScopeService` 只依赖其它服务接口）。
  - 存量行回填后 `scope_type` 的 `ALL` / `DEVICE` 取值必须与旧 `device_id IS NULL` / 非空语义逐位等价。
