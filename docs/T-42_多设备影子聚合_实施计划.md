# T-42 多设备影子聚合视图 实施计划

> 版本：v1.1　创建日期：2026-10-21　状态：**已交付**
> 目标：补齐 G-5-1，把「逐台打开设备详情看影子」升级为「一个表格横向对比多台设备的 desired / reported / delta」。

---

## 1. 为什么做

设备影子已有单设备视图（设备详情「设备影子」面板），但运维在排查「批量下发后哪些设备没收敛」时，需要逐台点开。主流平台通常提供影子列表 / 聚合视图，直接展示：

- 哪些设备存在 `delta`；
- 影子版本是否推进；
- 期望值与上报值差异；
- 最近更新时间。

本批只做**只读聚合**，不改变影子写入与 CAS 语义。

---

## 2. 设计决策（后续勿推翻）

1. **只读、零迁移**
   - 复用 `DeviceShadowService.get(deviceId, productId)`，不新增表、不新增写路径；
   - 不引入缓存：影子是最终一致视图，缓存会掩盖真实差异。
2. **默认只看本人设备**
   - `deviceIds` 不传时返回当前用户名下设备；
   - 显式传 `deviceIds` 时逐台做归属校验：非本人且非 ADMIN 返回 2003；
   - ADMIN 可跨账号显式查询。
3. **最多 200 台**
   - 聚合接口按设备逐台读影子（N+1），200 台是内存与查询次数的折中；
   - 超限显式 400，不静默截断——静默截断会让运维以为已经看全。
4. **不改变单设备端点**
   - `/devices/{deviceKey}/shadow` 保持原样；聚合端点是并列的只读视图。

---

## 3. 端点与响应

`GET /api/devices/shadow-summary?deviceIds=1,2,3`

```json
{
  "code": 200,
  "data": [
    {
      "deviceId": 1,
      "deviceKey": "dev-1",
      "deviceName": "温湿度传感器",
      "status": "ONLINE",
      "modeled": true,
      "version": 12,
      "desired": { "power": "true" },
      "reported": { "power": "false" },
      "delta": { "power": "true" },
      "updatedAt": "2026-10-21 12:00:00"
    }
  ]
}
```

## 4. 前端

- 左导航「监控」组新增「设备影子」（`/workbench/shadows`）；
- 页面顶部显示设备数 / 存在差异数 / 已建模数；
- 表格行支持展开查看 desired / reported / delta 完整 JSON；
- 点击设备跳转设备详情 `#device-shadow-section`；
- 刷新按钮重新拉取。

## 5. 测试

- 后端 `DeviceShadowSummaryControllerTest`：默认本人设备、显式非归属 2003、ADMIN 跨账号、超过 200 台拒绝；
- 前端 `shadowSummary.spec.js`：无参 / 显式设备集合的路径与参数；
- 路由快照同步 `ShadowOverview`。

---

## 6. 验收标准

1. 页面默认展示本人全部设备的影子；
2. 存在 delta 的设备数正确；
3. 非归属设备显式查询返回 2003；
4. 超过 200 台返回明确错误；
5. 单设备影子写入 / 查询行为零回归；
6. 后端 verify、前端 lint/test/build 全绿。

---

## 8. 明确不做

- 批量写影子 / 批量下发（仍走单设备或已有批量命令）；
- 影子聚合导出 / 大屏；
- 缓存与实时刷新（本页手动刷新；若需要实时可后续接 device-log / 影子事件）；
- 超过 200 台的分页聚合（当前显式拒绝）。
