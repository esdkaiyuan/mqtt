# D2 · 设备接入协议规范

> 版本：v1.1　创建日期：2026-10-21　状态：**权威规范（与代码同步）**
> 适用版本：T-14 / T-15 / T-16 / T-22 / T-24 / T-31 / T-50
> 代码基线：`ThingModelInterpretServiceImpl`、`ThingModelParamValidator`、`DeviceCommandServiceImpl`、`CommandReplyServiceImpl`、`OtaProgressPayload`、`PointTablePayloadBuilder`、`ModbusValueConverter`、`HttpIngestServiceImpl`

---

## 1. 传输方式

| 方式 | 端点 | 上行类型 | 认证 |
|---|---|---|---|
| MQTT | `tcp://host:1883` / `ssl://host:8883` | data / heartbeat / lwt / reply / ota | SECRET / X.509 / JWT |
| HTTP | `POST /api/ingest/{deviceKey}/{messageType}` | data / heartbeat / lwt | HTTP Basic（`{productKey}.{deviceKey}:{deviceSecret}`） |
| 平台 Modbus 主站 | 平台主动轮询设备 | 平台代为组装 `data` | 产品 `driver_config` |

- MQTT 主题与 ACL 见 [D1](./D1_MQTT主题与ACL规范.md)。
- HTTP 上报的 `messageType` 只支持 `data / heartbeat / lwt`；**不支持 reply / ota**。
- HTTP 上报的合成 Topic 固定为 `device/{deviceKey}/{messageType}`，**不随产品 `topic_prefix` 模板变化**；HTTP 设备应使用默认主题形态。
- HTTP 请求体默认上限 65536 字节（`HTTP_INGEST_MAX_PAYLOAD_BYTES`），超限返回 `413 + 6248`。

## 2. 编码与通用信封

- 字符编码：UTF-8。
- 业务载荷：JSON 对象（`{...}`）；JSON 数组 / 标量 / 非 JSON 文本在物模型解析阶段会被忽略。
- 平台统一使用 **Alink 风格信封**：

```json
{
  "id": "设备侧消息 ID（可选）",
  "version": "1.0",
  "method": "thing.event.property.post",
  "params": { }
}
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `id` | string | 否 | 属性 / 事件上报可省略；命令回执必填，且必须等于下行命令 id |
| `version` | string | 否 | 当前固定建议 `1.0`；解析链路不校验该值 |
| `method` | string | 是（属性 / 事件） | `thing.event.property.post` 或 `thing.event.post`；未知 method 静默忽略 |
| `params` | object | 是 | 属性映射 / 事件体；非对象忽略 |

> **时间口径**：平台以「消息到达服务端的时间」`receivedAt` 作为属性 / 事件时间，**不读取 payload 内的 `ts`**。设备侧时间戳仅作原始载荷保留，不参与属性最新值与历史排序。

## 3. 属性上报

`method = thing.event.property.post`，`params` 为 `identifier → value` 的平铺对象。

```json
{
  "id": "msg-20261021-0001",
  "version": "1.0",
  "method": "thing.event.property.post",
  "params": {
    "temperature": 26.5,
    "humidity": 61,
    "power": true,
    "mode": "auto"
  }
}
```

### 3.1 类型规则

| TSL 类型 | JSON 值 | 说明 |
|---|---|---|
| `int` | number（整数） | 不允许小数；受 `min/max` 约束 |
| `float` / `double` | number | 受 `min/max` 约束 |
| `bool` | boolean | 也接受 `0/1` 数字 |
| `text` | string | 受 `textLength` 约束 |
| `enum` | string | 必须命中 TSL 枚举键 |
| `date` | string / number / boolean | 按标量文本接受；建议 `yyyy-MM-dd HH:mm:ss` |
| `struct` | object | 原样文本化存储 |
| `array` | array | 原样文本化存储 |

- **数值必须是 JSON number，不能用字符串承载**；`"26.5"` 会被判为非法并忽略。
- `bool` 用 `true/false` 最稳妥。
- `enum` 用枚举键字符串，不是显示名称。
- 未在 TSL 中定义的 identifier：忽略并计入 `unknown_identifier` 指标。
- 值不符合类型 / 范围 / 枚举 / 长度：忽略该字段，保留同一报文中其它合法字段。
- `params` 为空对象：不产生属性更新。

### 3.2 上行效果

一条合法的属性上报会进入既有摄取管线，并触发：

1. `device_property_latest` 最新值更新；
2. `device_property_history` 属性历史追加（若开启）；
3. 设备影子 `reported` 合并与 `delta` 重算；
4. 阈值告警、消息规则、场景联动评估；
5. Webhook `device.data` 与 SSE 实时推送。

## 4. 事件上报

`method = thing.event.post`，`params` 必须包含 `eventId`，`value` 为可选事件输出。

```json
{
  "id": "evt-001",
  "version": "1.0",
  "method": "thing.event.post",
  "params": {
    "eventId": "overheat",
    "value": { "temperature": 91.2, "level": "critical" }
  }
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `params.eventId` | 是 | 必须在 TSL `events` 中存在；未知事件忽略 |
| `params.value` | 否 | 任意 JSON；原样存入事件的 `output_data` |

- 事件 `event_type` 取自 TSL 定义，不取上报载荷。
- 事件落库成功后才触发事件告警 / 规则 / 场景，避免「未落库却已触发」。
- 事件上报不会更新属性最新值。

## 5. 命令回执

设备收到 `cmd/down` 后，向 `{prefix}reply` 发布：

```json
{
  "id": "6f1c2a4e-8b7d-4e2a-9c1f-3d5e7a9b0c1d",
  "code": 200,
  "data": { "handled": true }
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | 是 | 必须等于下行命令的 `id`；否则回执被忽略 |
| `code` | 是 | 数字 `200` = 成功；其它 / 缺失 = 失败 |
| `data` | 否 | 成功时写入命令记录结果；失败时参与错误信息拼装 |

- 回执通过 `messageType=reply` 旁路处理，不进入物模型解析。
- 状态流转：`PENDING → SENT → ACKED / FAILED / TIMEOUT`；离线属性设置先 `QUEUED`，上线补发。
- 同一 `id` 的重复回执按条件更新，已终态记录不会被再次改写。

## 6. OTA 进度回传

Topic：`{prefix}ota`，`messageType=ota`。载荷是**扁平的 JSON 对象**（不是 Alink 信封）：

```json
{
  "version": "1.2.0",
  "status": "downloading",
  "progress": 42,
  "fileMd5": "d41d8cd98f00b204e9800998ecf8427e",
  "message": "downloading firmware"
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `version` | 是 | 固件版本；必须与任务目标版本一致才采纳 |
| `status` | 是 | `downloading / flashing / verifying / success / failed` |
| `progress` | 否 | 0~100 数字；`success` 恒按 100 处理；缺省不推进 |
| `fileMd5` | 否 | 32 位十六进制（大小写不敏感）；平台与固件 md5 比对 |
| `message` | 否 | 可读描述，≤255 字符 |

- 进度单调不减；状态只允许前向迁移，`failed` 可从任意非终态直达失败。
- 版本不一致、状态未知、进度越界、非 JSON 对象：整条丢弃并记 WARN。
- `fileMd5` 非法（长度/字符不符）按**未回传**处理，不丢弃整条；回传且不一致判失败。
- 未回传 md5 是否判失败由 `app.ota.verify-required` 决定（默认放行）。

## 7. 平台下行命令

### 7.1 Topic 与载荷

Topic：`{resolved_prefix}cmd/down`，QoS 1，不保留。

```json
{
  "id": "6f1c2a4e-8b7d-4e2a-9c1f-3d5e7a9b0c1d",
  "version": "1.0",
  "method": "thing.service.property.set",
  "params": { "power": true }
}
```

| 命令类型 | `method` | `params` |
|---|---|---|
| 属性设置 | `thing.service.property.set` | 可写属性 `identifier → value`，值需符合 TSL |
| 服务调用 | `thing.service.{serviceIdentifier}` | 服务入参 |
| OTA 升级（保留） | `thing.service.ota_upgrade` | 平台构造的 OTA 参数 |
| 点表下发（保留） | `thing.service.point_table_dispatch` | 见 §8 |

- `id`：平台生成的 UUID，回执关联键；
- `version`：固定 `1.0`；
- 属性设置会同时写入影子 `desired`；设备离线时命令 `QUEUED`，上线补发；
- 普通服务调用在设备离线时仍会发布（不排队），发布失败置 `FAILED`；点表下发是唯一可离线排队的保留服务；
- OTA 下发失败不排队，立即失败并由补投巡检重试。

### 7.2 关闭命令通道

设备端可只订阅自己的 `{prefix}cmd/#`；即使不订阅，平台仍会记录 `SENT`（QoS 1 发布成功 ≠ 设备已收到），需以回执为准。

## 8. 点表下发载荷（边缘路线 A）

下发通道复用 `{prefix}cmd/down`，`method=thing.service.point_table_dispatch`，`params` 结构：

```json
{
  "deviceId": 101,
  "version": 17,
  "dispatchedAt": 1790000000000,
  "points": [
    {
      "pointKey": "temperature",
      "pointType": "HOLDING_REGISTER",
      "address": "40001",
      "dataType": "float",
      "scale": "0.1",
      "offset": "0",
      "unit": "°C",
      "readIntervalMs": 5000
    }
  ]
}
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `deviceId` | number | 是 | 设备 ID，防止 A 设备点表被应用到 B 设备 |
| `version` | number | 是 | 点表版本，单调递增；设备应丢弃小于等于本地版本的载荷 |
| `dispatchedAt` | number | 是 | 下发时间，Unix 毫秒 |
| `points[]` | array | 是 | 启用中的 EDGE 点位；空点表拒绝下发（6291） |
| `pointKey` | string | 是 | 点位标识，需与物模型 identifier 对应 |
| `pointType` | string | 是 | `HOLDING_REGISTER / INPUT_REGISTER / COIL / DISCRETE_INPUT / TAG / NODE` |
| `address` | string | 条件 | 寄存器 / 线圈类必填，非负十进制整数；TAG/NODE 为名称 |
| `dataType` | string | 是 | `int / int32 / uint32 / int64 / uint64 / float / double / bool / string`；字序取 `driver_config.wordOrder` |
| `unitId` | number | 否 | Modbus 从站地址 0~247；空表示网关使用驱动默认值（T-50） |
| `scale` | string | 否 | 线性缩放系数，字符串承载以保留精度；空表示 1 |
| `offset` | string | 否 | 线性偏移；空表示 0 |
| `unit` | string | 否 | 单位，仅展示 |
| `readIntervalMs` | number | 否 | 采集周期（毫秒），边缘侧应有默认值兜底 |

**版本单调性**：

- 正常路径：Redis `INCR mqtt:pointtable:ver:{deviceId}`，跨副本单调；
- Redis 不可用：退化为进程内自增，基数为 `1_000_000_000_000`（`1e12`）；**只保证单副本单调**，多副本部署可能出现版本回退；
- 版本回退的后果是网关丢弃一份更新的点表（表现为配置改了但未生效），重新下发即可恢复，不会写坏数据；
- 设备必须按 `version` 丢弃旧载荷，不能只看收到时间。

**下发前置条件**：设备启用、产品 `protocol_type` 为空或 `GATEWAY_MQTT`、设备点表执行方为 `EDGE` 且至少有一个启用点位。错误码：`6290`（非 EDGE）、`6291`（无点位）、`6292`（设备不可下发）。

回执：设备向 `{prefix}reply` 发布 `{ "id": "<command id>", "code": 200 }`；平台按命令回执流程置 `ACKED`。

## 9. 平台 Modbus 主站点表（路线 B）

### 9.1 `driver_config`

产品字段 `driver_config`（JSON，仅 ADMIN 可读）：

```json
{
  "host": "192.168.10.20",
  "port": 502,
  "unitId": 1,
  "connectTimeoutMs": 3000,
  "readTimeoutMs": 3000,
  "retry": 1,
  "wordOrder": "ABCD"
}
```

| 字段 | 默认 | 说明 |
|---|---|---|
| `host` | `MODBUS_DEFAULT_HOST`（默认空） | 必填；平台可达的现场地址 |
| `port` | 502 | 1~65535 |
| `unitId` | 1 | 0~247；设备默认从站地址，点位 `unitId` 非空时覆盖（T-50） |
| `connectTimeoutMs` | 3000 | 连接超时 |
| `readTimeoutMs` | 3000 | 读超时 |
| `retry` | 1 | 0~10 |
| `wordOrder` | `ABCD` | 32/64 位数值字序：`ABCD` 大端、`CDAB` 字交换、`BADC` 字节交换、`DCBA` 小端；16 位 int / bool / string 不受影响 |

### 9.2 点表与寄存器

产品 `protocol_type=MODBUS`，点位 `executor=PLATFORM`。

| pointType | 功能码 | 宽度 |
|---|---|---|
| `HOLDING_REGISTER` | 03 | 按 dataType：int/bool/string 1 个寄存器，int32/uint32/float 2 个，int64/uint64/double 4 个 |
| `INPUT_REGISTER` | 04 | 同上 |
| `COIL` | 01 | 1 位 |
| `DISCRETE_INPUT` | 02 | 1 位 |

**地址**：十进制字符串，从 0 开始；平台不做 40001 偏移换算，若 PLC 文档使用 4xxxx 表示法，请在点表中填写实际零基地址。

**字节序**：

- `int`：1 个 16 位寄存器，**有符号**；
- `int32` / `uint32`：2 个寄存器，有符号 / 无符号 32 位；
- `int64` / `uint64`：4 个寄存器，有符号 / 无符号 64 位；`uint64` 以无符号十进制字符串输出；
- `float`：2 个寄存器，32 位 IEEE-754；
- `double`：4 个寄存器，64 位 IEEE-754；
- `bool`：寄存器 / 线圈非 0 为 true；
- `string`：1 个寄存器（2 字节 ASCII），遇 NUL 截断；当前不支持变长字符串；
- **字序由 `driver_config.wordOrder` 配置**：`ABCD`（大端）/ `CDAB`（字交换）/
  `BADC`（字节交换）/ `DCBA`（小端），默认 `ABCD`；只影响 int32/uint32/int64/uint64/float/double，
  16 位 int、bool、string 不受影响。

**工程值**：

```
工程值 = 原始值 × scale + offset
```

- `scale` 空按 1，`offset` 空按 0；
- `bool` / `string` 不做线性换算；
- 数值结果去掉无意义尾零（`25.0` 输出 `25`）；
- `NaN / Infinity` 判为换算失败，不写入属性。

### 9.3 平台采集上行的报文

平台采集成功后，按 D2 的属性信封组装：

```json
{
  "id": "modbus-101-1790000000000",
  "version": "1.0",
  "method": "thing.event.property.post",
  "params": {
    "temperature": 26.5,
    "power": true,
    "status": "running"
  }
}
```

- Topic：`device/{deviceKey}/data`（平台内部注入，不走 Broker）；
- `params` 的值按点表 `dataType` 转为 JSON 原生类型；
- 采集结果进入同一 `IngestPipeline`，与 MQTT 上报等价触发影子 / 规则 / 告警 / 场景 / 历史；
- 单点失败只写 `device_point_run=FAILED`，不影响同设备其它点位；
- 设备 / 产品停用、协议不匹配时写 `SKIPPED`，不采集；
- 采集周期下限由 `MODBUS_MIN_INTERVAL_MS` 钳制；
- 平台**不做写寄存器 / 写线圈**，控制类操作走 `cmd/down`。

## 10. 错误与忽略规则

| 场景 | 行为 |
|---|---|
| 非 JSON / 非对象 | 忽略，计入 `unparsed` |
| `method` 缺失或未知 | 忽略（不报错） |
| `params` 非对象 / 空 | 忽略 |
| 未知属性 identifier | 忽略该字段，其余字段继续 |
| 属性值类型 / 范围非法 | 忽略该字段，其余字段继续 |
| 未知事件 eventId | 忽略 |
| 命令回执 id 缺失 / 非文本 | 忽略 |
| 命令回执 code 非 200 | 命令置 FAILED，data 写入错误信息 |
| OTA 进度非法 | 整条丢弃；fileMd5 非法按未回传处理 |
| HTTP messageType 非白名单 | `400 + 6247` |
| HTTP 载荷超限 | `413 + 6248` |
| HTTP 凭据非法 | `401 + 6246` |

## 11. 与旧文档的差异（以本规范为准）

| 旧文档 | 实际代码 / 本规范 |
|---|---|
| 数据格式示例为平铺 `{"temperature":26.5}` | 物模型解析要求 Alink 信封 `method + params`；平铺对象会被判为 unable to parse |
| 设备 ACL publish `device/{deviceKey}/#` | 设备 publish 禁止进入 `{prefix}cmd/`，其余自有前缀主题允许 |
| 下行固定 `device/{deviceKey}/cmd/down` | 现按产品模板解析为 `{prefix}cmd/down` |
| 自定义模板只影响订阅 | 自定义模板同时影响上行解析与下行发布；模板必须含 `{deviceKey}` 且为最后一个占位符 |
| payload `ts` 作为时间 | 平台使用服务端 `receivedAt`，`ts` 不参与属性时间 |
