## 计划概览

- **Goal**：把消息规则（T-19）与场景联动（T-23）的编排配置从表单式升级为基于 `@vue-flow/core` 的画布视图，让「触发 → 条件 → 动作」数据流一屏可见并就地编辑；**后端、请求体、校验与既有表单视图零改动**。
- **Architecture**：画布是既有表单 `form` 响应式对象的**图形态投影**（`project` / `apply` 双向），唯一事实来源仍是 `form`；连线由模型语义自动生成（不开放任意 DAG）；`OrchestrationCanvas` 为无领域知识的容器，场景 / 规则的投影逻辑各自独立成模块；`buildPayload` / `validateForm` 一行不改。
- **Tech Stack**：Vue 3.4 + Vite 5 + Element Plus + `@vue-flow/core`（MIT，^1.48.2）+ Vitest；后端零改动。
- **Spec**：`docs/T-29_可视化拖拽编排_设计文档.md` v1.1。
- **Global Constraints**：
  - 纯前端改动：**不改**后端任何代码、`SceneRequest` / `RuleRequest` / `SceneDefinition` / `RuleDefinition`、任何迁移、错误码与配置项。
  - **不改** `buildPayload` / `validateForm` / `fillForm` 的**输出与校验口径**（上限、必填、Cron 合法性等一律不放宽）；`buildPayload` 仅把内联的动作组装改为调用抽出的 `buildRuleActionConfig(form)`（行为等价，纯移动），使画布摘要与提交体同源。
  - 既有表单视图**原样保留为默认视图**（`DEFAULT_VIEW_MODE = 'form'`），既有单测（`RuleEditor.spec.js` / `SceneFormDialog.spec.js`）必须保持全绿。
  - 连线由 `project` 自动生成，**不开放任意连边**；拖拽仅用于新增 / 重排 / 删除节点与节点定位。
  - 字段缺省值与联动清理逻辑抽到 `utils/scene.js` / `utils/rule.js` 共享，禁止表单视图与画布视图各写一份。
  - 节点 `data` 只承载展示文案与稳定 `key`，不复制可编辑状态，不含敏感字段。
  - `vite.config.js` 的 `manualChunks` 为 `@vue-flow` 单列分块；画布组件走 `defineAsyncComponent` 动态导入，表单视图不加载该分块。
  - 新增依赖仅 `@vue-flow/core`（及官方配套 `background` / `controls` / `minimap`），许可均为 MIT。
  - 节点坐标不持久化、不进请求体。
