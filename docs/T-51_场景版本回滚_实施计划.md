# T-51 场景版本回滚 实施计划

> 版本：v1.0　创建日期：2026-10-22　状态：已交付
> 目标：补齐 G-12-6，为场景保存历史快照并提供列表 / 回滚能力，避免一次误改后只能手工恢复。

---

## 1. 背景与范围

场景更新采用「整体替换步骤」，保存后旧配置立刻消失；当前没有历史版本，误改或误删步骤只能凭记忆重建。本任务：

- 每次创建 / 更新 / 回滚后自动留一份完整快照（定义 + 条件组 + 步骤流 + 启用状态）；
- 场景详情页可查看版本历史（版本号、变更类型、步骤数、保存时间）；
- 支持回滚到任一历史版本；回滚本身生成一个新版本，可再次回滚；
- 每个场景最多保留最近 20 个版本，超出自动清理最旧版本；
- 启停（enabled）不单独生成版本；回滚会覆盖当前启用状态。

不在本任务范围：版本 diff 可视化、多人协作冲突合并、按字段回滚、执行记录版本绑定。

## 2. 数据模型

### 2.1 迁移 `V29__scene_version.sql`

| 列 | 说明 |
|---|---|
| `id` | 主键 |
| `scene_id` | 场景 ID，外键 `ON DELETE CASCADE` |
| `version_no` | 场景内递增版本号，唯一键 `(scene_id, version_no)` |
| `change_type` | `CREATE` / `UPDATE` / `RESTORE` |
| `scene_name` / `trigger_type` / `step_count` | 快照摘要，供列表展示，避免逐行解析大 JSON |
| `snapshot` | `MEDIUMTEXT`，完整快照 JSON |
| `operator_id` | 操作者用户 ID |
| `created_at` | 保存时间 |

索引 `(scene_id, version_no)`；只加表、不改既有表。

### 2.2 快照结构

`SceneSnapshot` 保存：

- 场景定义：名称 / 描述 / 触发源及参数 / 影子变更侧 / cron / 条件逻辑与条件 JSON / 冷却 / 启用状态；
- 步骤流：`seq` / 延时 / 动作类型 / 目标类型与 JSON / 动作配置 JSON / 并行归属 / 启用状态；
- **不保存**主键、创建 / 更新时间、执行记录等运行时数据。

## 3. 后端实现

- `SceneVersion` / `SceneVersionMapper` / `SceneVersionVO`；
- `SceneConstants.MAX_VERSIONS_PER_SCENE = 20`；新增错误码 `6312`（版本不存在）；
- `SceneServiceImpl`：
  - 创建 / 更新成功后写 `CREATE` / `UPDATE` 版本；
  - `listVersions(userId, sceneId)` 先校验场景归属，再按版本号倒序返回摘要；
  - `restoreVersion(userId, sceneId, versionId)`：校验版本归属，反序列化快照，**用显式 UPDATE 覆盖全部字段（含 null）**，整体替换步骤，写 `RESTORE` 版本并失效场景缓存；
  - 回滚前校验恢复后的名称是否与其它场景重名；快照损坏返回 `6241`；
  - 版本号 = 当前最大值 + 1；保留最近 20 条。
- `SceneController` 新增：
  - `GET /scenes/{id}/versions`；
  - `POST /scenes/{id}/versions/{versionId}/restore`。

## 6. 已实测与未实测

已实测：

- 创建 / 回滚后写入版本，版本号递增与 `(scene, versionNo)` 唯一；
- 版本列表归属校验与摘要字段；
- 回滚覆盖定义字段（含 null）、整体替换步骤、生成 RESTORE 版本；
- 版本不存在 `6312`、快照损坏 `6241`、重名拒绝；
- 保留上限清理旧版本；
- 前端版本列表、当前版本禁用回滚、回滚确认 / 刷新 / 通知外部。

未实测：

- 浏览器中实际打开版本历史并回滚后的场景编辑器回填；
- 真实 MySQL 上 `V29` 迁移与 `(scene_id, version_no)` 并发保存冲突；
- 大量步骤快照（20 步）在列表 / 回滚时的响应体大小；
- 回滚到引用已删除分组 / 设备的旧配置后的运行期表现（当前直接恢复历史配置，不重新校验引用对象）。

## 7. 关键决策与已知限制

1. **保存即版本**：创建 / 更新 / 回滚都留存新状态，列表第一条始终是当前配置；不做「保存前快照」的两套语义。
2. **回滚生成新版本**：回滚是可逆操作，历史只追加不删除（除保留上限），避免「回滚把想回滚的版本本身删掉」。
3. **显式 UPDATE 覆盖全部字段**：MyBatis-Plus 默认 NOT_NULL 更新无法把触发设备 / cron 等字段清空，回滚必须用 UpdateWrapper 显式 set null。
4. **启停不生成版本**：避免频繁启停淹没配置历史；回滚会恢复快照中的启用状态。
5. **最多 20 个版本**：场景配置体量小，但快照含全部步骤 JSON，必须设保留上限。
6. **并发保存**：`(scene_id, version_no)` 唯一键兜底；同一场景并发保存时后提交者可能得到版本冲突，需重新保存（低概率，当前不做自动重试）。
