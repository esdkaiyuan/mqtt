## 计划概览

- **Goal**：为平台补上 **HTTP 上报端点**（设备凭据 HTTP Basic 鉴权），使「HTTP 上报数据与 MQTT 上报在属性最新值上等价」（路线图 §3 L11 验收句）；同时给出**边缘网关 / Modbus 评估结论**（边缘侧转换、平台不建拓扑，见设计文档 §4.5）。
- **Architecture**：`DeviceCredentialAuthFilter`（仅 `/ingest/**`，自写失败响应） → `HttpIngestController`（`POST /ingest/{deviceKey}/{messageType}`） → `HttpIngestService`（接口在 `service` 包、实现在 `service.impl`） → 构造与 MQTT **同形**的 `IngestRecord` → `IngestPipeline.submit`（**唯一投递入口，零改动**）。不新增第二条落库 / 解析路径。
- **Tech Stack**：Java 17 + Spring Boot 3（Spring Security 6 过滤器链）+ MyBatis-Plus + Flyway + JUnit 5 + Mockito + ArchUnit；Vue 3 文档站（纯静态说明，无接口调用）。
- **Spec**：[`docs/T-24_多协议接入_设计文档.md`](./T-24_多协议接入_设计文档.md)（v1.0），本计划逐条对应其 §2.1 / §8 / §10 / §12 / §13 / §14。
- **Global Constraints（全局约束，每个阶段都适用）**：
  - **零 DDL**：不新增表 / 列，不新增 Flyway 迁移脚本；既有 `V1`~`V12` **零改动**，无需 `V13`。
  - **零摄取改动**：`IngestPipeline` / `IngestDispatcher` / `IngestPersistenceService` / `ThingModelInterpretServiceImpl` **一行不改**，**不新增** `IngestDispatcher` 第 7 路 fan-out。
  - **零 MQTT 改动**：`MqttMessageHandler` / `EmqxAuthServiceImpl` / `emqx-init` / ACL **零改动**，不新增自有 MQTT 订阅 / 发布主题。
  - **唯一安全改动点**：`SecurityConfig`（新增 `/ingest/**` 为 `permitAll` + 注册 `DeviceCredentialAuthFilter`）。
  - **错误码水位**：`ResultCode` 自 **`6246`** 起（既有末项为 `SCENE_TRIGGER_UNSUPPORTED(6245)`）。
  - **测试基线**：既有 **693** 项（`mvn -B verify`）保持全绿（T-23 设计文档 §14.2 A16 / §14.3 与 T-23 实施计划 P7 所写「697」为**文档笔误**，本计划一律按 693）。
  - **包分层**：`controller → service → ingest`、`filter → service`；`service` 接口包**不得直接依赖 `mapper`**（ArchUnit `LayeringRulesTest`）。
  - **JSON 序列化**：过滤器注入 `tools.jackson.databind.ObjectMapper`（与 `RestSecurityExceptionHandler` **同源**，非 `com.fasterxml`）。
