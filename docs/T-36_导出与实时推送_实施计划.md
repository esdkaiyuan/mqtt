## 2. X-2 · CSV 导出

### 2.1 端点

| 端点 | 覆盖 |
|---|---|
| `GET /devices/{deviceKey}/logs/export` | 设备统一日志（消息 / 事件 / 命令 / 状态） |
| `GET /devices/{deviceKey}/properties/history/export` | 属性时序（长表：一行一个桶） |
| `GET /devices/{deviceKey}/commands/export` | 命令下发记录 |
| `GET /alerts/export` | 告警记录 |

与既有查询端点**并列**而非替代：控制台表格仍走分页查询（快、可翻页），导出是「一次性拿全量做二次分析」的路径。

### 2.2 `CsvWriter` 的三个关键细节

这三个不处理就会**直接坑到用户**，因此单独收敛成一个纯函数类并逐条单测：

1. **UTF-8 BOM** —— 不加 BOM 时 Excel 打开中文 CSV 就是乱码；而 BOM 会让部分解析器看到多余字符。
   故编码结果自带 BOM，文件名走 `ContentDisposition` 的 UTF-8 编码。
2. **公式注入防护** —— 单元格以 `=` `+` `-` `@`（及 tab / CR）开头时 Excel 会当公式执行。
   `=HYPERLINK("http://evil","点我")` 是经典的凭据钓鱼手法，而**设备上报的 payload 完全不可控**，
   所以这不是过度设计。这类值前置单引号强制按文本处理。
   ⚠️ 判定顺序要点：**先判公式注入、再判是否加引号** —— 反过来的话 `"=x"` 加了引号就逃掉了。
3. **RFC 4180 转义** —— 载荷含逗号 / 换行 / 双引号时加引号并把内部引号翻倍。

### 2.3 导出必须有行数上限

不分页的导出天然是**无界**的。十万行日志一次性拼进 `StringBuilder` 再编码成 `byte[]`，
峰值内存是结果的数倍 —— 一个手滑的时间窗就能把进程打挂。

因此：默认 1 万、上限 10 万（`limit<=0` 按默认，避免传 0 拿到空文件），
并在响应头 `X-Export-Truncated` **如实标注是否截断** —— 让用户知道「导出的不是全部」，而不是以为导完了。

### 2.4 属性时序的列按聚合口径

时序数据源是**分桶聚合**结果（`PropertyHistoryPoint` 只有 `time` / `count` / `min` / `max` / `avg`），
不是原始样本。所以 CSV 列给的是 `桶起点 / 样本数 / 最小值 / 最大值 / 均值`，
**不要臆造「value」列** —— 非数值型属性的桶里它根本不存在。

## 3. X-3 · 实时推送

### 3.1 SSE 由单主题扩为多主题

原先 `RealtimeStreamServiceImpl` 的事件名 `device-data` 是**硬编码常量**。现改为：

- 事件名：`device-data`（设备上行，既有）/ `device-log`（设备日志，预留）/ `property-trend`（属性上报，新增）
- `Subscriber` 携带 `topics` 集合，**空集合 = 订阅全部主题** ——
  这样既有的 `subscribe(userId, admin)` 单参调用行为与改造前**逐位等价**，既有 12 项测试零修改即通过
- 新增 `publishEvent(ownerId, eventName, payload)`：不绑定设备与 Topic 的通用发布

### 3.2 属性趋势流挂在 `append`

挂在 `PropertyHistoryService.append` 上是因为它是**属性历史唯一的写入点** ——
属性历史是追加型表，绕过 `append` 直写的路径不存在，因此不会漏推也不会重推。

**整段 `try/catch` 静默 + DEBUG 日志**：调用方是摄取主链路，
一个 SSE 推送失败不得让属性落库失败（进而让摄取重试）。

### 3.3 实时流开关与落库开关分离

新增 `PROPERTY_HISTORY_STREAM_ENABLED`（默认关闭），刻意与 `PROPERTY_HISTORY_ENABLED` 分开：
压测 / 极端降级时关掉落库，往往仍想保留已有历史可查，此时只关实时流即可。

### 3.4 设备日志实时流**刻意未做**

设备日志是**查询时**聚合消息 / 事件 / 命令 / 连接状态四路的 union，**没有单一写入点**。
要挂钩就得动摄取旁路（`ThingModelInterpretServiceImpl`），而摄取主链路的风险与收益不成比例 ——
日志页已有分页查询 + 手动刷新，加轮询的成本远低于在摄取路径上引入新的失败模式。

`device-log` 事件名与多主题订阅能力已就位，后续若要做只需加一个发布点，不必再改 SSE 基建。

## 5. 踩坑记录

- **`mvn -q compile` 的输出会骗人**：中文编译器的报错格式不含 `java:` 与 `符号:` 字样，
  用 `grep -aE "ERROR.*java:|符号:"` 过滤会漏掉全部错误而误判为成功。
  **判断编译成功必须看 exit code，不能只看 grep 有没有输出。**
- Python heredoc 里写 `\r\n` 时转义层数极易出错导致 `replace` 静默不生效 ——
  这次连续踩了两次（测试修正、`import` 插入）。**替换后必须回读确认。**
- 放宽可见性时 `private long subscriberCount()` 的实际签名是 `private int`，替换没匹配上；
  同理 `lastRecipientUserIds` 是字段不是方法，测试里写成 `lastRecipientUserIds()` 编译不过。
- `List.of("x", null)` 在测试里构造不出「含 null 的单元格」—— `ImmutableCollections` 拒绝 null 元素，须用 `Arrays.asList`。
