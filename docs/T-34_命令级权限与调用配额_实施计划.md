## 1. 计划概览

- **Goal**：让「谁能把哪条命令下发到设备」成为可配置、可收紧的显式约束，而不是「登录即可 + 设备归属即可」。
- **Architecture**：三层约束，**从粗到细**，各自独立、互不牵制：

  | 层 | 落点 | 手段 |
  |---|---|---|
  | ① 角色闸门 | `SecurityConfig` | 路径级 `hasAnyRole`，把 VIEWER 整体挡在命令下发之外 |
  | ② 标识符 / 类型权限 | `CommandGuardService` | 配置化黑名单 + 角色矩阵，只管外部来源 |
  | ③ 调用配额 | `CommandQuotaService` | Redis 固定窗口，按操作者维度，覆盖全部来源 |

- **Tech Stack**：Spring Boot 4.1.1 + Spring Security + Redis（StringRedisTemplate）+ Lombok；纯后端。
- **Global Constraints**：
  - **零回归红线**：命令域既有 39 项测试与全量后端测试必须全绿；默认配置下**不拦截任何既有命令**。
  - **默认宽松**：黑名单只含 `factory_reset` 一项，配额默认关闭。与项目其它开关一致 —— 未显式配置就强制限流会把正常下发打成 429。
  - **权限只管外部来源**：内部触发（规则 / OTA / 场景 / 点表）不套「当前登录角色」的判定，否则会出现「VIEWER 配了一条规则，规则却再也执行不了」的反直觉故障。

## 2. 现状基线（实施前已核实）

| 事实 | 结论 |
|---|---|
| 控制台命令端点 | `POST /devices/{deviceKey}/commands` **只做设备归属校验**，SecurityConfig 中无任何角色限制 |

## 3. 设计决策

### 3.1 权限只管外部来源，配额覆盖全部来源

这两个看似矛盾，实则是两件不同的事：

- **权限管「谁能发起」**：只有人（控制台 / 开放 API）才谈得上角色。规则执行的 `operatorId` 是「谁配置的这条自动化」，
  拿它去套角色判定会让「VIEWER 配的规则跑不起来」这类故障变得极难排查。
- **配额管「发起多频繁」**：规则风暴、场景误配同样能把 Broker 与设备打爆，
  这恰恰是命令配额**最有价值**的场景。所以内部触发**也计量**，只是阈值可能按来源再调。

### 3.2 判定放在落库之前

`invoke` 入口先过守卫、再 `insert`。若放在 `insert` 之后，被拒绝的命令会留下一条无主记录 ——
用户看到「明明拒绝了却有下发记录」会把排障方向带偏，执行记录表也会被无意义地灌满。

### 3.3 配额默认关闭 + failOpen

- `enabled=false` 时本类**完全不做 Redis 读写**，零开销。
- `failOpen=true`（默认）时 Redis 抖动降级放行并记 WARN：可用性优先于严格限流，
  与 `app.rate-limit` 的既有口径一致。`failOpen=false` 时 Redis 不可用直接拒绝（严格模式）。

### 3.4 TTL 只在首次写入时设置

`INCR` 返回 1 时才 `EXPIRE`。每次 `INCR` 都重设过期会把窗口无限续期，
退化成「从第一次调用起永不释放的滑动窗口」—— 那不是配额，是累计上限。

### 3.5 同步调用更贵

`callType=sync` 会阻塞等待设备回执，实际阈值取 `阈值 × sync_multiplier`（默认倍数 1 = 不额外收紧）。

### 3.6 路径通配的写法陷阱

注释里写 `/devices/*/commands` 会被 **Java 词法分析当成注释结束符 `*/`** 而提前关闭块注释。
本次踩中并修正：注释内一律改用路径模板写法 `/devices/{deviceKey}/commands`
（既避开陷阱，也与项目其它文档的 `{deviceKey}` 口径一致）。

## 5. 踩坑记录

- **注释里的路径通配 `/*/commands` 会提前关闭块注释**：表现为「类声明处报需要 class/interface/enum」这种
  完全指不到真正问题位置的编译错误。注释内改用路径模板写法。
- **`@RequiredArgsConstructor` 的参数顺序 = 字段声明顺序**：把新字段插在中间后，
  测试里按直觉追加到末尾会报「不兼容的类型」。改测试时应核对字段声明处的实际顺序。

## 6. 未做 / 遗留

- **设备级授权**（谁能对哪些设备下发，当前口径是「设备归属即可」）未做：跨用户 / 团队的设备授权表是
  与 G-8-1「分组级权限共享」同源的更大工程，应合并推进而非单独开。
- `/devices/batch/**` 下 enable/disable/groups/tags 仍对 VIEWER 开放，属**设备管理权限**缺口，本批刻意未扩大范围。
- 角色 → 命令类型矩阵的**配置写入界面**未做（当前只能改配置文件）：角色与权限本身尚无管理页，
  待「用户与角色」域有管理端时一并提供。
- 配额未做**按来源分档**（规则触发通常需要比人工下发更宽的阈值）：当前全局一个阈值，靠 `sync-multiplier` 微调。
