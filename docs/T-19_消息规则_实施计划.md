## P3 规则评估与动作执行

- [ ] `service/RuleEvaluationService.java`（接口，**不得依赖 mapper**）
  - `void onProperties(Long deviceId, Long productId, List<PropertySample> samples)`
  - `void onEvents(Long deviceId, List<EventSample> samples)`
  - 嵌套 record `PropertySample(String identifier, String valueText, LocalDateTime reportedAt)` / `EventSample(String identifier, String eventType, String outputData, LocalDateTime reportedAt)`
  - 类注释明确：全程 `try/catch` 隔离，异常只记 WARN，绝不冒泡到解析链路；**不依赖 T-17 的样本类型**（避免规则引擎反向耦合告警包）
- [ ] `service/impl/RuleEvaluationServiceImpl.java`
  - 规则缓存：`ConcurrentHashMap<Long, CachedRules>`（`userId` → 规则列表 + 过期时刻），TTL 取 `cache-ttl-seconds`，`0` 关闭缓存；`evictCache(userId)` 由 `RuleService` 在写操作后调用
  - 匹配：作用域（`deviceId==null` 或等于本次设备）→ 来源 → 标识符（`EVENT` 额外比对 `eventType`）→ 条件判定
  - 条件判定：`GT/GTE/LT/LTE` 用 `BigDecimal.compareTo`，任一侧不可解析 → 不命中；`EQ`/`NE` 用 `trim()` 后文本比较（口径与 T-17 一致）
  - 冷却：进程内 `ConcurrentHashMap<Long, Instant>`（规则 ID → 上次触发时刻）判定，窗口内跳过；命中后**先占用锚点**（摄取线程不读写库）
  - 触发：落 `rule_execution`（`status=PENDING`、`attempt_count=0`、`next_attempt_at=NULL`，快照字段齐全）→ 投递 `ruleExecutor`；`RejectedExecutionException` → 记 WARN + 置 `FAILED`（原因「执行队列已满」）
  - 全方法 `try/catch`：异常只记 WARN + 指标，**绝不冒泡**
- [ ] `service/RuleActionExecutor.java`（接口）+ `impl/RuleActionExecutorImpl.java`
  - `void execute(Long executionId)`：`touchLastTriggered`（回填展示用，失败只记 WARN）→ 读记录 → 渲染 → 按 `actionType` 分派 → `markSuccess` / 失败走重试
  - `UPDATE_PROPERTY`：取目标设备产品物模型 → `identifier` 必须存在且可写（否则失败）→ `DevicePropertyLatestMapper.upsertIfNewer(deviceId, identifier, spec.type(), renderedValue, now)`
  - `SEND_COMMAND`：`DeviceCommandService.invoke(new CommandInvoke(deviceId, productId, commandType, identifier, renderedParams, CALL_TYPE_ASYNC, SOURCE_RULE, null))`
  - `FORWARD_MQTT`：渲染 topic / payload → `RuleMqttForwarder.publish(topic, payload, qos)`
  - `FORWARD_HTTP`：渲染 URL / payload → `RuleHttpForwarder.send(method, url, headers, body, executionId)`
  - 转发类动作**渲染成功后**回填 `forward_payload` 快照（无论发送成功与否）
- [ ] `util/RuleTemplateRenderer.java`（静态纯函数）
  - 支持 `${ruleId}` `${ruleName}` `${executionId}` `${deviceId}` `${deviceKey}` `${deviceName}` `${deviceType}` `${sourceType}` `${identifier}` `${value}` `${reportedAt}` `${timestamp}`
  - **单次扫描**替换（不递归）、替换值 JSON 转义、未知占位符保留原样
- [ ] `service/RuleHttpForwarder.java`（`@Component`，对齐 `WebhookDispatcher` 位置与签名方案）
  - 按 `method`（`POST`/`PUT`）发送；头 `Content-Type` / `X-Event-Type: rule.triggered` / `X-Rule-Id` / `X-Execution-Id` / `X-Signature: sha256=<hex>`
  - `X-Signature` 为 HMAC-SHA256（密钥 `app.rule.http-secret`，为空则不下发该头）；`X-Execution-Id` **重试时不变**（接收方幂等键）
  - 连接 / 读取超时 `http-timeout-ms`；**不跟随重定向**；非 2xx 视为失败并记原因
- [ ] `mqtt/RuleMqttForwarder.java`（`@Component`，`MqttClientManager` 的兄弟组件，**独立 Paho 客户端**）
  - `clientId` / 连接参数取 `app.rule.mqtt.*`；`enabled=false` 时不建连，`publish` 直接抛业务异常（「外部 MQTT 转发未启用」）
  - **不订阅任何主题**（纯出站）；自动重连 + 监督线程；`@PreDestroy` 关闭
  - `publish(topic, payload, qos)`：未连接时尝试重连一次，仍失败则失败（交由重试兜底）
  - 该类**不得依赖 mapper**（ArchUnit：`com.mqtt.cloud.mqtt` 包禁 mapper）
- [ ] `service/impl/ThingModelInterpretServiceImpl.java`（**唯一改动点：新增第三处内部旁路**）
  - `interpretProperties`：同一循环内并行收集 `List<RuleEvaluationService.PropertySample> ruleSamples`，在 `applyReported` / `evaluateProperties` 之后调用 `evaluateRules(device, ruleSamples)`
  - `flushEvents` 批量写库成功后 → `evaluateRules(deviceId, eventSamples)`（按设备分组后逐设备调用，沿用 T-17「未落库不评估」纪律）
  - `evaluateRules(...)`：`try/catch → log.warn`，异常绝不冒泡
  - **不改** `IngestDispatcher`（不新增 fan-out 路）
