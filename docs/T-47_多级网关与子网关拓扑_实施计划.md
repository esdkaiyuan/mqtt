# T-47 多级网关与子网关拓扑 实施计划

> 版本：v1.0　创建日期：2026-10-22　状态：已交付
> 目标：补齐域 14 的「平台侧更深拓扑」，让子设备（`SUB`）也能作为父节点代连下一级设备，同时保持逐级 ACL 委托与深度上限。

---

## 1. 背景与范围

T-26 只支持两层拓扑：网关 → 子设备，父设备不得为 `SUB`，`maxDepth` 默认 2。现实现场存在「总网关 → 区域子网关 → 末端设备」的多级结构，本任务扩展：

- `SUB` 设备可作为父节点（子网关），继续挂载叶子设备；
- 拓扑深度按父链计算，默认上限由 2 提升到 5，可配置；
- ACL 委托允许 `SUB` 对其**直接子设备**代理收发，多级链路逐级委托；
- 解绑带下级的子网关时收敛为根 `GATEWAY`，保住其子树；
- 前端 `SUB` 设备详情也展示子设备面板与上级跳转。

不在本任务范围：整棵子树移动（当前只允许挂载叶子设备）、跨产品拓扑、按祖先一次性委托（仍逐级 direct parent 校验）、边缘驱动（OPC-UA / 串口）评估。

---

## 2. 拓扑规则

| 规则 | 说明 |
|---|---|
| 父节点 | `GATEWAY` 或已挂载的 `SUB`（子网关）；`DIRECT` 首次挂载自动提升 `GATEWAY` |
| 子节点 | 只能是叶子设备（`countByParentId(child)=0`），不支持整棵子树移动 |
| 同产品 | 父子必须同产品，跨产品 `6258` |
| 深度 | 根为第 1 层；`parentDepth + 1 <= maxDepth`，默认 5；低于 2 不接受挂载 |
| 数量 | 每个父节点直接子设备数不超过 `maxSubDevicesPerGateway`（默认 200） |
| 解绑 | 叶子回 `DIRECT`；带下级的子网关收敛为根 `GATEWAY` |
| 角色 | `SUB` 角色由挂载关系派生，不能通过 `node-type` 直接设置 |

**ACL 委托**：主题目标必须是当前设备的直接子设备；委托方须为 `GATEWAY` 或 `SUB`，目标须为 `SUB` 且 `parentId` 等于委托方；逐级委托，不跨级直连。发布仍禁 `cmd/`、订阅仅 `cmd/`。

---

## 3. 后端实现

### 3.1 挂载

`DeviceTopologyServiceImpl.attach`：

1. 自环 / 父不存在 / 子不存在 / 跨产品校验；
2. 子设备必须无下级（叶子）；
3. `depthOf(parent)` 沿 `parent_id` 上溯计算深度（visited 防环，父链缺失报 `6257`）；
4. 检查 `parentDepth + 1 <= maxDepth`；
5. 检查父节点直接子设备数量；
6. 子设备置 `SUB` + `parentId`；父为 `DIRECT` 时提升 `GATEWAY`，父为 `SUB` 时保持；
7. 失效子设备 / 新父 / **旧父**（重挂载时）的认证缓存。

### 3.2 解绑

- 叶子子设备 → `DIRECT`；
- 有下级的子网关 → 根 `GATEWAY`（`parent_id=NULL`），其下级 `parentId` 不变，子树保持完整；
- 原父网关角色不回落；失效子设备与原父缓存。

### 3.3 ACL

`AclEvaluator.allowDelegated` 的委托方准入从「仅 `GATEWAY`」扩为「`GATEWAY` 或 `SUB`」；目标与 direct parent 校验不变。链路上每一级只对自己直接子设备负责，跨级消息无法借祖先身份直连。

### 3.4 配置

- `app.device-topology.max-depth` 默认 `2 → 5`；
- `application.yml`、`.env.example` 同步默认值；
- `docker-compose.yml` 补三项拓扑环境变量透传（enabled / max-depth / max-sub-devices）。

无数据库迁移：沿用 `device.node_type` / `parent_id` 与 `idx_device_parent`。

## 7. 关键决策与已知限制

1. **只允许挂载叶子设备**：不支持整棵子树移动，避免一次操作重排多级拓扑与缓存；需要移动子树时先逐级解绑。
2. **逐级委托而非祖先直连**：每一级只对自己的直接子设备负责，保持 ACL 判定简单可证。
3. **解绑带下级的子网关收敛为根 GATEWAY**：保留子树，避免产生「DIRECT 但有子设备」的非法状态。
4. **深度沿父链实时计算**：拓扑最大 5 层，查询成本可接受；不新增 depth 列，避免拓扑移动时维护冗余字段。
5. **默认深度提升到 5**：部署方可用 `DEVICE_TOPOLOGY_MAX_DEPTH=2` 回退两层行为；深度 <2 仍视为禁用挂载。
