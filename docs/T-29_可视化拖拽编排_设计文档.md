> 版本：v1.1　日期：2026-10-09　状态：已交付（前端；后端门禁待复验）

## 1. 背景与目标

消息规则（T-19）与场景联动（T-23）已经各自具备一套完整的编排能力：

- **消息规则**（域 6）：触发源（`PROPERTY` / `EVENT`）→ 条件（标识符 + 比较符 + 阈值）→ 动作（`UPDATE_PROPERTY` / `SEND_COMMAND` / `FORWARD_MQTT` / `FORWARD_HTTP`），T-28 补齐四档作用域；
- **场景联动**（域 12）：触发源（`PROPERTY` / `EVENT` / `TIMER`）→ 条件组（`AND` / `OR`，≤ 10 项）→ 时序步骤流（≤ 20 步，含延时与多目标），即「多条件组合 + 时序动作流」。

但两者的配置界面都还是**表单式**：`RuleEditor.vue` 是顺序表单，`SceneFormDialog.vue` 是「触发源 / 条件组 / 执行步骤」三段式表单 —— 用户看不到「触发之后数据往哪流」，条件与步骤之间的先后与依赖只能靠文字描述脑补。

对标清单把该缺口记为 **G-6-1（规则可视化拖拽编排，现为表单式）** 与 **G-12-1（场景可视化拖拽编排，现为表单式三段编辑）**，均为 P1；路线图 §7 把 G-6-1 列为「追赶（Catch-up）」首项。

本链路目标：引入**基于画布的编排视图**，把上述两套既有模型以「节点 + 连线」的图形形态呈现并就地编辑，让「触发 → 条件 → 动作」的数据流一屏可见；同时**不改变后端模型、请求体与校验口径**，存量表单视图保留可用。

## 2. 范围

### 2.1 在范围内

- 新增前端依赖 `@vue-flow/core`（Vue 3 画布库，MIT），配套 `@vue-flow/background` / `@vue-flow/controls` / `@vue-flow/minimap`。
- 共享画布组件 `OrchestrationCanvas.vue`（节点渲染、拖拽、缩放、连线、选中）+ 节点组件（触发 / 条件组 / 条件 / 步骤 / 作用域 / 动作）+ 右侧属性面板 `NodeInspector.vue`。
- **场景编排画布**：`SceneOrchestrationView.vue` 承载「触发节点 → 条件组 + 条件节点 → 步骤链」，支持拖拽新增 / 重排 / 删除节点与条件项，就地编辑节点属性。
- **规则编排画布**：`RuleOrchestrationView.vue` 承载「触发节点 → 作用域节点 → 动作节点」三节点链，支持就地编辑节点属性。
- 两个既有编辑入口（`SceneFormDialog.vue` / `RuleEditor.vue`）增加「表单 / 画布」视图切换，**表单视图原样保留为默认视图**。
- 画布状态与既有表单 `form` 响应式对象**共享同一份数据**（画布是它的图形态投影），`buildPayload` / `validateForm` 一行不改。
- 前端单元测试与验收项；`vite.config.js` 的 `manualChunks` 为 `@vue-flow` 单列分块。

### 2.2 不在范围内

| 事项 | 归属 |
|------|------|
| 步骤级分支 / 循环（G-12-2） | 需后端条件边模型，另立任务 |
| 步骤级并行执行（G-12-3） | 另立任务 |
| 规则多条件 / 多动作模型扩展（把规则引擎对齐场景） | 需后端子表 + 评估链路改造，另立任务 |
| 上下线 / 影子变更作为触发源（G-12-4） | 另立任务 |
| 秒级定时（G-12-5，现 cron 分钟级） | 另立任务 |
| 场景 / 规则版本与回滚 | 另立任务 |
| 任意 DAG 连线（自由连边） | 后端模型为「条件组 + 时序序列」，无法表达任意图（见 §4.3） |
| 后端、数据库、API 与错误码的任何变更 | 本链路为纯前端 |
| 画布布局的持久化（节点坐标落库） | 坐标仅前端会话内保存，不落库 |

| 术语 | 含义 |

## 4. 画布与模型的映射

### 4.1 画布是表单模型的投影，不是第二份状态

本链路**不引入新的编排模型**。既有表单的 `form` 响应式对象仍是唯一事实来源，画布只是它的**图形态投影**：

```
form (唯一状态)  ──project──▶  nodes / edges (画布)
       ▲                                   │
       └──────── apply (拖拽 / 属性面板) ────┘
```

- `project(form)`：把 `form` 派生为 `nodes` / `edges`（`computed`），画布只读渲染；
- `apply(nodeEvent)`：画布的拖拽 / 删除 / 属性编辑写回 `form.conditions` / `form.steps` / 触发字段；
- `buildPayload(form)` 与 `validateForm(form)` **保持现状**，一行不改 —— 校验与请求体构建仍走既有单入口，画布不引入第二条落库路径。

这样做的理由：

- **零回归**：既有表单视图与既有单测（`RuleEditor.spec.js` / `SceneFormDialog.spec.js`）不受影响，画布是纯增量；
- **零后端改动**：请求体形状不变，后端与数据库完全不动，回滚只需回退前端；
- **避免双份状态漂移**：若画布自持一份 `nodes` 状态，则「画布改了、表单没改」或反之的两份真相必然漂移，且校验 / 提交需要两套适配。

### 4.2 节点模型

前端节点类型（`utils/orchestration.js` 常量，供两处复用）：

| 类型 | `type` | 数量约束 | 适用 |
|------|--------|----------|------|
| 触发节点 | `trigger` | 恒 1 | 场景 / 规则 |
| 条件组节点 | `conditionGroup` | 恒 1（无条件项时展示空态） | 场景 |
| 条件节点 | `condition` | 0..`MAX_CONDITIONS`(10) | 场景 |
| 步骤节点 | `step` | 1..`MAX_STEPS`(20) | 场景 |
| 作用域节点 | `scope` | 恒 1 | 规则 |
| 动作节点 | `action` | 恒 1 | 规则 |

节点 `data` 只承载**渲染所需的只读快照 + 稳定标识**（`key`、标题、摘要文案、状态徽标），字段编辑一律经属性面板回写 `form`，不在节点上复制可编辑状态。

节点摘要文案直接复用既有格式化函数，不另写一套：场景用 `utils/scene.js` 的 `formatTriggerSummary` / `formatCondition` / `formatActionSummary`，规则用 `utils/rule.js` 的 `formatTriggerCondition` / `formatActionSummary` 与 `utils/scope.js` 的 `formatScopeLabel`。

### 4.3 连线由模型语义自动生成

**不开放任意连线**。后端模型是「条件组（`AND` / `OR`）+ 时序步骤序列」，它表达不了任意 DAG：允许用户自由连边，会出现「画得出来、存不下」的假象（图与 `form` 无法对应），或需要在提交时静默丢弃用户画的边。

故边由 `project(form)` 按语义生成：

| 场景边 | 生成规则 |
|--------|----------|
| 触发 → 条件组 | 条件组节点存在时恒有 |
| 条件节点 → 条件组 | 每个条件节点一条 |
| 条件组 → 步骤 1 | 条件组存在时；否则 触发 → 步骤 1 |
| 步骤 N → 步骤 N+1 | 按 `seq` 顺序成链，边标签为步骤 N+1 的延时（`delaySeconds > 0` 时显示 `延时 Ns`） |

| 规则边 | 生成规则 |
|--------|----------|
| 触发 → 作用域 → 动作 | 顺序链，作用域边标签为作用域摘要，动作边标签为冷却窗口（`cooldownSeconds > 0` 时显示 `冷却 Ns`） |

**拖拽的语义边界**：拖拽用于「新增 / 重排 / 删除节点」与「节点定位」，不用于「改拓扑」。步骤节点的拖拽重排直接改写 `form.steps` 顺序并归一化 `seq`（复用 `SceneStepEditor` 既有的 `withNormalizedSeq` 口径），这是唯一会改变语义的拖拽动作。

### 4.4 可表达的编辑动作

| 动作 | 场景 | 规则 |
|------|------|------|
| 从节点面板拖入「条件」 | 追加 `form.conditions`（≤ 10） | — |
| 从节点面板拖入「步骤」 | 追加 `form.steps`（≤ 20） | — |
| 拖动步骤节点重排 | 重排 `form.steps` + 归一化 `seq` | — |
| 删除节点（条件 / 步骤） | 从对应数组移除 | — |
| 点击节点 → 属性面板编辑 | 回写触发 / 条件 / 步骤字段 | 回写触发 / 作用域 / 动作字段 |
| 画布缩放 / 平移 / 适应视图 | 有 | 有 |
| 新增 / 删除 触发 / 条件组 / 作用域 / 动作 节点 | 不允许（恒存在） | 不允许（恒存在） |

## 5. 节点与字段映射

### 5.1 场景编排

| 画布节点 | 对应 `form` 字段 | 属性面板字段 |
|----------|------------------|--------------|
| 触发节点 | `triggerType` / `triggerDeviceId` / `triggerIdentifier` / `triggerOperator` / `triggerThreshold` / `triggerEventType` / `timerCron` | 触发方式 + 按 `triggerType` 分支的触发条件（复用 `SceneFormDialog` 现有校验与联动清理逻辑） |
| 条件组节点 | `conditionLogic` | `AND` / `OR` 单选 |
| 条件节点 | `conditions[i]`（`deviceId` / `identifier` / `operator` / `threshold`） | 设备 + 标识符 + 比较符 + 阈值 |
| 步骤节点 | `steps[i]`（`seq` / `delaySeconds` / `actionType` / `targetType` / `targetConfig` / `actionConfig` / `enabled`） | 延时 + 动作类型 + 目标 + 动作配置（复用 `SceneStepEditor` 的字段形状与 `createActionConfig` 缺省） |
| 全局属性 | `name` / `description` / `cooldownSeconds` / `enabled` | 抽屉头部（非节点） |

### 5.2 规则编排

| 画布节点 | 对应 `form` 字段 | 属性面板字段 |
|----------|------------------|--------------|
| 触发节点 | `sourceType` / `identifier` / `operator` / `thresholdValue` / `eventType` | 触发源 + 标识符 + 比较符 / 阈值 或 事件类型 |
| 作用域节点 | `scopeType` / `deviceId` / `groupIds` / `tagIds` | 四档作用范围 + 条件控件（复用 T-28 `utils/scope.js` 的 `SCOPE_TYPE_OPTIONS` / `formatScopeLabel`） |
| 动作节点 | `actionType` + 扁平动作字段（`targetIdentifier` / `targetValue` / `commandType` / `commandParams` / `topic` / `qos` / `url` / `method` / `headers` / `payloadTemplate`） | 动作类型 + 动作配置。注意规则表单存的是**扁平字段**、没有 `actionConfig`，而 `formatActionSummary` 读的是 `actionConfig`，故节点摘要需先把扁平字段组装为 `actionConfig` 再喂给它；该组装**复用从 `RuleEditor.buildActionConfig` 抽出的 `buildRuleActionConfig(form)`**（见 §10.5），提交侧 `buildPayload` 同源复用 —— 全链路只有一个组装器，不新增第二条 |
| 全局属性 | `name` / `description` / `cooldownSeconds` / `enabled`（1/0） | 抽屉头部（非节点） |

规则的触发条件内嵌在触发节点（`PROPERTY` 档的 `identifier` + `operator` + `thresholdValue` 即触发条件），故规则画布无独立条件节点 —— 这是规则扁平模型的直接反映，本链路不扩展该模型（见 §2.2）。

## 6. 技术选型

| 候选 | 结论 | 理由 |
|------|------|------|
| **`@vue-flow/core`** | **选用** | Vue 3 专用、MIT、v1.48.2；基于 React Flow 移植，内置缩放 / 平移 / 框选 / 自定义节点与边 / 连接校验；`useVueFlow` 组合式 API 与本项目 Vue 3 + Composition API 口径一致；生态含 `background` / `controls` / `minimap` 官方配套包 [$TRAE_REF](https://www.npmjs.com/package/@vue-flow/core) |
| `rete.js` | 不选 | 定位偏低代码 dataflow / 可视化编程框架，插件与信号体系学习曲线更陡、API 更底层；本链路只需要「渲染既有模型 + 拖拽重排」，不需要可插拔的运行时求值引擎 [$TRAE_REF](https://blog.csdn.net/weixin_38734472/article/details/148170020) |
| 自绘 SVG / Canvas | 不选 | 缩放 / 平移 / 命中检测 / 连线路由全部自研，成本远高于引入成熟库，且与「不重复造轮子」的既有前端口径不符 |
| `echarts`（已在库） | 不选 | 图表库，`graph` 系列面向数据可视化展示，不支持「拖拽新增节点 / 就地编辑」的编辑器语义 |

依赖与打包：

- `package.json` 新增 `@vue-flow/core`（并视需要 `@vue-flow/background` / `@vue-flow/controls` / `@vue-flow/minimap`）；
- `vite.config.js` 的 `manualChunks` 追加 `if (id.includes('@vue-flow')) return 'vue-flow'`，避免并入 `vendor` 被入口 `modulepreload` 拖累工作台首屏（与 `highlight.js` 分块口径一致）；
- 画布组件走**动态导入**（`defineAsyncComponent`），仅切到画布视图时才加载该分块，表单视图不承担该体积。

## 7. 组件结构

```
components/orchestration/
├── OrchestrationCanvas.vue     画布容器：VueFlow + Background + Controls + MiniMap + 节点面板 + 属性面板
├── NodePalette.vue             左侧节点面板（可拖入的节点类型；按编排类型过滤）
├── NodeInspector.vue           右侧属性面板（按选中节点类型分派到字段表单）
└── nodes/
    ├── TriggerNode.vue         触发节点
    ├── ConditionGroupNode.vue  条件组节点（AND/OR）
    ├── ConditionNode.vue       条件节点
    ├── StepNode.vue            步骤节点
    ├── ScopeNode.vue           作用域节点
    └── ActionNode.vue          动作节点
```

场景与规则各自的「投影 / 回写」逻辑放在独立模块，避免容器组件承担领域知识：

```
views/workbench/scene/orchestration.js     projectScene(form) / applySceneEvent(form, event)
views/workbench/rule/orchestration.js      projectRule(form) / applyRuleEvent(form, event)
```

`OrchestrationCanvas` 通过 props 接收 `nodes` / `edges` / `palette` / `inspector`，通过 emit 抛出 `node-add` / `node-remove` / `node-reorder` / `node-update`，由调用方（场景 / 规则视图）翻译为 `form` 写入 —— 容器组件不含领域分支。

## 8. 交互边界

| 边界 | 约定 |
|------|------|
| 与 T-23 场景模型 | 只读写 `form`（其形状与 `SceneRequest` 一致），不改 `SceneRequest` / `SceneDefinition` / 评估与执行链路 |
| 与 T-19 / T-28 规则模型 | 只读写 `form`（其形状与 `RuleRequest` 一致），不改 `RuleRequest` / `RuleDefinition` / 作用域校验与评估链路 |
| 与表单视图 | 同一份 `form` 的两个视图，切换时无需转换；切换不触发校验（校验仍在提交时执行） |
| 与既有校验 | `validateForm` 原样复用；画布不新增校验规则，也不放宽既有约束（上限、必填、Cron 合法性等） |
| 与既有子编辑器 | `SceneConditionEditor` / `SceneStepEditor` 保留给表单视图使用；画布不依赖它们，但**字段形状与缺省值口径必须一致**（`createActionConfig` / `createCondition` / `createStep` 抽到 `utils/scene.js` 复用，避免两处漂移） |
| 与实时 / 执行链路 | 无耦合；画布只产出配置，不参与评估、执行、通知 |

## 9. 接口设计

**不新增任何端点、不改任何请求体与响应体。** 画布产出的 payload 与既有表单视图逐字段一致：

- 场景：`SceneRequest`（`POST /scenes` / `PUT /scenes/{id}`）；
- 规则：`RuleRequest`（`POST /rules` / `PUT /rules/{id}`）。

无新增错误码、无新增后端配置项。

## 10. 前端详细设计

### 10.1 视图切换

- `SceneFormDialog.vue`：抽屉头部增加「表单 / 画布」分段控件，`viewMode` 默认 `form`；切到画布时抽屉宽度由 `640px` 放宽到 `min(1100px, 92vw)`，画布区域高度撑满抽屉内容区。
- `RuleEditor.vue`：同上，抽屉宽度由 `560px` 放宽到 `min(880px, 92vw)`。
- 切换视图不重置 `form`，也不触发校验；提交按钮与「试运行」在两种视图下行为一致。

### 10.2 画布布局与坐标

- 首次 `project` 时按固定算法布局（触发居左，条件组居中，步骤按 `seq` 向右 / 向下延伸），不持久化坐标；
- 用户拖动后的坐标仅存于前端会话（`nodes` 的 `position`），刷新即回到默认布局 —— 不落库、不进请求体（见 §2.2）。

### 10.3 校验反馈

画布视图下的校验仍走 `validateForm`，错误文案以 `ElMessage.warning` 提示（与表单视图一致）；同时把错误定位到对应节点：`validateForm` 返回的文案含「第 N 个条件 / 第 N 步」前缀时，画布高亮对应节点并居中显示。

### 10.4 空态与上限

- 无步骤：画布展示空态提示「请至少添加一个执行步骤」并高亮节点面板的「步骤」项；
- 达到 `MAX_CONDITIONS` / `MAX_STEPS`：节点面板对应项置灰（与 `SceneStepEditor` 的 `:disabled` 口径一致）。

### 10.5 复用与抽取

为避免表单视图与画布视图的字段缺省值 / 联动清理逻辑两处漂移，以下逻辑抽到共享模块：

- `utils/scene.js` 追加 `createCondition()` / `createTargetConfig()` / `createActionConfig(actionType)` / `createStep(timerSource)` / `normalizeStep(step, timerSource)` / `withNormalizedSeq(items)`（从 `SceneConditionEditor` / `SceneStepEditor` 提取，二者改为复用）。

> 说明：`createStep` 与 `normalizeStep` 原为组件内函数，依赖 `props.timerSource`（`TIMER` 触发源下目标锁 `FIXED`）。抽到纯模块后失去 `props` 上下文，故**把 `timerSource` 提升为显式入参**；组件侧改为 `createStep(props.timerSource)` / `normalizeStep(step, props.timerSource)` 传参，行为不变。`createCondition` / `createTargetConfig` / `createActionConfig` / `withNormalizedSeq` 本无组件上下文依赖，签名不变。
- `utils/rule.js`（**既有文件**）追加 `buildRuleActionConfig(form)`（从 `RuleEditor.buildActionConfig` 提取，模块级 `form` 提升为入参，其局部 JSON 解析口径一并带上）与 `normalizeRuleScope(form)`（从 `RuleEditor.handleScopeTypeChange` 提取，切档时清掉非当前档位的 `deviceId` / `groupIds` / `tagIds`）。

> 规则侧只需抽上面两个函数：`buildRuleActionConfig` 解决「扁平字段 ↔ `actionConfig`」的同源问题（规则表单存扁平字段、无 `actionConfig`，画布摘要与提交体必须共用同一组装器）；`normalizeRuleScope` 解决切档联动清理的同源问题（表单视图的 `handleScopeTypeChange` 与画布作用域面板必须共用，否则两处清理口径会漂移）。规则的触发 / 作用域字段本就是 `form` 顶层字段（`formatTriggerCondition` / `formatScopeLabel` 可直接吃 `form`），无需转换。规则画布节点恒存在（`node-add` 为空操作），**不需要**按动作类型重置字段的工厂 —— 表单视图切换动作类型时本就不重置（`buildActionConfig` 只读当前类型对应字段，陈旧字段不进提交体），画布沿用同一口径。

抽取只做「移动 + 复用」，不改行为；既有单测保证等价。

## 附：设计自审

1. **是否动到底层架构**：否。本链路为纯前端表示层升级，后端模型、请求体、校验、评估、执行与通知链路全部零改动；符合「先补齐功能缺口，再动底层架构」的既有工作流。
2. **是否引入第二份状态**：否。画布是既有 `form` 的图形态投影（`project` / `apply` 双向），唯一事实来源仍是 `form`；`buildPayload` / `validateForm` 一行不改，不存在两套提交路径。
3. **是否引入「画得出来、存不下」的假象**：否。连线由模型语义自动生成，明确不开放任意连边；拖拽的语义边界限定为「新增 / 重排 / 删除节点」与「定位」，其中只有步骤重排会改变语义，且直接复用既有 `seq` 归一化口径。
4. **回滚是否安全**：是。纯前端改动，无迁移、无后端变更；回滚只需回退前端构建产物，存量表单视图与接口契约不受影响。
5. **是否与既有校验 / 上限漂移**：否。`validateForm` 原样复用，画布不新增也不放宽任何约束；上限常量沿用 `MAX_CONDITIONS` / `MAX_STEPS`；字段缺省值与联动清理逻辑抽到共享模块供两视图复用，避免两处漂移。
6. **遗留待定**：规则的触发条件内嵌于触发节点（扁平模型所致），规则画布因此只有三个节点、结构上不可拖拽新增。是否把规则引擎对齐场景模型（多条件 / 多动作）以让规则画布获得与场景同等的编排自由度，需后端子表与评估链路改造，另立任务评估；本期如实呈现模型，不假装规则具备其没有的编排能力。
7. **遗留待定**：节点坐标不持久化 —— 刷新后回到默认布局。是否需要「布局随规则 / 场景保存」需后端新增列与请求体字段，本期以「不落库」换取零后端改动，另立任务评估。
8. **遗留待定**：`@vue-flow/core` 为新增第三方依赖，需在 `DEPLOYMENT.md` 的构建说明中登记版本与许可；本期在 `package.json` 锁定 `^1.48.2`，并在实施计划的文档回填阶段同步登记。
9. **自审校准（对照真实代码）**：抽取清单已逐条核对到函数级 —— `createCondition` / `createTargetConfig` / `createActionConfig` / `withNormalizedSeq` 无组件上下文依赖，签名不变；`createStep` / `normalizeStep` 依赖 `props.timerSource`，提升为显式入参；规则侧原设想的 `createRuleActionConfig` / `emptyRuleForm` 在 `RuleEditor` 中并不存在（实为 `emptyForm`，且动作类型切换本就不重置字段），故改为抽 `buildRuleActionConfig(form)` 与 `normalizeRuleScope(form)`；`formatActionSummary` 读 `actionConfig` 而规则 `form` 存扁平字段，故 `projectRule` 必须复用提交侧同一组装器，否则摘要与提交体两处漂移。设计文档 §5.2 / §10.5 与实施计划 P1 / P4 已同步修正。
