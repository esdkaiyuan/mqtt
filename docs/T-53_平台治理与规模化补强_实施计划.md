# T-53 · 平台治理与规模化补强（审计日志 / 设备导入导出 / 开放 API 批次二 / HTTP 上报限流与幂等）

> 版本：v1.0　创建日期：2026-10-26　状态：**已交付**
> 定位：在 T-52 收口后，对照主流 MQTT / IoT 平台（阿里云 IoT、ThingsBoard、AWS IoT Core、EMQX Cloud、ThingsCloud）补齐**平台治理与规模化**能力，不引入新的运行时子系统。
> 输入依据：`docs/头部平台对标_尚未补齐功能项清单.md` v2.15、`docs/平台功能链路路线图.md`、`docs/ARCHITECTURE.md` v1.39、后端 / 前端实际在库代码。

## 1. 背景与目标

T-52 之后，平台在「设备接入 → 物模型 → 命令 / 影子 → 规则 / 告警 / 场景 → OTA → 可视化」主线上已基本对齐一线平台，剩余缺口集中在三类：

1. **治理与合规**：主流平台均提供操作审计（谁在何时改了什么），本平台此前只有应用日志，无法在控制台追溯到具体用户与资源；
2. **规模化接入**：设备台账仍只能单台创建或按前缀批量注册，缺少从既有系统 / Excel 迁移的 CSV 通道；HTTP 上报没有设备级限流与弱网重试去重；
3. **开放 API 覆盖不均**：分组、标签、规则执行、场景执行、看板、点位表在控制台已有，但 `/external/v1` 未暴露。

本任务只做**能力补强**，不改动摄取主链路、MQTT 主题 / ACL、告警 / 规则 / 场景评估语义，也不新增 `IngestDispatcher` fan-out 路。

## 3. 设计决策

### 3.1 审计日志：拦截器统一记录，而不是逐控制器埋点

- 选型：`HandlerInterceptor`（`AuditLogInterceptor`）+ `AuditLogWebConfig` 注册，**不用 Filter**。原因：审计需要登录态，拦截器在 DispatcherServlet 内、鉴权之后执行，`afterCompletion` 拿得到最终状态码与异常；Filter 需要显式编排到安全链中间。
- 覆盖范围：只记录 `POST` / `PUT` / `PATCH` / `DELETE`。读请求量大且审计价值低，全量记录会把审计表变成第二份访问日志。
- 认证事件：登录 / 注册 / 登出由 `AuthController` 显式记录。登录 / 注册发生在鉴权之前，登出会提前清空 `SecurityContext`，拦截器都拿不到用户身份。
- **不读请求体**：写请求里可能含设备密钥、API Key、证书私钥；审计只记录路径、动作、资源与结果。`AuditRequestInfo` 只读请求头与 IP。
- 动作解析：`AuditActionResolver` 按「HTTP 方法 + 路径后缀」推导 `action` / `resourceType` / `resourceId`（纯函数、可单测）。动作是展示与检索口径，不是权限判断依据。
- 失败隔离：审计写库异常只记 WARN，绝不影响业务请求。
- 保留清理：`AuditLogSweeper` 按 `AUDIT_LOG_RETENTION_DAYS` 分批硬删除；`enabled=false` 或间隔 `<=0` 不注册。审计表只追加，不提供修改 / 删除接口。
- 查询权限：`/audit-logs/**` 在 `SecurityConfig` 限定 ADMIN；控制器再加 `@PreAuthorize` 双重防护。

### 3.2 设备导入：复用单设备创建事务，逐行隔离

- `DeviceImportServiceImpl` 不直接操作 Mapper，而是逐行调用 `DeviceService.createDevice`（`@Transactional` 独立 Bean）。这样每台设备在自己的事务里创建 + 签发凭据，单行失败不影响已成功行，且与单设备创建共享同一套 deviceKey 唯一性 / 产品校验 / BCrypt 签发逻辑。
- CSV 解析新增 `CsvReader`（与 `CsvWriter` 配对）：BOM、引号内逗号 / 换行 / 双引号、CRLF / LF。格式非法抛业务码 `6316`。
- 列约定：`deviceKey` / `deviceName` / `productKey` 必填；`deviceType` 缺省 `sensor`，`topic` 缺省 `device/{deviceKey}/data`；`description` 可选；`firmwareVersion` 为 T-54 追加的可选列。
- 上限：单次 1000 行、2MB（`DEVICE_IMPORT_*`），避免一次导入打爆内存与数据库。
- 凭据：每台成功设备返回 `deviceKey` / `username` / 一次性 `secret`，仅本次响应；前端复用 `buildCredentialsCsv` + `downloadTextFile` 导出。
- 导出：按列表筛选条件导出设备台账（含产品、分组、标签、状态、拓扑、心跳），**不含任何密钥**；与「导出全部设备凭据」（ADMIN、会重置密钥）严格区分。
- 导入权限：`@PreAuthorize("hasAnyRole('ADMIN','OPERATOR')")`；导出沿用列表数据范围（非 ADMIN 仅本人设备）。

### 3.3 开放 API 批次二：继续只读、复用服务

- 新增端点：分组（平铺 / 树）、标签、点位表、规则执行记录、场景执行记录 / 详情、看板列表 / 详情。
- 与 T-35 同一约定：**零业务逻辑重写、严格只读、归属隔离由服务层 userId 校验承担**；API Key 只能看到本账号数据。
- 分组接口**不返回共享分组**（`includeShared=false`），避免 API Key 越出账号数据边界。
- 响应投影只挑展示字段：分组不暴露 `userId` / `deleted`，标签不暴露内部字段；看板列表不搬运 `config` 明细。

### 3.4 HTTP 上报限流与幂等：参数校验之后、入队之前

- 位置：`HttpIngestServiceImpl.ingest` 内，白名单 / 载荷大小校验之后、`IngestPipeline.submit` 之前。非法报文不占配额，也不会写幂等键（设备改好报文重试不会被误判为重复）。
- 限流：按设备固定 60 秒窗口 Redis `INCR`，键 `mqtt:ratelimit:ingest:{deviceKey}:{window}`；默认关闭（`HTTP_INGEST_RATE_LIMIT_ENABLED=false`），Redis 故障按 `failOpen` 放行或拒绝。
- 幂等：请求头 `Idempotency-Key`（1~128 个可见 ASCII），键 `mqtt:ingest:idem:{deviceKey}:{sha256(key)}`，`SET NX EX` 原子写入；值存首次受理时间。重复请求返回 `accepted=false`、`X-Ingest-Duplicate: true`，不再入队。
- Redis 幂等故障一律放行：宁可重复一条数据，也不能因缓存故障阻断全部设备上报。
- 兼容：不带 `Idempotency-Key` 的既有设备行为完全不变。

## 4. 数据模型

### 4.1 `audit_log`（`V31__audit_log.sql`）

| 列 | 类型 | 说明 |
|---|---|---|
| `id` | BIGINT PK | 自增主键 |
| `user_id` | BIGINT NULL | 操作者；**无外键**，用户删除后保留痕迹 |
| `username` / `role` | VARCHAR | 操作者快照 |
| `source` | VARCHAR(16) | `CONSOLE` / `OPEN_API` / `DEVICE` / `ANONYMOUS` |
| `http_method` / `path` | VARCHAR | 方法 / 去掉 context-path 的路径 |
| `action` | VARCHAR(32) | 动作编码（`CREATE` / `UPDATE` / `DELETE` / `COMMAND` / `ACK` / `LOGIN` …） |
| `resource_type` / `resource_id` | VARCHAR | 资源类型与路径中的标识 |
| `status_code` / `success` / `error_message` | INT / TINYINT / VARCHAR | 结果与失败摘要（不含请求体） |
| `ip` / `user_agent` / `duration_ms` | VARCHAR / BIGINT | 来源与耗时 |
| `created_at` | DATETIME(3) | 操作时间 |

索引：`idx_audit_user_time (user_id, created_at)`、`idx_audit_time (created_at)`、`idx_audit_action_time (action, created_at)`、`idx_audit_resource (resource_type, resource_id)`。

### 4.2 无新增表

设备导入、HTTP 限流 / 幂等、开放 API 批次二均无 DDL。

### 5.3 设备 HTTP 上报

`POST /ingest/{deviceKey}/{messageType}` 新增可选请求头 `Idempotency-Key`；重复请求返回 `accepted=false` 与 `X-Ingest-Duplicate: true`；超出频率返回 `429` + `6314`。

### 5.4 新增错误码

| 码 | 含义 |
|---|---|
| `6313` | 审计日志查询条件非法 |
| `6314` | HTTP 上报超出设备频率限制 |
| `6315` | 幂等键非法 |
| `6316` | 设备导入文件非法 |
