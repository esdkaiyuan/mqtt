## 计划概览

- **Goal**：落地 X.509 / JWT 认证与产品级 Topic 模板，三种认证方式并存，EMQX 认证回调按产品 `auth_mode` 分派。
- **Architecture**：单条 EMQX HTTP 认证器加 `${cert_subject}` / `${cert_common_name}` 占位符，分派全部收敛在 `EmqxAuthServiceImpl`；新增 8883 mTLS 监听器承载 X.509；授权侧主题前缀改由 `topic_prefix` 模板解析。
- **Tech Stack**：Java 17 + Spring Boot 4.1.1（Spring Security 6.5 过滤器链，`SecurityFilterChain` bean 装配）+ MyBatis-Plus 3.5.17 + Flyway + jjwt 0.12.7（JWT 签发与验签）+ BouncyCastle（证书签发）+ JUnit 5 + Mockito + ArchUnit；Vue 3 控制台与文档站。
- **Spec**：`docs/T-25_认证方式扩展_设计文档.md` v1.0。
- **Global Constraints**：
  - 设备 JWT 密钥与控制台 `app.jwt.secret` 严禁复用。
  - CA 私钥与设备私钥不入库、不落日志。
  - 认证回调失败统一返回 `deny`，不新增同义错误码。
  - 错误码自 6249 起，追加时把 `ResultCode` 现有末行分号改为逗号。
  - 配置段插入 `application.yml` 的 `http-ingest` 之后、`logging` 之前。
  - 迁移文件为 `V13__device_certificate.sql`。
  - ArchUnit 既有四条规则不得放松。
  - 默认模板 `device/{deviceKey}` 下，订阅生成须与既有 `device/+/...` 逐条一致。
