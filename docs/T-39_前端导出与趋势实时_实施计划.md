## 2. 设计决策（后续勿推翻）

1. **附件下载不能改变既有 blob 契约**
   - 现有固件下载 / 物模型导出直接拿 `Blob`；
   - 导出需要 `Content-Disposition` 与 `X-Export-Truncated` 响应头，故新增显式 `returnFullResponse: true` 配置，响应拦截器仅在该标记下返回完整 `response`，其余请求行为逐字不变。
2. **文件名以服务端为准**
   - 从 `Content-Disposition` 优先解析 `filename*=UTF-8''...`，解析失败才用前端兜底名；
   - 中文设备名不会出现乱码文件名。
3. **截断必须提示**
   - 后端 `X-Export-Truncated=true` 时前端明确警告「文件可能已截断」，避免用户误以为导全了。
4. **导出条件与当前筛选一致**
   - 设备日志用当前表单的 `types / startTime / endTime / keyword`；
   - 属性趋势用当前 `identifier / range / bucket`；
   - 命令记录从第 1 页导出（不分页）；
   - 告警用当前 `status / sourceType / severity / openOnly`。
5. **实时追加是可选开关，默认关闭**
   - 事件来自应用级 SSE 的 `property-trend`，payload 为 `{ deviceId, deviceKey, samples[] }`；
   - 与历史分桶合并时按 `time` 去重，实时点覆盖同时间桶；最多保留 600 个实时点，避免长时间开启导致内存与图表类目无限增长；
   - 开启时把游标定位到当前最后一条事件，避免把开关打开前的历史事件一次性倒灌；
   - 切换属性或关闭开关时清空实时点。
6. **实时流依赖服务端开关**
   - `PROPERTY_HISTORY_STREAM_ENABLED=false` 时不会收到 `property-trend` 事件；UI 用提示说明，不假装实时；
   - 设备日志实时流仍未做（没有单一写入点），不在本批范围。

## 5. 验收标准

1. 设备日志、属性趋势、命令记录、告警列表四个页面均可导出 CSV，文件名正确、中文不乱码；
2. 导出被截断时出现明确提示；
3. 开启「实时追加」后，收到 `property-trend` 事件时曲线立即追加新点；关闭后不再追加且清空实时层；
4. 既有固件下载 / 物模型导出行为不变；
5. 前端 `eslint` 0 error、`vitest` 全绿、`vite build` 通过。

## 7. 明确不做

- 设备日志实时流（X-3 剩余项，无单一写入点）；
- 导出任务异步化 / 大文件分片下载；
- 导出格式选择（JSON / Excel）；
- 实时曲线的断线回补（断线期间的历史数据仍通过重新查询获取）。
