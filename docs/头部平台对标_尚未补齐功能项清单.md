## 1. 口径与分类

**对标基线**：ThingsCloud（主基线）、阿里云 IoT（TSL / 影子 / 服务调用）、ThingsBoard（Rule Chain / RPC）。

**差距分类**：

| 类别 | 含义 | 数量 |
|------|------|------|
| **A 未交付链路** | 路线图中尚未交付的整条功能链路 | 2 |
| **B 能力域增强** | 链路已交付、但 §2 明确标注「缺…」的补强项 | 10 |
| **C 交付内声明的未做/待办** | 各任务交付文档「未做 / 待办」中已明示、尚未闭环的条目 | 40+ |
| **D 文档欠账** | 已交付但未回填 / §2 行已过期 | 2 |

**优先级口径**：`P0` = 主流平台必备、影响商用可用性；`P1` = 已有能力的重要补强；`P2` = 体验 / 规模化增强；`待补测` = 能力已实现、仅缺现场实测。

> **一句结论**：通信与接入主线（T-01~T-13）与「建模 → 控制 → 影子 → 告警 → 分组 → 规则 → 日志 → 时序 → OTA → 场景」平台主线均已打通；**尚未补齐的缺口集中在三处** —— ① 两条整链路（多协议接入、认证方式扩展）；② 各能力域的「增强项」（可视化编排、通知渠道、作用域、灰度、配额、导出/实时化、开放 API 覆盖）；③ 文档回填与现场验收欠账。

**差异化（Differentiate）— 已有能力做强**：G-6-3 / G-7-4 / X-5 规则与告警的分组标签作用域、G-8-1 分组级权限共享、G-5-1 多设备影子聚合、G-12-2 / G-12-4 场景分支与上下线触发（把「场景 + 影子 + 告警」串成联动闭环）。

**体验与规模化（Scale）**：X-1 开放 API 补齐、X-2 导出、X-3 实时推送、G-10-1 大屏 / 分享。

**工程收口（Hygiene）**：D-1 / D-2 文档回填、X-6 现场验收补测。

> 排期建议：**先做 P0 两条链路（L11 / L12）与 D 类文档回填**，再按 P1 增强项（通知渠道、作用域、可视化、OTA 灰度、命令配额）分批推进。
