## 1. 口径与分类

**对标基线**：ThingsCloud（主基线）、阿里云 IoT（TSL / 影子 / 服务调用）、ThingsBoard（Rule Chain / RPC）。

**差距分类**：

| 类别 | 含义 | 数量 |
|------|------|------|
| **A 未交付链路** | 路线图中尚未交付的整条功能链路 | 0 |
| **B 能力域增强** | 链路已交付、但 §2 明确标注「缺…」的补强项 | 8 |
| **C 交付内声明的未做/待办** | 各任务交付文档「未做 / 待办」中已明示、尚未闭环的条目 | 50+ |
| **D 文档欠账** | 已交付但未回填 / §2 行已过期 | 0 |

**优先级口径**：`P0` = 主流平台必备、影响商用可用性；`P1` = 已有能力的重要补强；`P2` = 体验 / 规模化增强；`待补测` = 能力已实现、仅缺现场实测。

> **一句结论**：通信与接入主线（T-01~T-13）与「建模 → 控制 → 影子 → 告警 → 分组 → 规则 → 日志 → 时序 → OTA → 场景 → 多协议接入 → 认证方式扩展 → 子设备与网关代理接入 → 通知渠道扩展 → 规则与告警作用域 → 可视化拖拽编排」平台主线均已打通，A / D 两类已清空；**尚未补齐的缺口集中在两处** —— ① 各能力域的「增强项」（OTA 灰度、命令配额、导出 / 实时化、开放 API 覆盖）；② 现场验收欠账。

## 7. 建议补齐顺序

**追赶（Catch-up）— 主流平台普遍具备、本项目缺失**：G-6-7 规则多条件 / 多动作模型、G-11-1 / G-11-2 OTA 灰度与固件校验、G-4-1 命令级权限与配额。

**差异化（Differentiate）— 已有能力做强**：G-8-1 分组级权限共享、G-5-1 多设备影子聚合、G-12-2 / G-12-4 场景分支与上下线触发（把「场景 + 影子 + 告警」串成联动闭环）。

**体验与规模化（Scale）**：X-1 开放 API 补齐、X-2 导出、X-3 实时推送、G-10-1 大屏 / 分享。

**工程收口（Hygiene）**：X-6 现场验收补测（T-15~T-21 待逐条实测，T-26 / T-27 / T-28 / T-29 待现场验收）。

> 排期建议：**A / D 两类已随 T-24、T-25 清空，子设备认证随 T-26、通知渠道随 T-27、规则与告警作用域随 T-28、可视化编排随 T-29 交付落地**，后续按 P1 增强项（规则多条件 / 多动作、OTA 灰度、命令配额）与域14 更深拓扑分批推进，并把 T-15~T-21 的现场验收补测并入其中。
