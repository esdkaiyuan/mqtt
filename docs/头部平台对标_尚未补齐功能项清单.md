## 1. 口径与分类

**对标基线**：ThingsCloud（主基线）、阿里云 IoT（TSL / 影子 / 服务调用）、ThingsBoard（Rule Chain / RPC）。

**差距分类**：

| 类别 | 含义 | 数量 |
|------|------|------|
| **A 未交付链路** | 路线图中尚未交付的整条功能链路 | 0 |
| **B 能力域增强** | 链路已交付、但 §2 明确标注「缺…」的补强项 | 3 |
| **C2 规模化增强** | X 类（导出 / 实时推送 / 开放 API 覆盖） | 0 |
| **C 交付内声明的未做/待办** | 各任务交付文档「未做 / 待办」中已明示、尚未闭环的条目 | 50+ |
| **D 文档欠账** | 已交付但未回填 / §2 行已过期 | 0 |

**优先级口径**：`P0` = 主流平台必备、影响商用可用性；`P1` = 已有能力的重要补强；`P2` = 体验 / 规模化增强；`待补测` = 能力已实现、仅缺现场实测。

> **一句结论**：通信与接入主线（T-01~T-13）与「建模 → 控制 → 影子 → 告警 → 分组 → 规则 → 日志 → 时序 → OTA → 场景 → 多协议接入 → 认证方式扩展 → 子设备与网关代理接入 → 通知渠道扩展 → 规则与告警作用域 → 可视化拖拽编排 → OTA 灰度与固件校验 → 规则多条件多动作 → 命令权限与配额」平台主线均已打通，A / D 两类与 **P1 追赶段全部清空**；**尚未补齐的缺口集中在两处** —— ① 各能力域的「增强项」（脚本化解析、数据桥接、开放 API 写操作、OTA 对象存储 / 固件签名、多租户等）—— T-53 已补齐审计日志、设备台账导入导出、开放 API 只读批次二与 HTTP 上报限流 / 幂等；T-54 补齐 OTA 固件版本跟踪与降级拦截；T-55 补齐产品级 Payload Codec 声明式数据映射；② 现场验收欠账。
