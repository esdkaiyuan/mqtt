## T-31 P4：平台侧 Modbus 主站采集（交付）

补齐路线 B：平台自己作为 Modbus TCP 主站，按 `device_point_table.executor='PLATFORM'` 的点位周期轮询并入库。

### 落地内容

- `collect/modbus/`：`ModbusPointCollector`（driverId=modbus-tcp）、`ModbusMasterRegistry`（信号量限流 + finally 关闭）、`ModbusValueConverter`、`ModbusPointDispatch`（同功能码连续地址合并读）、`ModbusConnectionConfig`；
- `service/ModbusCollectService` + `Impl`、`service/impl/PointRunRecorder`；
- `config/ModbusCollectProperties` / `ModbusCollectExecutorConfig`（独立阻塞 IO 线程池，CallerRuns）/ `ModbusCollectSweeper`；
- `DevicePointTableMapper.findDuePlatformPoints` 增加 `minIntervalMs`，用 `TIMESTAMPADD + GREATEST` 在 SQL 内钳制周期下限；
- 15 个 `MODBUS_*` 环境变量透传 `.env.example` / `docker-compose.yml`。

### 关键决策（后续勿推翻）

1. **采集结果走 `IngestPipeline`，不直写属性表** —— 否则绕过物模型解析 / 影子 / 规则 / 告警 / 场景 / 历史五条旁路。
2. **`messageType=data` 且必须是 Alink 信封** —— 解析链路只处理 `method + params`；`params` 数值 / 布尔 / 文本必须是 JSON 原生类型，字符串数字会被判非法。
3. **合并维度 = 功能码 + 连续地址**，不按 `read_interval`；到期查询已筛过周期，再按周期拆组会让同一设备开多个连接。
4. **设备级单 unitId**；多从站需在分组键加 unitId，本批不假装支持。
5. **默认不常驻连接、只读、不写寄存器**；连接失败不改设备在线状态（平台网络故障 vs 真离线无法区分）。
6. **SKIPPED 只表示状态不允许采集**；未到周期的点位不进到期查询、不写日志行，避免日志爆炸。
7. **在途设备去重**：异步任务完成前下一轮巡检仍会判到期，重复提交会重复读总线。

### 踩坑

- j2mod 3.4.0 的包名是 `com.ghgande.j2mod.modbus`（不是老版 `com.serotonin.modbus4j`）；`readMultipleRegisters` 返回 `Register[]`、`readInputRegisters` 返回 `InputRegister[]`，异常类型是 `ModbusException` 而非 `IOException`；Mockito 对后者的 checked 类型校验会直接报错。
- `DeviceService.getDeviceById` 在设备不存在时抛 `BusinessException`，不是返回 null；采集任务里改用 `getById` 并自行判空，避免把「设备已删」记成「任务异常」。
- 同一设备异步任务未落日志前，下一轮巡检会再次选中它；必须加 `inFlightDevices` 去重。

## T-40：Modbus 字序与 32 位整型（交付）

补齐平台侧 Modbus 的真实现场兼容缺口：word-swap 浮点与 32 位累计量。

### 落地内容

- `driver_config.wordOrder`：ABCD（默认）/ CDAB / BADC / DCBA；`ModbusConnectionConfig` 解析时校验，非法值显式失败。
- `ModbusValueConverter`：新增 int32 / uint32；32/64 位数值先按大端展开字节，再按字序重排：
  - CDAB 每个 32 位字内交换两个 16 位字；
  - BADC 每个 16 位字内交换字节；
  - DCBA 完整反转（小端）；double 的 CDAB/BADC 按每 4 字节块处理。
- 点表 dataType 白名单与前端选项同步扩 `int32/uint32`；零迁移（dataType 是字符串列、wordOrder 在 JSON 内）。

### 踩坑

- 测试 double 的 DCBA 时，**不能只把寄存器数组倒序**：DCBA 是完整字节反转，输入寄存器还需按「小端字节流重新打包成大端寄存器」。只倒序数组得到的是 `[b6,b7,b4,b5,...]`，再 reverse 仍不是大端；测试因此先构造大端字节、反转、再按寄存器打包。
- 「字序」只应作用于 int32/uint32/float/double；16 位 int、bool、string 不重排，否则单寄存器值会被改坏。
- 非法 wordOrder 不能静默回落 ABCD——现场会误以为配置生效，结果仍读错值。

## T-44：场景步骤分支与循环（交付，G-12-2）

把线性步骤流扩为「向前条件分支 + 有界计数循环」，不引入第二套流程引擎。

### 落地内容

- `SceneConstants` 新增 `STEP_BRANCH` / `STEP_LOOP` / `TARGET_NONE`，`STEP_TYPES` 与 `FLOW_STEPS`；
- `SceneValidator` 保存期结构校验：分支只向前、目标必须存在且启用、禁止从循环外跳入；循环范围嵌套或互斥；单循环 ≤20 次、展开 ≤200 步；
- `V23__scene_flow_steps.sql`：`scene_step_run` 增加 `loop_iteration` / `flow_result`，同步步骤类型列注释；
- `SceneActionExecutorImpl`：`StepOutcome`（NEXT / JUMP / END / REPEAT）路由；分支读属性最新值选 `trueSeq` / `falseSeq`；循环未完成时 `resetLoopBody` + `resetLoopStep` 重放；终态清理残留 `PENDING` 并按明细 `recountFinishedSteps`；
- `SceneTestServiceImpl`：流程步骤摘要与循环展开耗时上界；
- 前端：表单 / 画布流程步骤编辑与目标显隐、分支 / 循环跳转边、步骤增删移动引用重映射、执行抽屉展示 `flowResult` / `loop_iteration`；
- 文档：T-44 实施计划、总督促 §3.37 / v1.48、路线图 L31 / v2.21、对标清单 G-12-2 / v2.7、ARCHITECTURE v1.31、DEPLOYMENT 排障。

### 关键决策（后续勿推翻）

1. **只向前分支，不做任意回跳**：分支目标必须大于当前 `seq`，从模型上消除不可判定循环。
2. **循环步骤是结束标记**：循环体由 `startSeq` 向前引用，`times` 为次数；不新增块表 / 嵌套结构。
3. **一行一步骤复用**：循环轮次写入 `loop_iteration`，每轮覆盖同一行；不保留逐轮历史，这是不新建明细表的取舍。
4. **进度以明细为准**：循环重放、手动重试、终态收口都 `recountFinishedSteps`，不要依赖手工 `bumpFinishedSteps` 叠加。
5. **终态统一清理 PENDING**：分支跳过、循环提前退出留下的 PENDING 在收口时置 SKIPPED，避免悬挂。
6. **结构约束**：分支不能从循环外跳进循环体（含循环步骤本身）；循环范围只能完全嵌套或互不相交。

### 踩坑

- `SceneExecutionLauncher` 只为启用步骤建 run；分支目标 / 循环起始步骤必须校验为启用，否则运行时会「找不到目标」而提前结束。
- `stepRunColumns` 是显式列清单，新增 `loop_iteration` / `flow_result` 必须同步 XML，否则查询出来为 null（MyBatis 不会自动补列）。
- 结束收口原先只在 `markSuccess` 里直接置执行成功，分支/循环会留下 PENDING；现在必须先 `markSkipped` 再 `recountFinishedSteps`。
- 循环重放不能直接 `bumpFinishedSteps(-N)`：并发 / 部分重置会漂移，统一按明细重算。
- 前端 `normalizeStep` 必须先判断流程步骤再处理转发 / FIXED，否则 BRANCH/LOOP 会被错误写回 `TRIGGER` 目标。
- 画布新增回跳边只是可视化，执行顺序完全由服务端 `seq` 决定；不要试图让 Vue Flow 的边参与执行。

### 关键决策（后续勿推翻）

1. **只发布实际变化**：值未变或 CAS 失败不发布；CAS 重试耗尽的事件随合并一起放弃，宁缺勿重。

4. **reported 来源 INGEST**：摄取链路在属性 `upsertIfNewer` 后回读权威值，影子与属性最新值同源。
5. **失败隔离**：事件发布 / 场景评估异常只记 WARN，绝不影响影子写入或命令事务。

- `DeviceShadowServiceImpl` 原来 `merge` 不区分目标侧，也不保留前后状态；要计算 diff 必须在 mutator 前后对**目标侧**做快照，不能用整个 State 比较（会混入另一侧）。

## T-47：多级网关与子网关拓扑（交付，域 14 更深拓扑）

### 落地内容

- `detach`：叶子回 `DIRECT`；带下级的子网关收敛为根 `GATEWAY`，保留子树；
- `AclEvaluator.allowDelegated`：委托方从「仅 GATEWAY」扩为「GATEWAY 或 SUB」，目标仍须为直接子设备；

### 关键决策（后续勿推翻）

1. **只允许挂载叶子设备**：不支持整棵子树移动；要移动子树先逐级解绑，避免一次操作重排多级拓扑与缓存。
2. **逐级 direct-parent 委托**：每一级只对自己的直接子设备负责；不要把 `allowDelegated` 改成祖先直连，否则 ACL 判定会跨级扩散。
3. **解绑带下级的子网关收敛为根 GATEWAY**：不能回 `DIRECT`，否则会出现「DIRECT 但有子设备」的非法状态。
4. **深度实时计算、不新增 depth 列**：默认最多 5 层，父链查询成本可接受；新增列会在拓扑移动时产生冗余维护。
5. **默认深度 5 可回退 2**：`DEVICE_TOPOLOGY_MAX_DEPTH=2` 恢复两层行为，现场可灰度。

### 踩坑

- `attach` 的父类型检查删除后，必须补「父链深度」校验；否则 SUB 父节点可以无限嵌套。
- 深度计算要有 visited 集合防环，父链缺失也要拒绝（不能默认按 1 处理）。
- 重挂载时只失效新父和子设备不够，旧父的委托缓存也必须失效，否则旧网关仍能代理已移走的子设备。
- 解绑带下级的子网关时，若仍写 `DIRECT`，其下级 ACL 委托会立即失效；必须收敛为 `GATEWAY`。
- 前端 `DeviceDetail` 原来 `if (isGateway) loadSubDevices else if (SUB) loadParent` 是互斥的；多级后 SUB 两者都要加载。
- `SubDevicePanel` 测试断言了旧文案「该网关下暂无子设备」，改文案需同步测试。

## T-49：场景步骤并行（交付，G-12-3）

让场景步骤流支持「PARALLEL 分叉 → 多条分支并发 → JOIN 汇合」，同时保持一行一步骤明细、重试与巡检语义。

### 落地内容

- 新增 `PARALLEL` / `JOIN` 流程步骤；`PARALLEL` 配置 `{branches: 2..8}`，`JOIN` 为空配置；
- `V27` 给 `scene_step` / `scene_step_run` 增加 `parallel_seq` / `branch_index`，块内普通动作步骤归属具体分支；
- 保存期校验：成对、不嵌套、块内只允许普通动作、每个分支至少一个启用步骤、不能与循环体重叠、分支不能跳入并行块、分支数 2..8；
- 执行器：`PARALLEL` 同时排期各分支首步；分支内按 `seq` 串行；分支结束按明细状态实时判断所有分支是否完成，全部完成才排期 `JOIN`；执行已失败时不再排期后续步骤；
- 手动重试：失败步骤在并行块内时从 `PARALLEL` 整体重置该块及之后的并行块，避免已成功分支不重放导致汇合条件永不满足；
- 前端步骤编辑器 / 画布属性面板支持并行开始、汇合与「并行分支」选择；画布绘制分叉 / 汇合边并隐藏跨分支顺序边；执行抽屉展示分支归属；
- 文档：T-49 实施计划、总督促 §3.42 / v1.53、路线图 L36 / v2.26、对标清单 G-12-3 / v2.12、ARCHITECTURE v1.36、DEPLOYMENT §9.28。

### 关键决策（后续勿推翻）

1. **显式 PARALLEL / JOIN 成对结构**：比隐式按 seq 推断更容易校验与可视化，避免分支范围何时结束的二义。
2. **分支归属落库**：`parallel_seq` + `branch_index` 是步骤与执行明细的快照，执行器不必每次反解整份配置。
3. **不新增计数器**：分支完成直接读明细状态，重试 / 重启 / 多副本都不会计数漂移；汇合排期用幂等 `scheduleNext`。
4. **块内禁用分支 / 循环 / 嵌套**：首版只支持普通动作步骤的并行分支，避免并行 + 回跳 + 重放的组合爆炸。
5. **失败后不强行中断在途动作**：已开始的外部动作允许完成，但不会继续排期后续步骤。

### 踩坑

- 并行分支完成判定不能只看“当前分支最后一步成功”，必须遍历该块全部分支的明细；两个分支同时完成时可能都排期汇合，但 `scheduleNext` 只对 PENDING 生效、`claimPending` 再兜底，重复投递无害。
- 手动重试不能只重置 FAILED/SKIPPED：并行块内已成功分支若不重放，汇合永远不满足；必须从 PARALLEL 整体重置，块前已完成步骤不回退。
- 前端 `syncMembership` 自身会写 `steps.value`，调用方不要再赋值一次，否则一次点击触发两次 `update:modelValue`（单测会抓到）。
- 并行块内步骤的分支编号必须由块扫描实时计算，不能依赖移动前的 `parallelSeq` 快照；提交前统一 `normalizeParallelMembership`。
- 画布不能继续画“分支 1 末步 → 分支 2 首步”的普通顺序边；必须抑制块内线性边，改为并行开始 → 分支首步、分支末步 → 汇合。
- `DeviceLogMapperSqlTest` / `DeviceMapperColumnsTest` 解析 MyBatis XML 时会联网拉 `mybatis.org` DTD，网络抖动会让全量 verify 报 `Socket Unexpected end of file`；测试里已加 EntityResolver 返回空 DTD，离线构建稳定。

## T-50：Modbus 多从站与 64 位整型（交付，G-13-2 / T-40 残留）

让一个 Modbus TCP 网关连接下可按点位指定多个 unitId，并补齐 int64/uint64。

### 落地内容

- `V28` 为 `device_point_table` 增加 `unit_id INT NULL`：空 = 继承 `driver_config.unitId`，点位值优先；
- 点表请求 / 实体 / DTO / 服务校验贯通 unitId（0~247，非法 6311）；前端点表页新增「从站」列与导入别名；
- `ModbusPointDispatch` 合并键从「功能码」扩为 `(功能码, unitId)`；`ReadGroup` 携带 unitId；采集器按分组 unitId 读，合并失败降级逐点读仍用该从站；
- `ModbusValueConverter` 新增 `int64` / `uint64`（4 寄存器）：有符号 `long`、无符号 `Long.toUnsignedString`，沿用 wordOrder 与 scale/offset；
- 前端数据类型选项、创建默认值、导入解析与文档同步。

### 关键决策（后续勿推翻）

1. **点位 unitId 优先于驱动默认值**：同一网关下不同从站共用 host/port，需要覆盖时才在点位行填写。
2. **合并键必须包含 unitId**：不同从站相同地址合并会把 A 从站的值写到 B 从站点位上。
3. **uint64 用无符号十进制字符串**：Java long 直接输出会变负数；BigDecimal 能承载该字符串参与换算。
4. **保持 TCP-only**：RTU 串口 / OPC-UA 另立协议批次，不在本批假装支持。

### 踩坑

- 多从站不是「读的时候多传一个 unitId」那么简单：批量读合并必须先按 unitId 分组，否则相邻地址的跨从站点会串位且不会报错。
- 合并读失败降级逐点读时，unitId 必须沿用原分组的，不能回落到设备默认值。
- int64 的 DCBA 测试不能做「寄存器数组反转」，要把大端 8 字节完整反转后再映射为寄存器；否则会得到字节序错误的期望值。
- Mockito `verify(registry, never()).open(any())` 会触发 `open` 声明的受检异常，测试方法必须 `throws Exception`。
- 点表页的从站地址用文本输入（`v-model`），保存时统一把 `''` / null 归一为 null；否则 Jackson 对空串转 Integer 的行为不稳定。
